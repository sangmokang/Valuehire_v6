# /verify — 종합 코드 검증

각 단계는 **실제로 실행한 결과**만 보고한다. 어떤 단계도 하드코딩된 점수나 가짜 통과를 리턴하지 않는다.
설정이 없어 실행할 수 없는 검사는 "스킵"으로 정직하게 표시하고 "통과"로 포장하지 않는다.

## 옵션
- 인자 없음 → 현재 git 변경사항(`git diff` / `git diff --staged`) 대상
- 파일 경로 → 해당 파일 대상
- `--gpt` → 4단계(ChatGPT 리뷰) 포함, 없으면 스킵
- `--strict` → 2단계 Architect 검증에서 더 깊은 리뷰 요청
- `--quick` → 1단계만 실행하고 종료
- `--no-test` → 1단계에서 테스트만 제외 (로컬 스크립트에 --no-test 인자로 전달)

## 1단계 — 로컬 자동 검증 (필수, 실제 실행)

```bash
bash .claude/skills/verify/local-checks.sh
```

이 스크립트의 **stdout을 그대로** 사용자에게 보여준다 (숫자를 지어내지 않는다).
`package.json`이 없으면 스크립트가 "package.json 없음 — 자동 검증 대상 아님"이라고 스킵 처리하는데, 이 경우 1단계는 "N/A"로 보고하고 무조건 통과 취급하지 않는다 — 사실 그대로 전달.

fail이 1개 이상이면: 여기서 중단하고 실패 내용을 사용자에게 보여준다. `--quick`이면 여기서 종료.

## 2단계 — Architect / 품질 리뷰 (실제 서브에이전트)

`Agent` 도구로 실제 리뷰를 요청한다. 가짜 데이터를 만들지 않는다.

- 기본: `subagent_type: "oh-my-claudecode:quality-reviewer"`
- `--strict`: `subagent_type: "oh-my-claudecode:architect"` (Opus, 더 깊은 설계 검토)

프롬프트에 대상 파일/diff 내용을 포함시키고, "복잡도·구조·리팩토링 필요성"을 물어본다.
에이전트가 돌려준 findings를 그대로 요약해서 보고한다 (임의로 등급/점수를 만들지 않는다).

## 3단계 — Security 리뷰 (실제 서브에이전트)

`Agent` 도구로 `subagent_type: "oh-my-claudecode:security-reviewer"` 호출.
대상 파일/diff를 프롬프트에 포함하고 OWASP Top 10, 입력 검증, 인증/인가, 민감정보 노출 관점을 명시적으로 요청한다.
에이전트의 실제 findings를 보고한다.

의존성 감사는 이미 1단계 `local-checks.sh`의 `npm audit`이 처리하므로 중복하지 않는다.

## 4단계 — ChatGPT 적대적 리뷰 (선택, `--gpt`일 때만)

`--gpt`가 없으면 이 단계는 완전히 스킵하고 그렇게 보고한다 ("실행 안 함", "통과"가 아님).

있으면 `Skill` 도구로 `gptreview` 스킬을 같은 대상(파일/diff)에 대해 호출한다.
이 단계는 사용자의 수동 로그인이 필요할 수 있음을 미리 안내한다.

## 최종 보고

각 단계를 다음 중 하나로만 표시한다: **✅ 통과** / **❌ 실패** / **⏭️ 스킵(미실행)**.
전체 판정은 "1~3단계 중 하나라도 ❌면 배포 보류"로 정한다. 4단계는 선택 사항이라 판정에 포함하지 않되, 발견 사항은 함께 제시한다.

보고서 끝에 다음 중 하나를 명시한다:
- 🚀 **배포 가능** (모든 필수 단계 통과)
- 🛑 **배포 보류** (실패 항목과 원인 나열)

실행하지 않은 단계를 "통과"로 적지 않는다 — 검증 없는 완료 선언 금지.
