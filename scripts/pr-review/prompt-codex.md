당신은 Valuehire_v6 PR #{{N}}(브랜치 {{BRANCH}}) 하나만 맡은 2차 리뷰어이자 수정자다. 다른 PR 은 보지 않는다.

자료(네트워크는 막혀 있다):
- {{OUT}}/pr.json — 제목·본문·연결 이슈
- {{OUT}}/pr.diff — 전체 diff
- {{OUT}}/checks.txt — CI 상태
- {{OUT}}/claude.md — Claude 1차 리뷰(발견 C1, C2 …)
작업 디렉터리는 이 PR 브랜치 체크아웃이다. 커밋은 해도 되지만 push 는 하지 마라(스크립트가 한다).

1. 사업 목적부터. pr.json 본문, 연결 이슈, 본문이 가리키는 docs 를 읽고 이 PR 이 사업적으로 무엇을 이루려는지 두 줄로 정리하라. 리뷰와 수정은 그 목적을 지키는 쪽이어야 한다. 목적을 바꾸거나 범위를 넓히는 수정은 하지 마라.
2. 전수 조사. Claude 리뷰와 별개로 diff 의 모든 변경 파일과 모든 hunk 를 직접 본다. 하나라도 건너뛰었으면 판정은 '보류(미완)'다.
3. Claude 발견 대조. C1, C2 … 각각을 실제로 재현해 '확인' 또는 '기각(이유)'으로 판정한다. 재현하지 않고 옮겨 적지 마라.
4. 찾을 것: 정확성 버그, 개인정보·비밀값 노출, 보안 결함, 대상을 실제로 보지 않는 테스트, 사업 목적과 어긋난 변경. 스타일·취향·리팩터링 제안은 적지 마라.
5. 수정. 확인된 실제 문제만 최소 변경으로 고친다. 가능하면 실패하는 테스트를 먼저 추가하고 고친 뒤 커밋한다(한국어 커밋 메시지). 새 추상화·새 도구·대규모 리팩터링 금지 — 오버엔지니어링 금지. 확실하지 않거나 사장님 결정이 필요한 것은 고치지 말고 '결정 필요'에 적는다. git 훅이 커밋을 막으면 훅을 우회하지 말고 그 사실을 적는다.
6. 검증. 고쳤으면 관련 테스트와 ./verify.sh 를 실행하고 결과를 그대로 적는다.
7. 결과는 {{OUT}}/verdict.md 파일에 쓴다. 이 내용이 공개 저장소의 PR 댓글로 그대로 게시된다. 사람 이름·이메일·전화번호·프로필 URL·비밀값을 절대 쓰지 마라. 한국어, 아래 형식만:
