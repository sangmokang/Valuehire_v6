# 업무 대화 검수와 Supabase 증거 적재

이 모드는 사용자가 명시적으로 요청한 작업에 적용한다. 정책 JSON은 Git 밖에 둔다. 특정인의 이름·별칭이나 실제 전사 내용을 스킬·테스트에 넣지 않는다.

1. 원본 목록과 사용자 제외 대상, 등록된 컨설턴트 명단, 허용한 삭제 방식·폴더를 비공개 정책으로 고정한다. 제외 인물은 표기 변형과 실제로 확인한 별칭을 포함한다. 일반 인물명을 임의로 컨설턴트라고 단정하지 않는다.
2. Gemini 웹 대화와 Gemini API 전사는 서로 다른 원천이다. 웹 대화는 로그인된 브라우저에서 각 대화를 실제로 열고, 접힌 답변·이전 메시지·스크롤 영역을 모두 확인하여 전문과 원본 대화 URL을 보존한다. 제목 목록이나 보이는 일부 메시지를 전체 수집이라고 부르지 않는다. 브라우저가 본문 읽기를 막으면 사용자에게 필요한 브라우저 설정을 알리고 다른 독립 작업을 계속한다. API 응답을 과거 웹 대화라고 보고하지 않는다.
3. 오디오 전사는 `phone.py`의 응답·시간·긴 인식 공백 검사를 먼저 통과해야 한다. 전사 실패·음질 불명은 비업무 판정의 근거가 아니다. 해당 원본은 보존하고 재전사·청취 검토 대상으로 남긴다. 텍스트 대조는 수집 누락을 검사하며 ASR의 모든 단어가 정확하다는 보증은 아니다.
4. `review.py`를 서로 다른 두 Gemini 모델로 실행한다. 원문을 고정된 발화 단위로 나누고 모든 발화를 빠짐없이 업무/중립/사적/제외 컨설턴트 관련/불명으로 판정한다. 한 모델이라도 사적·컨설턴트 관련·불명으로 판단한 구간은 결과에서 제외한다. 별칭 검사도 별도로 적용한다. 이름만 지우지 말고 그 인물을 가리키는 뒷말·해당 주제의 대화 구간 전체를 검토한다. 그 밖의 업무 발언은 원문 그대로 유지한다.
   Gemini 검수 호출이 차단되면 Codex가 해당 전사 **전체**를 직접 읽어 발화별 판정 JSON을 만들 수 있다. `--direct-review`는 원본 SHA-256·전체 단어 배열 해시·정책 해시·검수자에 묶인 입력만 받는다. 이 경우 `codex_source_review_with_machine_checks`로 기록하며 두 모델 독립 검수를 통과했다고 주장하지 않는다. 이름이 같은 외부 회사 인물 등은 원본별 정확한 문맥 인용을 확인한 예외만 허용한다. 예외는 다른 통화·같은 이름의 다른 문맥에 적용하지 않는다.
5. 부분 제외가 있는 통화는 나머지 업무 대화를 보존하며, 원본 단어 수 = 보존 단어 수 + 제외 단어 수를 검사한다. 제외 장부는 시간·원문 해시·사유 코드만 남기고 제외 내용을 결과 문서에 반복하지 않는다. 비업무로 의심되는 통화 전체의 삭제는 사용자가 명시한 경우에만 `--trash-nonbusiness`로 수행한다. 원본 해시·폴더 경계를 다시 확인하고 macOS 휴지통 이동 후 원본 위치 부재를 확인한다. 복구 불가능한 영구 삭제를 기본값으로 삼지 않는다.
6. 검수 결과 `BUSINESS_REVIEWED`인 경우에만 정제된 `transcript.txt`와 `docs-requests.json`을 Google Docs에 저장한다. 제목·본문·메타데이터 모두 제외 인물·사적 내용이 남지 않아야 한다. 일부 구간을 제외한 문서는 이를 명시하며 가공 전 전체 전문이라고 부르지 않는다. 웹 원문 대비 수집 완전성 검수와 업무 적합성 검수 결과는 분리한다.
7. Docs 전체를 읽어 로컬 본문과 일치하는지 검증하고 `document-receipt.json`에 `status: VERIFIED`, 실제 `document_id`, 실제 `url`, `text_sha256`를 저장한다. 미검수 문서·보류 통화·빈 문서는 Supabase에 넣지 않는다.
8. 기존 Supabase 스키마·정본과 익명 접근권한을 먼저 확인한다. `review.py --sync-env <기존 .env.local>`는 정제된 **원천 증거**를 비공개 Storage에 저장하고 `ontology_meta`에는 불투명한 포인터만 멱등 upsert한다. 원본 SHA-256으로 UUID를 생성한다. Docs 링크·정제된 본문·검수/제외 단어 수는 비공개 객체에만 저장한다. 원본 경로·제외 인물·삭제된 사적 본문은 업로드하지 않는다. 고객사 집계나 기존 확정 사실을 덮어쓰지 않는다. 수집된 발언을 검증된 사실로 승격하지 않는다.
9. 저장 직후 색인 행과 비공개 객체를 다시 읽어 ID·도메인·정제된 본문 전체·해시·출처를 대조한다. `SUPABASE_VERIFIED` 영수증이 있어야 원격 적재 완료다. DB 실패 시 로컬 정제 결과와 Docs를 보존하고 DB 대기 상태를 명확히 남긴다.

   라이브 `ontology_meta`에는 `UNIQUE(domain)` 제약이 있다. 증거별 domain 키는 `business_call_transcripts:<원본 SHA-256>`으로 만들어 서로 다른 통화가 충돌하거나 덮어쓰지 않게 한다. 기존 고객사·정산 도메인은 수정하지 않는다.

   **본문 접근권한:** 라이브 `ontology_meta`는 익명 조회가 가능하다. 이 테이블에는 본문·인명·Docs URL을 저장하지 않고, 불투명한 원본 해시와 비공개 Storage 객체 포인터만 색인한다. 본문은 `phone-business-evidence` 비공개 버킷에 저장한다. 민감한 본문을 올리기 전에 무해한 canary로 서비스 역할 다운로드 성공과 익명 다운로드 차단을 모두 확인한다. 본문 저장 후에도 전문 재조회·익명 차단을 재검증한다. 공개/익명 접근이 허용되면 본문 업로드를 중단하거나 방금 쓴 객체를 회수하고 실패 처리한다. 본문은 서비스 역할을 가진 서버 경로에서만 가져온다.

   조회는 `review.py --read-id <검증된 UUID> --sync-env <기존 .env.local> --policy <현재 정책> --out <작업 폴더>`를 사용한다. 색인/객체 해시와 현재 정책을 확인하고 기본 응답은 800자 이하 발췌만 돌려준다. 다른 고객 메타 데이터나 경로를 임의로 가져오지 않는다.

```bash
python3 scripts/review.py --manifest /private/run/manifest.json --record 1 \
  --policy /private/policy.json --out /private/reviewed/call-001 --trash-nonbusiness

# Docs 저장·전체 본문 대조 및 VERIFIED 영수증 저장 후에만:
python3 scripts/review.py --policy /private/policy.json \
  --out /private/reviewed/call-001 --sync-env /existing/project/.env.local
```

대량 처리 시 각 통화의 전사·분류·삭제·Docs·Supabase 상태를 따로 checkpoint한다. 실패한 한 건 때문에 성공 상태를 지우거나 이미 생성된 문서·DB 행을 중복 생성하지 않는다. 결과를 보고할 때 각 단계의 실제 완료·대기 건수를 구분한다.
