# HumanSearch L0 인증 화면 분류 계약 (SOT)

최종 갱신: 2026-08-22 (사람인 L1 일회 관측 소비자 연결 반영)

## 1층 — 결론

첫 기능은 현재 화면이 로그인 전인지, 로그인됐는지, 사람 확인이 필요한지, 알 수 없는지, 화면
구조가 바뀌었는지만 답한다. 로그인 뒤 실행 순서와 중단 절차는 이 기능에 넣지 않는다.

## 2층 — 판단 근거

L0는 시간에 따라 실행을 움직이는 전체 상태기계(= 현재 상태와 사건에 따라 다음 상태를 정하는
절차)가 아니다. 현재 화면에서 인증 관련 의미 역할을 관측한 결과를 분류하는 순수 함수(= 외부
접속이나 저장 없이 입력값만으로 결과를 내는 함수)다.

기존 실행 지시에는 다섯 개 화면 결과와 후속 단계의 `RECHECK`, `AUTH_CONFLICT`, `RUNNING`,
`STOP`이 섞여 있었다. 둘을 한 열거형(= 허용값을 미리 고정한 타입)에 넣으면 L0가 후속 단계의
책임을 선점하고, `AUTHENTICATED`를 전체 실행의 종료로 오해하게 된다.

따라서 L0는 아래 세 입력 역할, 하나의 관측 유효성, 다섯 출력 상태만 소유한다.

**무엇을** — L0를 현재 인증 화면의 의미만 분류하는 기능으로 제한한다.

**왜** — 정상 입력 조합을 빠짐없이 셀 수 있고 후속 실행 절차와 검증 책임을 섞지 않기 위해서다.

**버린 길** — 재확인, 세션 충돌, 실행 시작까지 일곱 상태로 묶는 방식을 버렸다. 첫 기능이 시간에
따른 실행 절차까지 선점하기 때문이다.

**대가** — L0만으로 로그인 완료 뒤의 실행 흐름을 진행할 수 없다. 그 흐름은 별도 변경이 필요하다.

**되돌리기** — 현재 사람인 L1 일회 관측기가 이 분류기를 소비한다. 분류 계약을 되돌리려면
`humansearch.observe`의 변환·출력·시험과 두 SOT를 같은 변경에서 함께 되돌린다.

## 3층 — 정본 계약

### 입력

`SurfaceObservation`은 두 필드로 고정한다.

- `matched_roles`: `frozenset[SurfaceRole]`
- `contract_valid`: `bool`

`SurfaceRole`은 정확히 세 값이다.

- `AUTHENTICATED_SURFACE = "authenticated_surface"`
- `HUMAN_AUTH_SURFACE = "human_auth_surface"`
- `CHALLENGE_SURFACE = "challenge_surface"`

이 값은 화면의 의미만 나타낸다. CSS, XPath, URL, 포털명, 화면 문구는 L0 입력이 아니다.

`contract_valid`는 상위 화면 계약 판정기가 구조를 정상적으로 해석했는지를 뜻한다. `False`이면
역할 집합과 관계없이 구조가 바뀐 것으로 분류한다. 구조 변경을 가짜 화면 역할로 만들지 않는다.

런타임 입력이 `SurfaceObservation`이 아니거나, `contract_valid`가 실제 `bool`이 아니거나,
`matched_roles`가 `frozenset`이 아니거나, 그 안에 `SurfaceRole`이 아닌 값이 있으면
`InvalidObservation`을 발생시킨다. 문자열 값이 우연히 열거형 값과 같아도 거부한다.

### 출력

`AuthSurfaceState`는 정확히 다섯 값이다.

- `UNKNOWN`: 계약은 유효하지만 인증 역할을 하나도 관측하지 못했다.
- `HUMAN_AUTH`: 사람 로그인이 필요한 화면을 유일하게 관측했다.
- `AUTHENTICATED`: 인증된 화면을 유일하게 관측했다.
- `CHALLENGE`: 캡차나 2단계 확인 화면을 유일하게 관측했다.
- `DRIFTED`: 계약이 유효하지 않거나 서로 배타적인 역할을 둘 이상 관측했다.

`AUTHENTICATED`는 L0의 화면 분류 결과일 뿐 전체 실행의 종료 상태가 아니다. 후속 실행기가 최신
인증 증거와 좌석 사용 조건을 확인한 뒤 실제 작업 시작 여부를 결정한다.

`DRIFTED`는 입력 역할이 아니다. 관측 계약의 불일치에서 계산되는 출력이다.

### 완전 결정표

| `contract_valid` | `matched_roles` | 결과 |
|---|---|---|
| `False` | 세 역할의 부분집합 8개 전부 | `DRIFTED` |
| `True` | 빈 집합 | `UNKNOWN` |
| `True` | 인증 역할 한 개 | `AUTHENTICATED` |
| `True` | 사람 로그인 역할 한 개 | `HUMAN_AUTH` |
| `True` | 사람 확인 역할 한 개 | `CHALLENGE` |
| `True` | 크기 2 또는 3인 부분집합 전부 | `DRIFTED` |

→ 세 역할의 부분집합 8개와 유효성 2개를 곱한 정상 입력 16개가 모두 정의됐다. 위험 역할에 임의
우선순위를 두지 않으므로 모순 관측이 인증 성공으로 축소되지 않는다.

### 공개 기능

구현 모듈은 `humansearch/src/humansearch/auth_surface.py`다. 공개 이름은 다음으로 제한한다.

- `AuthSurfaceState`
- `SurfaceRole`
- `SurfaceObservation`
- `InvalidObservation`
- `classify_auth_surface(observation: SurfaceObservation) -> AuthSurfaceState`

`transition`, `decide_role`, `is_terminal`은 L0 기능이 아니다. 시간 전이, 재확인, 기다림, 좌석 해제,
재시도, 중단, 실행 진입은 후속 계약과 별도 변경 요청이 소유한다.

분류 함수는 네트워크, 파일, 환경변수, 시계, 난수, 화면 요소, 브라우저에 접근하지 않는다. 같은 값의
입력은 항상 같은 열거형 결과를 반환한다.

### 실행 가능한 인수 기준

이 작업의 단일 인수 기준은 다음과 같다.

> 세 의미 역할과 관측 유효성으로 만들 수 있는 정상 입력 16개를 모두 위 결정표대로 분류하고,
> 잘못된 입력은 전부 `InvalidObservation`으로 거부하며, 같은 입력은 항상 같은 결과를 낸다.

검증은 정상 입력 전수 시험, Hypothesis(= 입력 조합을 자동 생성해 모든 입력이 지켜야 할 성질을
검사하는 개발 도구), 잘못된 입력 시험, 실제 패키지 불러오기, 일부러 구현 한 줄을 틀리게 바꾸는
변조 시험으로 증명한다.

### 구현 순서 불변식

- RED(= 필요한 기능이 없어서 시험이 실패하는 상태) 커밋은 시험, Hypothesis 의존성, 잠금 파일만
  바꾼다.
- RED는 기능 부재 때문에 실패해야 한다. 문법 오류, 잘못된 작업 폴더, 의존성 설치 실패, 시험 0건은
  유효한 RED가 아니다.
- GREEN(= 최소 구현으로 같은 시험이 통과하는 상태) 커밋은 제품 모듈과 공개 내보내기만 바꾼다.
- GREEN은 RED의 기대값, 건너뛰기 설정, 의존성, 잠금 파일을 바꾸지 않는다.

### 후속 단계 소유권

- 후속 로그인 단계: 사람 로그인 완료 뒤 최신 화면을 다시 확인하는 절차와 `RECHECK` 의미.
- 후속 중단 단계: 보안 확인과 세션 충돌의 종료 행동, 자동 제출·재시도 0회.
- 실행기: 인증 화면 확인 뒤 좌석과 증거를 검사하고 `RUNNING`에 들어갈지 결정.
- 화면 계약: 실제 화면 구조를 세 의미 역할과 `contract_valid`로 바꾸는 판정.

### 비범위

- 실제 채용 포털, 브라우저, 로그인, 세션, 자격증명, 화면 저장, 후보자 개인정보
- 화면 요소나 포털별 계약 생성
- 기다림, 좌석 해제, 재시도, 중단, 실행 전이
- 다음 라이브 단계와 이후 후보 검색
- 합치기와 배포

### 충돌 해소

날짜가 있는 `docs/engineering/` 계획이나 실행 지시가 이 문서와 다르면 L0 구현에서는 이 문서를
따른다. 이 계약을 바꾸려면 같은 변경 요청에서 이 파일, 인수 시험, 구현 지시를 함께 바꾸고 검사
약화 여부를 명시한다.
