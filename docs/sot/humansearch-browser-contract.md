# HumanSearch 브라우저 접속 계약 (SOT)

최종 갱신: 2026-08-18

## 1층 — 결론

HumanSearch는 사람인과 잡코리아의 준비된 정상 작업에서 채널별 전용 브라우저에 로컬 진단 통로로
접근한다. 사용자는 작업마다 탭을 다시 넘기지 않는다. 로그인이나 보안 확인이 필요하거나 대상이
하나로 확정되지 않으면 사람을 부르고 멈춘다.

이 정본은 브라우저를 실제로 켜거나 연결하는 방법을 완료했다고 선언하지 않는다. 다음 단계가
증명해야 할 접근 권한, 목표 탭, 사용 시간, 사람 개입, 개인정보와 채널별 허용 범위를 고정한다.
LinkedIn Recruiter 안의 자동 처리는 별도 허용 근거가 확인될 때까지 금지한다.

## 2층 — 판단 근거

사용자가 현재 탭을 매번 선택하는 방식은 접근 범위가 작지만 정상 명령 뒤 클릭 0회라는 운영 목표와
맞지 않는다. 진단 통로는 클릭 없이 기존 로그인 세션을 이어 쓸 수 있지만, 프로필의 열린 탭과 인증
자료에 넓게 접근할 수 있다. 따라서 편의를 얻는 대신 기본 사람 프로필을 쓰지 않고, 채널별 전용
프로필·정확히 하나인 목표 탭·짧은 사용권·사람 입력 즉시 회수를 필수 조건으로 둔다.

**무엇을** — 사람인·잡코리아에는 채널별 상주 브라우저 + 로컬 진단 포트를 채택하고, LinkedIn Recruiter 사이트 내부 자동화는 허용 근거 전 금지한다.

**왜** — 준비된 정상 세션의 클릭 0회 목표를 지키면서도 자격증명 입력·탭 추측·브라우저 생성과 종료를 금지하는 단일 경계를 만들 수 있기 때문이다.

**버린 길** — PR #15의 Active Tab Bridge는 브라우저가 현재 탭 하나로 권한을 좁혀 주지만 작업마다 사람 클릭이 필요해 정상 운영 목표와 맞지 않으므로 버린다.

**대가** — 진단 접속은 프로필 수준의 넓은 능력을 가지므로 작은 전용 프로필, 명령 허용 목록, 단일 탭 증거, 만료와 증가 번호, 사람 개입 뒤 잔여 명령 0을 D1이 증명해야 한다.

**되돌리기** — 새 L3 결정 기록과 오너 승인으로 이 정본을 교체하고 D1 이후 구현을 중단한 뒤 Active Tab Bridge 또는 더 좁은 경계를 다시 채택한다. PR #15를 조용히 정본으로 되살리지 않는다.

## 3층 — 정본 계약

### 1. 지위와 적용 범위

이 파일은 HumanSearch의 브라우저 접속 방식, 권한 수명, 목표 탭 선택, 사람 개입 중단, 채널별 허용
범위와 C1 최소 경계의 단일 정본이다. 이 파일이 현재 `main`에 병합된 뒤에만 정본 지위를 가진다.

이 계약은 다음을 구현하거나 증명하지 않는다.

- 브라우저 실행·자동 기동·생존 감시
- 포트·프로필 경로 발견
- 실제 탭 연결·화면 읽기·로그인·후보 검색
- 화면 캡처·개인정보 제거·보존·삭제
- LinkedIn Recruiter 자동화 허용

위 항목은 아래 `NOT_RUN` 장부와 후속 단계가 소유한다.

### 2. 선택한 접속 방식

사람인과 잡코리아의 후속 자동화는 다음 구조만 사용할 수 있다.

```text
사람이 준비한 채널별 비기본 전용 프로필
  → 이미 실행 중인 상주 브라우저
  → 로컬 주소에만 열린 진단 포트
  → D1이 승인한 최소 접속 어댑터
  → 실행 전에 새로 확인한 목표 탭 정확히 1개
```

→ 구조가 말하는 것: HumanSearch 자동 운영은 브라우저를 만들거나 사람의 기본 프로필을 가로채지
않는다. 이미 준비된 전용 브라우저의 정확히 하나인 탭에만, 증명된 최소 어댑터를 통해 접근한다. C1의
한 번 읽기 관측은 §12의 별도 일회성 경계를 따른다.

`Active Tab Bridge`, Chrome 자동 연결, 임의 브라우저 자동 탐색, 전체 프로필 자동 연결은 정상
작업의 대체 경로가 아니다. 주 경로가 실패하면 다른 경로로 자동 전환하지 않고 중단한다.

### 3. Chrome 공식 근거와 보안 대가

2026-08-18에 확인한 Chrome 공식 문서는 다음 사실을 명시한다.

- Chrome 136부터 기본 Chrome 데이터 디렉터리에 원격 디버깅 포트나 파이프를 붙이는 스위치는
  무시된다. 비기본 사용자 자료 디렉터리가 함께 필요하다.
- 기존 브라우저 세션에 연결하면 연결 주체가 로그인 계정, 열린 탭, 세션 저장소, 로컬 저장소, 쿠키와
  JavaScript가 노출하는 다른 자료에 접근할 수 있다.
- Chrome 144+ 자동 연결도 사용자가 원격 디버깅을 켜고 연결 요청에서 `Allow`를 눌러야 한다.
- 진단 포트의 `/json/version`은 브라우저 접속 주소를, `/json` 또는 `/json/list`는 모든 가용 대상을
  제공한다. 포트 0으로 시작하면 선택된 포트를 프로필의 `DevToolsActivePort`에 기록할 수 있다.
- 같은 진단 인터페이스에는 새 탭 열기, 탭 활성화, 탭 닫기 같은 넓은 기능도 있다.
- 최신 tip-of-tree 프로토콜은 자주 바뀌며 하위 호환이 보장되지 않는다.

따라서 진단 포트 사용은 좁은 권한을 뜻하지 않는다. D1 제품이 넓은 인터페이스 가운데 아래 허용
명령만 구조적으로 노출하고 금지 명령의 도달 경로를 제거해야 한다. 포트가 제공한다는 이유만으로
제품 권한으로 채택하지 않는다.

공식 근거:

- <https://developer.chrome.com/blog/remote-debugging-port>
- <https://developer.chrome.com/docs/devtools/agents/get-started/configuration>
- <https://developer.chrome.com/docs/devtools/agents/use-cases/auto-connect>
- <https://chromedevtools.github.io/devtools-protocol/>

Chrome 공식 문서는 HumanSearch의 목표 탭, 사용권, 사람 입력 감지, 포털 허용 범위와 LinkedIn 정책을
정하지 않는다. 이 항목들은 Chrome이 보증한 사실이 아니라 아래 제품 계약과 후속 검증 책임이다.

### 4. 프로필과 세션 경계

#### 사람인·잡코리아

- 채널별로 서로 다른 비기본 전용 사용자 자료 디렉터리를 사용한다.
- 그 프로필은 사람이 만들고 사람이 직접 로그인한다.
- HumanSearch는 기존 로그인 세션을 **사용**할 수 있지만 비밀번호·쿠키·토큰을 읽거나 복사·내보내기·
  입력·갱신할 수 없다.
- 평소 쓰는 기본 Chrome 프로필, 다른 채널 프로필, 다른 사람의 프로필을 자동 후보로 삼지 않는다.
- 전용 프로필과 기존 사람 세션이 서로 밀어내거나 좌석 충돌을 만들면 자동 복구하지 않고 중단한다.
- 프로필을 복제하거나 다른 프로필의 쿠키·저장소를 가져오는 기능은 금지한다.

#### LinkedIn Recruiter

- 자동 접속용 origin 허용 목록은 비어 있다.
- 사이트 내부 프로젝트 생성, 필터 입력, 후보 순회, 후보 열기, 저장, 메시지 작성·발송을 자동화하지
  않는다.
- 로컬에서 프로젝트명·검색식·필터 준비표를 만드는 일만 허용한다.
- 사람이 기존 세션에서 사이트 내부 작업을 수행한다. 사람인·잡코리아의 전용 프로필 전략을 LinkedIn에
  자동 적용하지 않는다.
- 계약·정책·계정별 허용 근거와 오너 승인이 새 정본에 기록되기 전에는 이 범위를 넓힐 수 없다.

### 5. 채널별 허용 범위

| 채널 | 브라우저 접속 | 정상 작업 클릭 | 사이트 내부 자동화 | 현재 origin 상태 |
|---|---|---:|---|---|
| 사람인 | 자동 운영은 D1 증명 뒤 전용 브라우저만; C1은 §12 일회성 읽기만 | 0회 목표 | 후속 단계가 별도 승인한 동작만 | 자동 운영 exact-origin 목록 NOT_RUN; C1은 별도 정본의 exact origin 필수 |
| 잡코리아 | 자동 운영은 D1 증명 뒤 전용 브라우저만; C1은 현재 범위 아님 | 0회 목표 | 후속 단계가 별도 승인한 동작만 | exact-origin 목록 NOT_RUN; 목록 없으면 연결 금지 |
| LinkedIn Recruiter | 자동 접속 금지 | 해당 없음 | 사이트 내부 전부 사람 수행 | 자동화 origin 허용 목록 비어 있음 |

→ 표가 말하는 것: 사람인·잡코리아도 이 문서만으로 접속할 수 없다. 자동 운영은 D1이 현재 공식 포털
근거로 exact-origin(= scheme·host·port가 모두 고정된 주소 경계) 목록을 정본화하고 시험하기 전에는
기본 거부한다. C1의 사람인 한 번 읽기는 별도 C1 정본이 실행 시점의 exact origin을 기록·승인해야
한다. 기억한 도메인 문자열이나 eTLD+1 부분 일치로 넓히지 않는다.

허용 origin은 코드 여러 곳에 쓰지 않고 P22에 따라 후속 `contracts/*.json` 한 곳에서만 소유해야
한다. 서브도메인 와일드카드, URL 문자열 포함 검사, 정규식의 임의 확장은 금지한다. 경로·query에
계정·후보 식별자가 있더라도 로그나 증거에 값을 남기지 않는다.

### 6. 포트·프로필·브라우저 발견

포트 번호와 프로필 경로를 기억이나 소스 리터럴로 하드코딩하지 않는다. D1은 매 브라우저 기동과 작업
시작 전에 다음을 새로 발견하고 다시 확인해야 한다.

- 브라우저 인스턴스 신원
- 채널별 프로필 인스턴스 신원
- 로컬 주소에만 바인딩된 진단 포트
- 현재 브라우저·프로토콜 버전과 D1 지원 범위
- 목표 탭 후보 목록과 각각의 origin

발견 방법 자체는 D1 중립 실증 전까지 `NOT_RUN`이다. Chrome 공식 문서의
`DevToolsActivePort`, `/json/version`, `/json/list`는 가능한 근거일 뿐 자동 채택한 구현 지시가
아니다. 포트 응답 하나만으로 프로필·채널·탭·로그인 일치를 증명하지 못한다.

### 7. 목표 탭 계약

작업 시작 전에 다음 조건을 모두 확인한다.

1. 채널의 승인된 exact-origin 목록이 존재한다.
2. 브라우저와 프로필 증거가 현재 작업의 채널과 일치한다.
3. 허용 origin과 목표 화면 구조를 모두 만족하는 탭이 정확히 하나다.
4. L0 입력을 만드는 상위 화면 계약이 유효하다.
5. 목표 탭 증거는 현재 사용권 안에서 새로 얻은 것이다.

목표 탭이 0개이거나 2개 이상이면 시작하지 않는다. 제목, 탭 순서, 최근 활성 시각, URL의 부분 일치,
과거 target id, 이전 작업의 탭 번호로 하나를 추측하지 않는다. 사람이 선택해 주길 기다리며 기존 후보
중 임의 대상을 활성화하지 않는다.

새 창·새 탭 생성, 탭 활성화·전면화, 탭·창·브라우저 종료는 D0와 C1의 허용 명령이 아니다. 후속
단계가 활성화 같은 능력을 실제로 필요로 하면 별도 L3 결정과 중립 시험으로 범위를 변경해야 한다.

### 8. 사용권·만료·증가 번호

브라우저 접근은 채널당 작업 하나의 사용권으로만 허용한다.

최소 사용권 필드는 다음과 같다.

```json
{
  "channel": "saramin | jobkorea",
  "lease_id": "opaque-id",
  "fencing_number": "strictly-increasing-integer",
  "expires_at": "timestamp",
  "allowed_origins_version": "approved-version",
  "browser_instance_proof": "fresh-proof",
  "profile_instance_proof": "fresh-proof",
  "target_tab_proof": "exactly-one-fresh-target"
}
```

→ 계약이 말하는 것: 만료 시각과 이전 권한을 무효화하는 증가 번호가 없으면 브라우저 명령을 낼 수
없다. 현재 값보다 작은 증가 번호, 만료된 사용권, 다른 채널의 사용권은 모두 거부한다.

LinkedIn Recruiter는 이 사용권의 채널 값이 아니며 브라우저 사용권을 얻을 수 없다. 허용 근거 전
LinkedIn용 로컬 준비 자료에는 브라우저 권한 필드를 넣지 않는다.

모든 외부 효과 직전에는 사용권, 만료, 증가 번호와 사람 개입 상태를 다시 읽는다. 작업 시작 때 한 번
검사한 결과를 긴 작업 전체에 재사용하지 않는다. 채널당 두 번째 작업이 사용권을 얻으려 하면 기다리며
첫 작업의 권한을 훔치거나 브라우저를 다시 시작하지 않는다.

### 9. 사람 입력과 권한 회수

사람 입력을 감지하면 즉시 다음 순서로 자동화 권한을 회수한다.

1. 현재 사용권을 취소하고 증가 번호를 올려 이전 권한을 무효화한다.
2. 아직 실행하지 않은 명령, 재시도, 타이머, 콜백을 취소한다.
3. 진행 중 명령의 다음 외부 효과 전에 취소 상태를 다시 확인한다.
4. 브라우저·탭을 닫거나 사람 입력을 되돌리지 않는다.
5. 자동 재개하지 않는다.

사람 입력 감지 수단, 감지 지연 상한, 진행 중 명령 취소와 잔여 명령 0건은 D1 중립 시험 전까지
`NOT_RUN`이다. 이 세 가지를 증명하지 못하면 실제 포털 자동화 권한을 부여할 수 없다.

### 10. 자격증명과 명령 능력 경계

제품 코드에는 다음 능력이 없어야 한다.

- 비밀번호·쿠키·토큰·인증 헤더·세션 저장소 값을 읽거나 출력하는 API
- 비밀번호·보안문자·인증번호·2단계 인증을 입력·제출·우회하는 API
- Network·Storage·Cookie 계열 진단 명령을 범용으로 호출하는 통로
- 문자열로 임의 CDP 메서드와 매개변수를 전달하는 범용 pass-through
- 새 탭·창 생성, 임의 navigation, 목표 외 탭 활성화, 탭·창·브라우저 종료 API
- 프로필 복제·쿠키 가져오기·내보내기·세션 주입 API

“raw CDP 금지”는 진단 포트라는 전송 수단을 쓰지 말라는 뜻이 아니다. 진단 포트 위에서 임의
프로토콜 명령을 전달하거나 전체 대상·프로필 능력을 제품에 노출하는 **범용 제어면**을 금지한다는
뜻이다. D1은 명시된 최소 읽기·입력 동작만 가진 좁은 어댑터를 만들고, 금지 메서드를 일부러 심은
변조 시험이 실패하는지 증명해야 한다.

D0의 제품 동작은 0건이다. C1에서 허용되는 제품 동작은 현재 화면의 계약된 구조를 읽고, 로컬 상태를
중단으로 바꾸고, PII 없는 상태 알림을 한 번 남기는 범위뿐이다. 실제 입력·순회 동작은 이후 단계의
별도 계약이 없으면 허용되지 않는다.

### 11. 정상 흐름과 사람 호출

사람인·잡코리아의 “정상 흐름 클릭 0회”는 다음 준비가 이미 끝난 작업만 뜻한다.

- 사람이 채널별 전용 브라우저를 준비하고 직접 로그인했다.
- D1이 브라우저·프로필·포트·origin·목표 탭·사람 입력 회수를 증명했다.
- 현재 사용권과 증가 번호가 유효하다.
- L0가 현재 화면을 `AUTHENTICATED`로 분류하고 상위 계약이 유효하다.

최초 프로필 생성, 브라우저 재기동, 로그인, 보안 확인과 충돌 해결은 클릭 0회 약속에 포함되지 않는
사람 작업이다. 그 예외를 정상 자동 흐름으로 숨기지 않는다.

다음 중 하나면 PII 없는 알림으로 사람을 한 번 호출하고 중단한다.

- 로그인 만료 또는 `HUMAN_AUTH`
- 보안문자·캡차·2단계 인증 또는 `CHALLENGE`
- 세션·좌석·프로필 충돌
- 허용 origin·목표 화면·브라우저·프로필·포트 증거 불일치
- 목표 탭 0개 또는 2개 이상
- 사용권 만료, 증가 번호 역전, 채널 중복 작업
- 사람 입력 감지
- `DRIFTED`, 알 수 없는 화면 또는 지원하지 않는 브라우저·프로토콜 버전

중단 뒤에는 비밀번호 입력, 로그인 버튼 클릭, 보안문자·2단계 인증 제출, 재시도, 브라우저 재시작,
다른 탭 선택을 하지 않는다. 사람이 문제를 해결해도 자동 재개하지 않는다. 새 작업이 새 증가 번호와
새 증거를 받아 처음부터 다시 확인하는 절차가 별도 승인되기 전까지 재개는 `NOT_RUN`이다.

### 12. C1 최소 접속·중단·개인정보 경계

C1은 실제 사람인 화면 하나의 개인정보 제거 구조 자료를 만드는 별도 단계다. 다음 조건이 모두
충족되기 전에는 포털에 접속하지 않는다.

1. L0와 이 D0 계약이 현재 `main`에 병합돼 있다.
2. 추적되는 C1 캡처·개인정보 계약이 현재 `main`에 있다.
3. 오너가 이번 C1 실행을 명시적으로 승인했다.
4. 실행 직전에 사람이 승인한 일회성 증거로 정확한 브라우저·비기본 전용 프로필·로컬 포트·exact
   origin·단일 목표 탭을 다시 확인했다. 이 값은 제품 코드에 저장하거나 하드코딩하지 않는다.
5. 사람이 해당 전용 프로필에 직접 로그인했다.
6. Git 밖 원본 저장 위치, 암호화, 디렉터리 0700·파일 0600 권한이 준비됐다.
7. 채널별 보존기간, 삭제 작업과 PII 없는 삭제 결과 영수증 계약이 승인되고 시험됐다.
8. raw DOM·ARIA·스크린샷 경로가 Git ignore와 데이터 노출 검사로 차단됐다.
9. accessible name·textContent·placeholder 값 없이 판정 가능한 개인정보 제거 전략이 정본에 있다.

C1의 최소 접속은 exact origin과 화면 계약을 만족하는 **정확히 하나인 현재 탭의 읽기**다. 새 탭·창
생성, 활성화·전면화, 브라우저 종료, 로그인 제출, 검색어·필터 입력, 후보 상세 열기, 저장·등록·발송은
금지한다.

C1은 D1 자동 탐지 구현을 완료했다고 전제하지 않는다. 대신 별도 C1 계약이 일회성 수동 확인 방법,
확인 시각, 허용 exact origin, 브라우저·프로필·포트·목표 탭 증거의 비민감 지문과 만료를 소유한다.
그 증거를 다음 실행에 재사용하지 않는다.

raw DOM·ARIA·스크린샷은 모두 개인정보 자료다. Git·로그·PR 본문에는 저장 위치의 민감한 세부값,
원본 내용, 이름·메일·전화·후보 식별자를 남기지 않는다. 보호 위치, 가린 항목 종류, SHA-256 지문과
PII 없는 provenance만 허용한다. 구체적인 serializer·보존·삭제 계약은 병합된 C1 정본이 소유한다.

C1은 로그인 만료, 보안문자, 2단계 인증, 세션 충돌, 사람 입력, target 수 불일치, origin 불일치,
저장·보존·삭제 계약 불충족, `DRIFTED` 중 하나라도 만나면 자동 복구 없이 중단한다. C1 성공은 로그인
자동화나 후보 검색 완료가 아니다.

### 15. D1 인수 불변식

D1은 실제 포털에 접속하기 전에 중립 대상에서 최소한 다음을 증명해야 한다.

- 채널당 동시에 유효한 사용권은 하나뿐이다.
- 만료된 사용권과 더 작은 증가 번호의 명령은 모두 차단된다.
- target 0개와 2개 이상에서 외부 효과가 0이다.
- 허용 origin 밖 target이 하나뿐이어도 선택하지 않는다.
- 임의 raw 명령, 쿠키·저장소·자격증명 접근, 새 탭·창, 활성화, 닫기, 브라우저 종료 능력이 없다.
- 사람 입력 뒤 사용권이 즉시 취소되고 대기·재시도·콜백의 외부 효과가 0이다.
- 브라우저·프로필·포트·프로토콜 증거를 매 작업 새로 확인한다.
- 실패 시 다른 프로필·탭·브라우저·접속 방식으로 자동 전환하지 않는다.

이 가운데 하나라도 증명하지 못하면 D1은 실제 포털 연결 권한을 얻지 못한다.
