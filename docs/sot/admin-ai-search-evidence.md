# AI Search 관리자 증거 계약 (SOT)

최종 갱신: 2026-10-30

## 현재 제품 계약 — 기존 관리자 모듈 v2

현재 제품은 기존 관리자 앱의 `/admin/ai-search-weekly` 및 `/api/admin/ai-search/*`다.
기존 관리자 세션·내부 권한 검사를 재사용하며 로컬과 preview에서도 익명 접근을 허용하지 않는다.
아래의 `/ai-search` shadow 계약과 2026-10-29 수치는 이력이다. 현재 집계 기준은 본 절과
[실제 통합 명세](../engineering/admin-ai-search-native-spec-2026-10-30.md)가 우선한다.

- Gmail Inbox 전체와 현재 계정에서 확인한 `02aisearch` 라벨 전체의 **합집합**을 message ID로
  중복 제거한다. Sent 전체는 별도 컨택 근거 범위다. ID·메타데이터·본문을 끝까지 읽으며
  마지막 토큰이 없는 체크포인트만 수집 완료다. 중간 페이지 ID를 먼저 저장해 재개한다.
- 원본 MIME는 비공개 수집 저장소에 보존한다. DB에는 메일·첨부·실행·포지션·후보·평가·구성점수·
  컨택·근거·검토·체크포인트를 분리한다. 공개 정적 JSON과 클라이언트 자격증명을 금지한다.
- 내부 Batch ID는 영구다. 확정은 `W44-01`, provisional은 `W44-P01`이다. `(week_year,
  week_number, sequence)`와 provisional 예약을 DB에서 유일하게 보장한다. 확정 전환에도 내부 ID와
  과거 표시번호를 보존하고 번호를 재사용하지 않는다. 도착시각 근접만으로 실행을 합치지 않는다.
- 실행시각을 찾지 못하면 `received_at_fallback`과 사유를 표시한다. 명시적 run ID 또는 정확한
  실행시각·실행 완료 근거가 없는 묶음은 provisional이다. 과거 일자 기반 shadow 묶음을 승격하지 않는다.
- 주차는 Asia/Seoul 일요일 00:00 이상~다음 일요일 00:00 미만이다. 표시 W번호는 기존 주간 회의
  ISO 라벨을 재사용한다. 따라서 `2026 W44`는 `10.18~10.24`다. 실제 기간을 항상 함께 표시한다.
- 기본 행은 `(week_id, canonical_candidate_id, position_id)`다. 모든 Batch와 과거 평가를 별도로
  보존한다. 현재 parser version과 일치하는 PROCESSED 원문 해석만 현재 집계에 사용한다.
- Saramin `res_idx`, Jobkorea `rNo`, LinkedIn public/Recruiter 식별자를 보존한다. 이름이나 서로 다른
  채널만으로 병합하지 않는다. 프로필 링크는 http/https만 허용한다.
- 검증 점수는 40/40/10/10 계약의 네 구성 점수와 근거가 모두 있을 때만 계산한다. 메일 원본 점수는
  별도 필드다. 구성 점수가 없으면 NOT_RUN이며 역산하지 않는다.
- 고점수 기준은 `contracts/admin-ai-search/evidence-contract-v1.json`의 `weekly_contract`가 소유한다.
  기존 `90_plus` 구간의 하한 90을 v2 기준으로 명시했다. 화면·SQL은 저장된 설정을 읽는다.
- 각 후보+포지션의 SARAMIN / JOBKOREA / LINKEDIN / GMAIL 상태는 독립적이다. 허용 상태는
  CONTACTED / REPLIED / CONFIRMED_NOT_CONTACTED / NOT_RUN / REVIEW_REQUIRED / FAILED다.
  부재만으로 미발송을 확정하지 않는다. 후보 식별자·포지션·조회 범위·pagination 종료·확인시각·근거가
  있어야 음성 증거가 된다. 시각이 잘못되거나 미발송과 발송 근거가 상충하면 검토 대기다.
- Grok 등의 Gmail 총계 보고서는 원문과 reported totals로 보존한다. 총계를 후보에게 나누어 귀속하지
  않는다. 개별 근거가 연결되지 않은 발송은 review queue다. 주간 활동과 누적 상태를 구분한다.
- 고점수 미컨택자는 점수 PASS·기준 이상·필요 네 채널 확인 완료·양성 컨택 없음·미연결 발송 없음일
  때만 확정한다. 불완전한 점수·컨택·후보 해석은 0으로 표시하지 않는다. 관찰된 후보 수는 별도다.
- 이 모듈의 외부 효과는 Gmail/채용사이트 읽기 전용과 모듈 테이블 upsert뿐이다. 발송·라벨 변경·보관·
  삭제·채용사이트 수정은 금지한다. 배포와 머지는 현재 작업 범위에 없다.

## 과거 shadow 계약 — 호환성 및 감사 이력

아래는 초기 로컬 증거 화면의 계약을 보존한 것이다. 현재 제품 경로·행 정체성·수집 기준·수치는 위
v2 계약으로 대체된다. 과거 숫자는 현재 DB 기본값이나 정답이 아니다.

이 문서는 `/ai-search` 관리자 화면과 `/api/ai-search`가 무엇을 사실로 표시할 수 있는지 정한다.
AI Search 실행 절차 자체가 아니라, Gmail에서 이미 생성된 결과와 보낸편지를 읽어 운영자가 검증하는
증거 화면의 정본이다. 상세 설계와 실데이터 기준선은
`docs/engineering/admin-ai-search-evidence-spec-2026-10-29.md`가 소유한다.

화면의 기본 단위는 **주차별 2차원 운영 원장**이다. 카드나 개별 Batch 상세이 기본 탐색 구조가
아니다. 운영자는 한 주에 몇 Batch가 실행됐고, 각 Batch에서 어느 고객사·포지션으로 어떤 후보를
찾았으며, 어떤 AI가 검색했고 그 주에 AI 또는 사람이 어떻게 컨택했는지를 표의 한 행에서 확인한다.

## 1. 불변조건

1. Gmail 검색은 `next_page_token`이 없어질 때까지 읽는다. 끝나지 않은 수집은 PASS가 아니다.
2. 가짜 후보·샘플 숫자·추정 점수·추정 컨택을 만들지 않는다. 확인하지 못한 값은 0이 아니라
   `NOT_RUN`과 사유다.
3. 같은 Gmail message는 `stable_batch_id()`에 동일한 immutable message/run identity를 넣어 항상
   같은 Batch ID를 만든다.
4. 동일 실행 근거가 있는 후보별 알림은 한 Batch로 묶는다. run ID 또는 동일한 고객사·포지션·실행
   주체·날짜가 없으면 묶지 않고 사유를 남긴다.
5. 테스트·QA·회신·전달 등 실제 실행이 아닌 메일은 excluded로 분리하고 사유를 보존한다.
6. 후보 수 장부는 반드시 `raw = parsed + duplicate + unparsed + excluded`를 만족한다. 등식이
   확인되지 않은 Batch의 raw/unparsed는 숫자로 가장하지 않는다.
7. 프로필 정본키는 채널별 canonical profile URL에서 만든다. 이름만 같거나 서로 다른 채널이라는
   이유로 동일인이라고 합치지 않는다.
8. 실행 주체 허용값은 `GROK | CLAUDE_CODE | CHATGPT | AI_SEARCH | OTHER`다. 판단 근거로 제목,
   발신자, Gmail thread/message ID, 수신시각과 분류 사유를 저장한다.
9. Batch에는 고객사, 포지션, 채널, 검색 기간, 실행일시, 후보 수 장부, 점수대, 실제 후속 연락,
   검증 상태를 저장한다.
10. 후보에는 모든 고객사·포지션·Batch 이력과 학력, 전체 경력, 핵심 경력, 필수요건별 근거,
    적합 근거, 더 적합한 포지션 존재 여부, 컨택 출처·확인시각·의견 근거를 저장한다. 원문에 없으면
    필드를 만들지 않고 NOT_RUN으로 표시한다.

## 2. 점수 계약

점수는 네 축의 0~100 정수 입력이 모두 증거로 있을 때만 코드가 결정론적으로 계산한다.

- 학력 40%
- 직무적합성 40%
- 고난도 업무 10%
- 직무기술 논리성 10%

축 하나라도 없거나 상충하거나 범위를 벗어나면 총점과 90점 이상·80~89점·70~79점 구간은
`NOT_RUN`이다. Gmail 본문에 적힌 총점만으로 네 축을 역산하거나 LLM이 임의 점수를 만들지 않는다.

## 3. 직접 컨택 계약

Gmail 보낸편지의 실제 제안 메일을 읽어 발송 주체를 `AI | OWNER | UNKNOWN`으로 저장한다. 이벤트마다
발송시각, 제목, Gmail message/thread ID, 주체 판단 근거를 보존한다. 후보 정본 프로필 URL이 메일에
명시된 경우에만 후보에게 연결한다. 이름·수신자·서명·문체로 연결하지 않는다.

화면은 전체 직접 제안 수와 후보 연결 수를 분리한다. “직접 제안 8건, 후보 연결 0건”은 0건의
컨택이 아니라 8건의 실재 발송과 0건의 안전한 후보 귀속을 뜻한다.

## 4. 화면 계약

- 주차는 KST 일요일 00:00부터 다음 일요일 00:00 직전까지다. 기존 관리자 주간 계약과 같이 해당
  기간이 끝난 뒤의 운영회의 ISO 주차로 표기한다. 예: `2026-W34 · 2026.08.09~2026.08.15`.
- 주차 선택기는 Gmail 증거에 존재하는 최초 주차부터 최종 주차까지 빠짐없이 제공한다.
- 상단은 실행 Batch 수, 주간 고유 후보 수, 후보·포지션 행 수, AI 발송, 사람 직접 발송,
  후보 연결/미연결을 분리해 표시한다.
- 후보 서치 원장의 한 행은 `(batch_id, canonical_key)`다. 즉 **한 행 = 한 Batch의 중복 제거 후보
  1명**이다. 같은 후보가 같은 Batch에서 중복되면 한 번만 표시하고, 다른 고객사·포지션 Batch에
  등장하면 그 이력을 잃지 않도록 별도 행으로 표시한다. 주간 고유 후보 수에서는 한 번만 센다.
- 후보 서치 원장 열은 실행 일시, 간략 Batch 표기, 고객사, 포지션, 검색 AI, 후보자, 프로필 URL,
  채널, 학력, 전체·핵심 경력, 점수, 점수·적합 이유, 주간 컨택이다.
- 주간 컨택 원장은 Gmail 보낸편지 이벤트를 발송 일시, 발송 주체, 제목, 연결 후보, 연결 상태,
  message/thread ID로 표시한다.
- 후보 프로필 URL로 연결된 컨택도 어느 Batch의 후속 연락인지 근거가 없으면 후보 수준으로만
  표시한다. 같은 후보의 여러 Batch 행에 특정 Batch 후속 연락처럼 귀속하지 않는다.
- 빈 상태: 수집 대상 없음과 수집 미실행을 구분한다.
- 오류 상태: API·계약 오류를 빈 목록이나 PASS로 바꾸지 않는다.
- 최소 본문 글자는 16px, 운영 표 본문은 16px 이상을 기본으로 하며 내부 해시를 주 정보로 쓰지 않는다.
- 포괄적인 “판정 근거” 메뉴는 두지 않는다. 사용자가 요구한 구체 증거 필드만 상세에 둔다.

주간 원장의 전용 읽기 API는 `GET /api/ai-search/weekly`와
`GET /api/ai-search/weekly/{week_id}`다. 첫 API는 주차와 집계만 반환하고, 두 번째 API는 선택한 주의
후보·컨택 행을 반환한다. 초기 화면에서 전체 원문 payload를 내려받지 않는다.

## 5. 외부 효과와 비범위

Gmail과 채용사이트는 읽기 전용이다. 외부 발송 0건, 채용사이트 변경 0건, 원격 DB 쓰기 0건을
유지한다. FU 채용사이트 검증과 Daily 재검증은 이 화면 구현의 비범위이며 실행하지 않은 값을
PASS로 바꾸지 않는다. 머지·배포는 오너의 별도 결정이다.

## 6. 완료 증거

코드 변경은 focused pytest의 RED→GREEN, 전체 pytest, ruff, mypy strict, `bash verify.sh`, API
readback, 주차 선택·후보 서치 원장·주간 컨택 원장·빈 상태·오류 상태 브라우저 확인을 거친다. 실데이터 숫자는
수집 시각과 query, pagination 종료 여부와 함께 보고한다.
