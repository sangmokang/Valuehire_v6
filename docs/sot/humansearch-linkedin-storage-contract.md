## 입력·출력·오류

저장 입력은 같은 실행·포지션·후보에 결합한 관측 증거다. 타입과 구간 판정은 HS-02.01~03을 재사용한다.
별도의 LinkedIn 전용 manifest나 원본 SQLite를 만들지 않는다.

| 입력 | 필요한 근거 |
|---|---|
| 실행·포지션·후보 참조 | 현재 checkpoint·후보 잠금과 같은 대상, 안정 ID 재조회 |
| 브라우저 관측 참조 | Aside 앱·승인 RPS 계정/프로필·정확한 탭·origin·관측 시각 |
| 출처·검색 조건 | 보호된 원문 URL, 프로젝트 ID, 실제 적용 필터와 반복 검색식 버전 |
| 상세 증거 | 관측 구간·화면 크기·문서 높이 상태·파일 지문·텍스트와 출처 구간 연결 |
| 완전성 | 전체/부분/실패, 누락 구간·동적 높이 변경·중단·실패 사유 |
| 추출 필드 | 학력·회사별 경력/담당 업무·관측 연락처, 값/빈 값/미관측/미제공 구분 |

→ 입력의 완료 상태를 신뢰해 그대로 저장 성공으로 만들지 않는다. 공통 검증기가 실제 구간·파일·해시를 대조한다.
부분 자료를 전체라고 표시하지 않고, 관측하지 않은 내용을 채워 넣지 않는다.
해시 불일치·손상·누락은 유효한 전체 증거로 받아들이지 않는다.
이미 확보한 부분 증거는 보호 저장 경계에서 실패 사유와 함께 보존하며 순회를 정지한다.

반환값은 `evidence_ref`, `coverage_status`, `storage_status`, `readback_ref`, `error_code`다.
`storage_status`의 상태명과 전이는 HS-04.01 공통 저장 계약이 단일 소유한다. LinkedIn 전용 상태 enum을 만들지 않는다.
파일 쓰기 응답만으로 저장 완료가 되지 않는다. 별도 연결의 실제 재조회가 복호화된 원문·manifest·SQLite의
같은 후보·실행·지문 관계에 일치해야 한다. 부분 열람을 저장 완료해도 `coverage_status`는 부분으로 유지한다.
검증 실패·쓰기 실패·대상 불일치는 오류로 반환하고 빈 성공 객체로 변환하지 않는다.
원본 URL은 저장 전에 인증·세션 query/fragment 값을 제거한다. 안전한 출처를 만들 수 없으면
민감 URL을 저장하지 않고 출처 미확정과 실패 이유를 남긴다. 보존한 탭·origin은 다음 실행의 선택 증거가 아니다.
일반 로그에는 비민감 상태와 영수증 참조만 남기며 후보 이름·원문 URL·연락처·세션 값은 넣지 않는다.

## 전량 저장과 순회 경계

1. 상세를 열기 전에 저장 권한·암호화 준비·용량 오류 처리·현재 사용권·후보 잠금을 확인한다.
2. 새로 관측한 구간은 보호 저장 경계에 전달한다. 목록 복귀 뒤 한꺼번에 저장하는 방식으로 유실 창을 만들지 않는다.
3. 상세의 안정 ID와 구간 증거를 공통 SQLite의 실행·후보·증거 관계에 연결한다.
4. 독립 실행기가 저장 파일과 DB 관계를 새 연결로 읽어 후보·원문 지문·완전성을 확인한다.
5. 저장과 재조회 확인 뒤 목록 복귀·다음 후보 외부 호출 직전에 사용권·만료·증가 번호·사람 개입·STOP을
   다시 확인한다. 하나라도 불일치면 새 호출을 보내지 않는다. 부분이면 부분 상태를 유지한다.

명시적 STOP 뒤에는 새 브라우저 호출을 보내지 않는다. 이미 관측한 자료의 로컬 저장·복구 기록은
브라우저 자동 재개와 구분한다. 종료로 저장이 미확정이면 checkpoint를 미완료로 남긴다.
보호 저장 자체가 실패하면 공통 저장 계약의 암호화 recovery 위치로 복구를 시도하고, 거기도 실패하면
메모리에 있는 이미 관측 자료의 보존을 시도하되 영속 보존 성공을 주장하지 않는다. 원본 쓰기와 checkpoint
기록이 모두 불가능할 수 있으므로 시작 전 intent를 미완료로 두고 성공 재조회 전에는 완료로 바꾸지 않는다.
재시작은 저장 결과부터 확인하고 기존 완료 후보를 새로 열어 중복 증거를 만들지 않는다.
STOP은 새 관측만으로 해제하지 않는다. 자동 재개는 HS-05.07·HS-06.01의 조건을 따른다.

## 개인정보·보존·삭제

사용자가 승인한 열람 증거의 원본은 암호화된 로컬 저장과 공통 SQLite가 소유한다.
Supabase는 후속 허용 열·권한 계약을 통과한 파생 저장이며 원본을 역으로 덮어쓰지 않는다.
보존은 9월 8일 결정에 따라 무기한이다. 기간 만료 자동 삭제를 추가하지 않는다.
삭제는 명시적 `/hs purge`의 확정 대상에 한하며 HS-03.05가 개인정보 없는 영수증을 남긴다.
권한·대상 모호·일부 삭제 실패는 성공으로 보고하지 않는다. 정책은 HS-04.01, 암호화·키 구현은 HS-03.03, 권한 분리는 HS-04.02~04가 소유한다.

연락처는 1촌의 실제 표시된 값만 취득한다. 비표시 주소를 추정하거나 외부 자료로 보충하지 않는다.
관측 증거의 보존과 후보 연락처 필드의 추출·공유는 다른 경계다. 승인되지 않은 연락처를 공유 필드로 내보내지 않는다.
인증 값은 증거 수집 대상에서 제외하며, 예외·디버그·리뷰 산출물에도 복사하지 않는다.
같은 사용자 권한의 별도 모델 검토는 맥락 독립성만 뜻하며 OS 쓰기 권한 격리를 증명하지 않는다.
