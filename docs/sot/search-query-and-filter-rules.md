# 서치 검색어·채널 필터 규칙 (SOT)

- 제정: 2026-09-27, 사장님 지시 및 1촌·필터 재서치 시행착오
- 적용: Claude·Codex search 스킬 공통(`~/.claude/skills/search`, `~/.codex/skills/search`)


- 기술용어는 영문만 고정하지 않는다. JD 핵심 키워드마다 영문·한글 표기, 띄어쓰기·붙여쓰기, 약어·정식명, 업계에서 실제 쓰는 유관어를 검토하고 검색에 사용할 변형과 제외어를 기록한다(예: Braze·브레이즈, lifecycle·라이프사이클, A/B·AB 테스트).
- 키워드 = JD 핵심 키워드 + 유관 검색어 + 그 직무 최상위 실무자들이 서로 쓰는 실무 용어(mutual jargon)다. 예: Data Engineer → Spark, Flink, Kafka, Iceberg, CDC, Debezium, dbt, lakehouse, backfill. 실무 용어는 검색 가설을 넓히는 데만 쓰며 JD 필수요건을 몰래 바꾸지 않는다.
- 검색 전 JD의 회사·직무·경력요건을 한 줄로 고정한다. J01 번개장터 Product Manager(Core Product)와 J06 스푼랩스 CRM Marketer처럼 URL·포지션 ID가 다른 업무는 후보·필터·메일을 섞지 않는다.
- 회사 LinkedIn 직원 프로필은 현업 용어·역할·경력 흐름과 학력 분포를 파악하는 참고 표본으로 사용한다. 사용자 명시 기준에 따라 교육 배경 우선순위(인서울 대학·주요 지방 국공립대·아래 인천 소재 2개 대학)를 후보 평가의 보조 가중치로 기록하되, 후보 본인 프로필에 실제 표시된 학교·학위·전공만 사용한다.

## 학력 순위 참고 기준 (2026-09-28 웹 확인)

- 공개 순위의 정본은 [QS 서울 도시 페이지](https://www.topuniversities.com/university-rankings-articles/qs-best-student-cities/seoul)와 [Times Higher Education(THE) 한국 대학 2026 순위](https://beta.timeshighereducation.com/student/best-universities/best-universities-south-korea)다. QS 페이지에 표시된 순위판은 [QS 2027 세계 대학 순위](https://www.topuniversities.com/world-university-rankings)로 확인했다. QS 페이지에는 경기도 소재 대학도 있으므로 아래 서울 소재 항목만 발췌한다. THE에서는 **비수도권 국공립 종합대**를 발췌하고 인하대·인천대는 인천 소재 대학으로 별도 표기해 한국 내 순위·동률을 확인한다. 서울·경기·인천 소재 대학과 과학기술 특성화대학은 지방 국공립대 목록에 포함하지 않는다. 서로 다른 기관의 숫자를 합쳐 단일 전국 순위나 점수로 만들지 않는다. 조회일은 2026-09-28이며, 순위판과 조회일을 함께 남기고 새 판이 나오면 출처를 다시 확인해 이 절을 갱신한다.
- **서울 소재 대학 참고 순서(QS 2027 세계 순위)**: 서울대(세계 38위) → 연세대(42위) → 고려대(공동 52위) → 성균관대(108위) → 한양대(155위) → 경희대(공동 309위) → 세종대(공동 398위) → 중앙대(공동 432위) → 이화여대(공동 488위) → 서강대(공동 494위) → 동국대(520위) → 한국외대(공동 620위) → 건국대(공동 683위) → 서울시립대(851–900위) → 서울과기대(1001–1200위) → 숙명여대·성신여대(각 1201–1400위) → 홍익대(1401위 이상). 동률·구간은 그 상태로 보존하며 구간 안에 임의 순서를 붙이지 않는다. QS의 도시 목록이 모든 인서울 대학을 망라한다고 해석하지 않는다.
- **주요 지방 국공립대 참고 순서(THE 2026 한국 내 순위)**: 경북대·부산대(공동 15위) → 전남대·전북대(공동 23위) → 충북대·충남대(공동 27위) → 경상국립대·제주대·강원대·부경대(공동 30위). 이는 THE에 수록된 비수도권 국공립 종합대 발췌 목록이다. 목록에 없는 대학의 품질이나 후보 적합성이 낮다는 뜻이 아니다. KAIST·POSTECH·UNIST 등 특성화대학은 별도 분야·JD 근거로 판단한다.
- **인천 소재 대학 별도 참고(THE 2026 한국 내 순위)**: 인하대(공동 23위), 인천대(공동 30위). 두 대학은 수도권에 있으므로 위 지방 국공립대 목록이나 QS 서울 목록에 넣지 않는다.
- 순위는 **검색 순서와 동일한 직무 근거를 가진 후보 사이의 보조 참고**에만 사용한다. 후보 본인 프로필 원문에 실제 학교와 캠퍼스가 확인되고 필요한 학위·전공·졸업 상태가 확인된 범위에서만 기록한다. 원문에 없거나 동명이교·캠퍼스가 불명확하면 `학력 확인되지 않음`으로 두고 순위 가중치를 적용하지 않는다. 과학고·외고도 후보 본인 원문에서 실제 고교와 학교 유형이 확인될 때만 작은 보조 우대로 기록하며, 별도 고교 순위는 만들지 않는다. JD의 직접 관련 전공·학위·면허 요건, 직무 적합성, 성과, 현재 재직 상태보다 앞세우거나 순위 밖 학교를 자동 탈락시키지 않는다. 회사 직원의 학력 분포는 검색어·학교 필터 탐색 참고일 뿐 후보 개인의 학력을 추정하는 근거가 아니다.
- 후보가 과거에 목표 회사에 재직했다는 사실만으로 현재 적합하다고 판정하지 않는다. 현재 회사·직무·재직 상태는 후보 본인 최신 프로필 원문으로 확인한다.
- 프리랜서·단기계약 표시는 JD 또는 고객 지시가 명시하지 않는 한 자동 탈락이 아니다. 다만 정규직 전환 가능성·현재 계약 상태가 확인되지 않으면 추천이 아닌 확인 필요로 둔다.
- 국적·외국인 여부는 선별 기준으로 사용하지 않는다. JD에 직접 관련되고 후보 원문이 뒷받침하는 한국어 업무 수행, 근무지 접근성, 합법적 근무 가능 여부만 별도 확인 항목으로 기록한다.
- 후보와 검색 결과를 저장할 때는 후보 본인 원문·URL·관찰 시각·보이는 화면 캡처가 서로 같은지 확인한다. listing만 저장된 후보는 상세 검증 후보로 세지 않는다.
- 검색은 후보 수나 조합 수를 채우기 위한 작업이 아니다. 검색어 변형·필터·결과 페이지를 충분히 시도했는지, 새 검색의 정보가치를 판단했는지 기록하고 추가 후보가 반복되거나 가치가 낮으면 종료 사유를 남긴다. 반대로 관련 후보가 계속 나오면 더 탐색한다.
- 사람인 인재풀 필터는 새 후보군을 찾을 때마다 바꾼다: 경력 하한(N년 이상)과 상한(N년 이하)을 JD에 맞춰 둘 다 쓰고, 근속연수·휴식기간·연봉·직무 카테고리·기업규모·재직/구직·정렬(업데이트일순)을 조합마다 달리한다. 업데이트 기간 드롭다운은 최대 24개월이므로 "기간 넓히기"는 다른 필터 해제로 대신하고, 경력 필터와 혼동해 보고하지 않는다.
- 사람인 상단 초기화는 경력 select를 지우지 않는다. 조합마다 경력을 명시(조건 없으면 빈 값)하고, 입력 후 검색바 문자열과 총 인원을 확인한다(유니코드 입력 오타·이전 키워드 잔존 방지). 목록이 60 미만인데 총 인원이 크면 로딩 미완이므로 재수집하고, 반복되면 사유를 기록한다.
- RPS "multiple sign-ins" 화면이 뜨면 다른 세션을 로그아웃시키지 말고 BLOCKED_SESSION_CONFLICT로 즉시 보고한다.
- 채널 카드에 기존 제안/저장 이력이 보이면 prior_contact로 선별·메일에 명시한다.
- RPS 필터 입력은 칸마다 Return으로 확정하고, 검색 전 필터 요약(Keywords·Job titles·Network·Seniority·Location)을 다시 읽어 빠진 칸이 없는지 확인한다. 한 칸을 입력하면 다른 칸의 미확정 입력이 버려지는 경우가 있다.
- 사람인 인재풀 페이지를 새로고침하면 페이지 보조 스크립트가 사라진다. `artifacts/search-20260924/bin/sr_helpers.js`를 다시 주입하고, 검색바가 빈 상태로 돌아왔는지 확인한 뒤 조합을 입력한다.

## 2026-09-28 추가 (브라우저 확장 미연결 세션 · 신규 4포지션 서치)
- 2026-09-28 사장님 지시(재발 금지) — **Aside 에 이미 열린 사람인·RPS 창/탭을 재사용한다. 새 창·새 탭을 만들지 않는다(`make new window`·`make new tab` 금지).** 시작 시 AppleScript 로 전 창의 탭 id·URL 을 읽고, 이미 있는 RPS(`linkedin.com/talent/...`) 탭과 사람인 인재풀(`saramin.co.kr/zf_user/memcom/talent-pool/...`)·이력서(`hiring.saramin.co.kr/applicant-view/...`) 탭의 id 를 골라 그 탭의 URL 만 바꿔 쓴다. 보이는 탭이 필요한 작업(RPS 목록 수집·사람인 이력서 캡처)은 이미 열린 RPS/사람인 탭 중 자기 창의 활성 탭인 것을 우선 쓰고, 사장님 메인 창의 활성 탭을 다른 탭으로 바꾸지 않는다. 숨김이어도 되는 작업(RPS 프로필 본문 읽기·사람인 목록 수집)은 비활성 기존 탭에서 한다. 다른 세션이 쓰는 탭(최근 1시간 산출물·실행 중 스크립트에 그 탭 id 가 있음)은 건드리지 않는다. 쓸 만한 기존 탭이 하나도 없을 때만 사장님께 한 줄 알리고 새 탭 1개를 연다.
- Claude 확장이 세션에 안 붙어 있으면 Aside 를 AppleScript `execute tab ... javascript` 로 조작한다(탭은 순번이 아니라 탭 id 로 지정 — 사장님/다른 세션이 탭을 옮기면 순번이 바뀐다). 창 id 숫자는 osascript -e 문자열에 직접 넣으면 실수형으로 바뀌어 실패하니 인자로 넘긴다.
- 창이 가려지거나 비활성 탭이면 `document.visibilityState=hidden` → 타이머가 분 단위로 느려지고, RPS 결과 목록은 화면에 보일 때만 카드를 그려 페이지당 5명만 잡힌다. RPS 목록 수집·사람인 이력서 캡처는 반드시 보이는 탭(창의 활성 탭)에서 한다. RPS 프로필 본문 읽기와 사람인 목록 수집은 숨김 탭에서도 된다.
- 창이 앞에 있지 않으면 `el.focus()` 가 포커스 이벤트를 내지 않는다. 사람인 검색어 칸은 `focusin` 이벤트를 직접 보내야 열리고, 실제 입력칸은 드롭다운 안의 `.search_detail input.search_input` 이다(겉의 `input.search_input.result` 가 아님).
- 사람인 '우수 재학 경력' 스페셜 태그(tag_res_100 국내 유명 대학·tag_res_101 인서울 대학)로 학교 1차 거름, 최종은 카드 원문의 학교명(예: 한양대학교(서울))으로 판정한다. 분교(세종·원주·ERICA·안성)는 제외.
- RPS 학교 필터는 오른쪽 "Schools (Schools attended)" — 첫 클릭이 다른 열린 칸을 닫는 데 쓰여 입력칸이 안 열리는 경우가 많다. placeholder "enter a school…" 입력칸이 보일 때까지 다시 누른다. 자동완성은 click 만으로는 안 되고 pointerdown·mousedown·mouseup·click 순서로 보내야 칩이 붙는다.
- RPS 필터 결과를 브라우저 localStorage 에 쌓으면 이전 세션 기록 때문에 저장 한도 초과로 실패한다 → 결과는 스크립트 반환값으로 바로 파일에 쓴다.
- 사람인 상세 이력서 본문은 닫힌 shadow DOM 에 그려져 텍스트로 못 읽는다 → 보이는 탭에서 창 단위 캡처(`screencapture -l <CGWindowID>`)로 읽는다.
