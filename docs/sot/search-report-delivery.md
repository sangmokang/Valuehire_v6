# 후보 서치 결과 보고 메일 계약 (SOT)

최종 갱신: 2026-09-17 (사장님 직접 지시로 신설)

## 1층 — 결론

후보 서치 결과는 **사장님 본인 주소(sangmokang@valueconnect.kr)로** 보낸다. 사장님이 "보내"라고 했으면
확인 질문 없이 바로 발송한다. 결과는 첨부에만 두지 않고 **메일 본문에 전체 명단·전 필드를 모두 적는다.**
"보내"는 사장님에게 보내라는 뜻이며, 후보자·고객사 등 제3자에게 보내라는 뜻이 아니다.

## 2층 — 판단 근거

**무엇을** — 서치 리포트 메일의 수신자·발송 시점·본문 범위를 고정한다.

**왜** — 2026-09-17 패스트뷰 AI Engineer·마케터 서치에서 본문엔 상위 45명만 싣고 나머지를 엑셀 첨부로
돌린 뒤 "후보자 소개 메시지 초안을 만들어 둘까요?"라고 물었다. 사장님 지시: "그냥 보내. 이럴때는 그냥
보내 그리고 메일 본문에 다 적어. 앞으로 기억해 보내라고 했으면 보내", "후보자에게 보내는게 아니라 나한테
보내라고". 사장님은 메일 본문만 보고 판단하며, 확인 질문은 작업을 멈춘다. 2026-09-16에는 Codex가
후보자에게 제안 메일을 직접 보내는 오발송이 있었다.

**버린 길** — 본문 요약 + 첨부 전체, 발송 전 확인 질문. 둘 다 사장님이 명시적으로 거부했다.

**대가** — 본문이 수백 KB가 되어 Gmail에서 잘려 보일 수 있다("전체 메시지 보기"로 열람). 첨부는 보조로 함께 붙여도 된다.

**되돌리기** — 사장님의 새 지시로만 바꾼다.

## 3층 — 정본 계약

1. **수신자** — 기본 수신자는 sangmokang@valueconnect.kr 하나다. 발송 코드는 수신자를 고정하고
   To 이외(Cc·Bcc)를 두지 않는다. 사장님이 다른 내부 수신자를 명시한 경우에만 추가한다.
2. **발송 시점** — 요청에 "보내"가 있으면 결과가 준비되는 즉시 발송한다. "보낼까요?", "초안 만들어 둘까요?"
   같은 확인 질문을 하지 않는다. 발송 후 대화에는 결과만 짧게 보고한다.
3. **본문 범위** — 수집한 후보 **전원**을 본문 표에 싣는다. 필드: 순위, 점수(수동/자동 구분), 이름, 촌수,
   현재 직함@회사, 경력 연수, 학력, 프로필 URL, 이메일, 적합 사유, 기존 컨택 이력, 주요 경력.
   채점 기준과 컨택 이력 대조 범위도 본문에 적는다. 첨부 엑셀은 같은 내용의 보조본이다.
4. **제3자 발송 금지** — 후보자·고객사 등 사장님 외 사람에게 메일·InMail·메시지를 보내는 것은 이 계약으로
   허용하지 않는다. 사장님이 대상과 내용을 명시해 따로 지시한 경우에만 한다
   ([humansearch-browser-contract.md](humansearch-browser-contract.md)의 발송 자동화 금지와 같다).
5. **발송 경로** — 첨부가 있는 메일은 Gmail MCP로 base64를 직접 쓰지 않는다. 로컬 발송 토큰
   (`Valueconnect-Ops/apps/gmail-clickup-sync/config/gmail-token-send.json`, gmail.send 스코프)으로 `users/me/messages/send`를
   호출하고, 발송 후 Gmail에서 SENT 라벨·수신자를 조회해 확인한다. 토큰 값은 출력·커밋하지 않는다.
