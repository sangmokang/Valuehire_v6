# 밸류커넥트 채용 수수료 Invoice 정본

최종 갱신: 2026-09-01
기계 계약: `contracts/invoice/invoice-v1.json`
구현·검증 근거: `docs/engineering/invoice-skill-goal-2026-09-01.md`

## 목적과 적용 범위

`invoice` 스킬은 밸류커넥트 주식회사가 고객사에 청구할 채용 수수료를 결정 연봉에서 계산하고, 한 페이지 A4 PDF를 만든 뒤, 최종 승인된 경우에만 지정 Gmail 수신자로 보낸다. Codex와 Claude는 이 문서와 같은 기계 계약·렌더러를 사용한다.

이 문서는 일반 청구서의 업무 계약이다. 세금계산서 발행, 회계 분개, 계약서 법률 해석은 포함하지 않는다.

## 정본 우선순위

1. 현재 요청에서 사용자가 명시한 값
2. 이 문서의 업무 규칙
3. `contracts/invoice/invoice-v1.json`의 기계 판독 값
4. 일반 양식 관례

문서와 JSON이 다르면 최종 PDF나 메일을 만들지 말고 `CONTRACT_ERROR`로 중단한다. 계산·계좌·수신자 같은 운영 상수는 런타임 코드나 스킬에 복사하지 않고 JSON에서만 읽는다. 회귀시험은 정본 드리프트를 빨간불로 만들기 위해 현재 상수를 기대값으로 잠글 수 있지만 운영 값을 공급하는 경로로 사용하지 않는다.

## 입력 계약

한 인보이스는 한 입사자만 다룬다. 여러 입사자는 각각 별도 PDF로 만든다.

필수 입력:

- 수신 회사명
- 입사자명
- 입사일 `YYYY-MM-DD`
- 직책
- 결정 연봉: `annual_salary_krw` 원 단위 양의 정수 또는 `annual_salary_manwon` 만원 단위 양의 정수 중 정확히 하나
- 발행일 `YYYY-MM-DD`
- 인보이스 번호
- 검수본 여부

수수료·총액·납부 기한은 입력받지 않고 계산한다. 입력에 `fee_amount`, `requested_fee`, `total_amount`, `due_date`가 있으면 자동 계산을 우회하려는 값이므로 거부한다.

문자열은 앞뒤 공백 제거 후 1~120자이고 HTML 예약 문자는 이스케이프한다. 만원 입력은 코드가 10,000을 곱해 원화로 바꾸며, 변환한 연봉은 1원 이상 10,000,000,000원 이하의 정수여야 한다. 날짜는 실제 달력 날짜여야 한다.

## 계산 계약

### 요청 수수료

- 검수본 기본 수수료율: 결정 연봉의 20%
- 근거: 사용자가 제공한 두 예시가 각각 60,000,000원 → 12,000,000원, 40,000,000원 → 8,000,000원으로 일치한다.
- 계산: `결정 연봉 × 0.20`
- 계산기는 이진 부동소수점이 아니라 십진수 연산을 사용하고 원 단위에서 반올림한다.
- 수수료율은 고객사별 계약서 자동 판독값이 아니다. 사용자가 다른 비율을 명시하면 이 SOT와 기계 계약을 먼저 개정하고 같은 변경에서 시험한다.

### 납부 기한

- 계산: `입사일 + 달력 날짜 14일`
- 예: 2026-09-01 입사 → 2026-09-15 납부 기한
- 주말·공휴일·영업일 보정은 적용하지 않는다. 계약서 원문이 다른 규칙을 정하면 이 SOT를 먼저 고친다.

### 총 청구 금액과 세금

- 현재 부가가치세 기준은 `UNCONFIRMED`다.
- 검수본에서는 요청 수수료를 “세금 처리 전 검수용 총액”으로 표시한다.
- `UNCONFIRMED` 상태에서는 최종본 생성과 메일 발송을 금지한다.
- 사용자가 `EXCLUSIVE`, `INCLUSIVE`, `NOT_APPLICABLE` 중 하나를 확정하면 총액 계산·표시·시험을 같은 변경에서 갱신한다.

## PDF 양식 계약

- A4 세로 1페이지, 흰 배경, 짙은 남색과 중립 회색만 사용한다.
- 상단에는 `INVOICE / 채용 수수료 청구서`, 발행자, 발행일, 인보이스 번호, 수신 회사를 둔다.
- 본문은 입사자명, 입사일, 직책, 결정 연봉을 행 단위로 정렬한다.
- 금액 영역은 요청 수수료와 총 청구 금액을 오른쪽 정렬하고 원화 천 단위 쉼표를 사용한다.
- 하단 결제 영역은 납부 기한, 은행, 계좌번호를 한눈에 읽게 분리한다.
- 검수본은 `DRAFT · 검수용` 표식과 “메일 발송 안 됨” 문구를 표시한다.
- 계산용 입력이나 내부 수수료율 필드는 본문에 노출하지 않는다. 사용자가 요구한 `요청 수수료` 결과만 표시한다.
- 페이지 밖 넘침, 글자 겹침, 잘린 계좌·금액, 한글 대체 글리프, 2페이지 분리는 실패다.

## 파일과 개인정보

- 실제 후보자 입력·HTML·PDF·메타데이터·PNG는 `artifacts/invoices/` 아래에만 둔다.
- 실제 후보자 이름은 추적 문서, 시험 fixture, 커밋 메시지, 생성 파일명에 넣지 않는다.
- 기본 파일명은 `invoice-review-NNN`처럼 개인을 식별하지 않는 값을 쓴다.
- 출력이 이미 있으면 명시적 `--overwrite` 없이는 덮지 않는다.
- 메타데이터에는 입력/PDF SHA-256, 계약 버전, 계산 결과를 기록한다. 이 파일도 개인정보 산출물로 취급한다.

## 이메일 계약

- 기본 수신자: `sangmokang@valueconnect.kr`
- 기본 제목: `[밸류커넥트] 채용 수수료 인보이스 — {회사명} / {입사자명}`
- 본문은 회사명, 입사자명, 요청 수수료, 총 청구 금액, 납부 기한, 첨부 파일명을 간결하게 요약한다.

Python 렌더러에는 메일 전송 기능이 없다. `delivery` 값은 Codex·Claude 스킬이 연결된 Gmail 도구를 호출하기 전에 읽어 강제할 워크플로 계약이며, 렌더러 자체가 발송을 막는다고 주장하지 않는다.

발송 순서의 불변조건:

1. PDF 생성과 시각 검수가 `PASS`여야 한다.
2. 세금 기준이 확정되고 기계 계약의 `send_enabled`가 `true`여야 한다.
3. 스킬은 수신자, 제목, PDF 경로, PDF SHA-256, 요청 수수료, 총액, 납부 기한을 사용자에게 한 번에 보여준다.
4. 사용자가 그 구체적인 발송을 승인한 뒤에만 연결된 Gmail 발송 도구를 1회 호출한다. “PDF 만들어”, “검수본 보여줘”, 과거의 일반 발송 의향은 이 승인으로 세지 않는다.
5. 성공 응답의 Gmail 메시지 식별자를 다시 읽어 수신자와 첨부 유무를 확인한다. 도구가 없거나 확인이 안 되면 성공으로 보고하지 않는다.
6. 실패 뒤 자동 재발송하지 않는다. 같은 PDF SHA-256의 재발송은 새 사용자 승인이 필요하다.

Codex와 Claude의 Gmail 도구 이름이 달라도 위 계약은 같다. 연결된 Gmail 도구가 없는 플랫폼은 PDF와 메일 초안까지만 만들고 `BLOCKED`로 보고한다. SMTP 자격증명을 새로 요구하거나 소스에 저장하지 않는다.

## 상태 계약

- `PASS`: 입력·계산·PDF·메타데이터가 모두 완성되고 검수 항목이 통과함
- `FAIL`: 입력·계약·계산·렌더·시각 검사 중 하나가 위반됨
- `NOT_RUN`: 필수 실행을 시작하지 못했거나 결과를 읽지 못함
- `BLOCKED`: 최종 발송에 필요한 사용자 승인·세금 결정·Gmail 연결처럼 작업 권한 밖 조건이 없음

`PASS`인 검수본은 “메일 발송 완료”를 뜻하지 않는다. 생성과 발송은 별도 상태로 보고한다.

## 현재 미확정 사항

최종 발송 전에 사용자 결정을 받아 이 문서와 JSON 계약을 함께 갱신한다.

1. 부가가치세: 별도 10%, 수수료에 포함, 비대상 중 선택
2. 최종 인보이스 번호 규칙: 순번 사용 여부와 중복 방지 기준
3. 계좌 예금주 표시 여부와 정확한 표기
4. 회사 사업자등록번호·주소·대표자·담당 연락처 표시 여부
5. 14일째가 휴일일 때 계약상 납부일 조정 여부

## 변경 절차

계산, 계좌, 수신자, 세금, 발송 승인 규칙을 바꿀 때는 문서와 JSON 계약, 계산·렌더 시험, Codex·Claude 두 스킬의 공통 계약 검사를 같은 변경에서 실행한다. 실제 후보자 자료는 근거 문서에 복사하지 않는다.
