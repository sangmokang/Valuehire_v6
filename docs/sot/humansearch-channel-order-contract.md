# HumanSearch 채널 순서·잡코리아 우선 계약 (SOT)

최종 갱신: 2026-09-14

## 1층 — 결론

HumanSearch의 다음 라이브 완주 순서는 사람인 완주를 기다리지 않고 잡코리아를 먼저 진행할 수 있다. 이 변경은 채널 순서만 바꾸며, 공통 증거·저장·브라우저 권한·사용권·STOP·checkpoint·후보 잠금 선행 조건을 낮추지 않는다.

사람인은 실제로 확인된 결제 제한만 보류한다. 목록, 검색, 상세 중 어느 단계가 막히는지는 아직 실측되지 않았으므로 미리 실패로 확정하지 않는다. 결제와 카드 삭제는 하지 않는다.

## 2층 — 판단 근거

기존 HS-11 장부는 잡코리아와 LinkedIn 확장의 선행을 HS-07 사람인 1명 완주로 두었다. 2026-09-14 최신 실행 지시는 사람인 미결제가 다른 채널 작업을 막지 않게 하고, 잡코리아와 RPS를 이번 필수 대상으로 유지하라고 바꿨다.

따라서 의존성은 두 층으로 나눈다. 모든 채널이 공유하는 안전·저장·중단 기반은 여전히 선행이다. 반면 사람인 전용 화면 구현과 사람인 실제 완주 증거는 잡코리아의 필수 선행이 아니다.

**무엇을** — 잡코리아 HS-11.01→02→07→08→09→10을 사람인 HS-07 완주 없이 시작할 수 있게 한다.

**왜** — 사람인 결제 상태가 미확정인 동안에도 잡코리아와 RPS의 독립 작업을 진행하라는 최신 결정 때문이다.

**버린 길** — “사람인 HS-07 실제 완주 전에는 잡코리아를 시작하지 않는다”는 과거 의존성을 버린다.

**대가** — 잡코리아 완주는 사람인 성공을 대신 증명하지 않는다. 잡코리아용 화면 계약, precise origin, 검색·상세·저장·복귀 증거를 별도로 가져야 한다.

**되돌리기** — 새 결정으로 채널 순서를 다시 묶을 수 있다. 단, 과거 HS-07 선행을 조용히 되살리지 말고 공통 선행과 채널 전용 선행을 분리해 설명해야 한다.

## 3층 — 정본 계약

### 1. 지위와 적용 범위

이 문서는 HumanSearch의 잡코리아 우선 진입 순서와 그 선행 조건을 정한다. 브라우저 접속 권한, 저장 정책, 증거 필드, RPS 프로젝트 생성·필터 쓰기, LinkedIn 상세 저장, 사람인 화면 구현은 각각의 정본이 소유한다.

이 문서는 실제 포털 접속, origin 실측, 검색어 입력, 후보 열람, 저장, 결제, 카드 삭제를 수행하지 않는다.

### 2. 대체되는 과거 의존성

과거 장부의 HS-11은 성공 기준을 “각 채널 실제 1명 완주”로 두고 선행을 `HS-07, HS-05.08`로 적었다. 이 문서는 그 중 “HS-07 사람인 완주”를 잡코리아 필수 선행에서 제거한다.

대체 규칙:

1. 잡코리아는 공통 선행 조건이 충족되면 사람인 완주 없이 HS-11.01부터 진행할 수 있다.
2. 사람인 전용 화면 계약, 사람인 검색·상세·저장 구현, 사람인 실제 완주 증거는 잡코리아 완료의 필수 선행이 아니다.
3. 잡코리아 실증은 사람인 접근 가능성, 사람인 결제 상태, 사람인 상세 제한을 대신 증명하지 않는다.
4. 사람인 카드는 삭제하지 않고, 실제로 막힌 카드만 이유와 해제 조건을 붙여 보류한다.
5. 사람인 결제 0회, 카드 삭제 0회가 유지돼야 한다.

### 3. 채널 공통 선행 조건

잡코리아 라이브 접속 전 다음 공통 조건이 모두 현재 정본과 시험 증거로 충족돼야 한다.

1. 공통 증거 계약: complete, partial, failed 판정과 필수 manifest 필드가 정해져 있다.
2. 저장 계약: 열람한 원문은 전량 암호화 저장 대상이고, 독립 readback 실패 시 다음 후보로 넘어가지 않는다.
3. 브라우저 권한 계약: Aside 전용 자동화, Chrome 비간섭, 대상 앱·프로필·탭 입력 귀속, 사람 입력 감지, 권한 회수, 잔여 명령 0이 증명돼 있다.
4. 사용권 계약: 채널 작업은 만료와 증가 번호가 있는 lease를 획득해야 하며, 만료·오래된 명령·다른 작업 소유권을 거부한다.
5. STOP 계약: STOP 뒤에는 새 관측과 새 lease가 있기 전까지 작업을 재개하지 않는다.
6. checkpoint 계약: 검색 조건, 목록 위치, 후보 잠금, 상세 식별, 저장 intent, 복귀 상태를 순서대로 기록한다.
7. 후보 잠금: 같은 position, channel, candidate key 조합은 중복 열람하지 않는다.
8. Git 유출 금지: 후보 PII, raw DOM, ARIA, 스크린샷, 토큰, 쿠키, 세션 값, 키 원본은 Git·PR·일반 로그에 남기지 않는다.

이 조건 중 하나라도 `NOT_RUN`이면 잡코리아 라이브 접속은 시작하지 않는다.

### 4. 잡코리아 전용 선행 조건

잡코리아는 아래 전용 조건을 별도로 가져야 한다.

1. precise-origin 계약: 실제 잡코리아 허용 origin 목록은 추측하지 않는다. 후속 origin 확인 WU가 공식 근거 또는 실제 승인 관측으로 exact origin을 확정해야 한다.
2. 전용 프로필: 잡코리아는 Aside의 잡코리아 전용 비기본 프로필만 사용한다. RPS 실프로필과 섞지 않는다.
3. 화면 fixture 출처: 목록·검색 조건·상세·복귀 fixture는 잡코리아 실제 화면에서 개인정보를 제거한 C1 산출물 또는 비PII 합성 fixture여야 한다. 사람인 fixture나 RPS fixture를 잡코리아 화면 증거로 재사용하지 않는다.
4. 검색 조건: 최신 사용자 포지션 조건을 적용하고 readback으로 잔재 조건과 미적용을 거부해야 한다.
5. 후보 식별: 후보 key는 사람 이름 원문이 아니라 비민감 지문으로 기록한다.
6. 저장 후 복귀: 상세 저장 뒤 목록 필터와 위치를 독립 readback으로 확인한다.

→ 해석: 잡코리아는 여섯 단계 모두 독립 증거가 있어야 하며, 사람인 완주나 RPS 실행 결과로 대체할 수 없다. 중복 후보는 같은 후보 재열람만 막고, 다른 후보 진행은 새 잠금·새 checkpoint가 성공한 경우에만 허용한다.

### 6. 중복 후보와 다른 후보 진행

중복 방지는 채널과 포지션 안에서 같은 후보의 재열람을 막기 위한 조건이다. 같은 후보 key가 이미 `confirmed`, `partial`, `failed`, `forbidden_input`, `recovery_required` 중 하나로 기록돼 있으면 그 후보를 다시 열지 않는다.

다른 후보 진행은 아래 조건을 모두 만족할 때만 가능하다.

1. 현재 후보가 저장 실패나 readback 실패로 순회 중단 상태가 아니다.
2. STOP, 사람 입력, 권한 회수, origin drift, target drift가 발생하지 않았다.
3. 다음 후보 key가 현재 후보와 다르고 잠금 획득에 성공했다.
4. 목록 위치와 검색 조건 readback이 유지돼 있다.

저장 실패 뒤 “다른 후보니까 계속”은 금지다.

### 7. 사람인 상태 계약

사람인은 결제하지 않는다. 카드 삭제도 하지 않는다. 현재 계약은 사람인의 목록 검색, 상세 접근, 저장 중 어느 단계가 실제로 제한되는지 확정하지 않는다.

사람인 보류는 실제 확인된 막힌 카드에만 붙인다. 보류 기록은 차단 위치, 관측 시각, 비PII 증거, 해제 조건을 가져야 한다. “미결제일 것”이라는 추정만으로 사람인 전체를 실패 처리하거나 잡코리아 진행을 막지 않는다.

| 항목 | 상태 | 해제 조건 |

| 잡코리아 실제 목록·검색·상세 fixture | NOT_RUN | 실제 fixture 승격은 잡코리아 C1 개인정보 제거 관측 필요. 비PII 합성 fixture는 계약 단위 시험만 해제 |
| 잡코리아 라이브 검색 조건 적용 | NOT_RUN | 기존 2026-09-14 실행 승인 범위 안에서 공통 선행, origin, 사용권, STOP, 저장 조건 충족 |

→ 해석: 이 문서가 만드는 것은 순서와 선행 조건의 계약이다. 잡코리아 origin, 실제 fixture, 라이브 완료, 사람인 제한 위치는 아직 실행 증거가 아니다. 합성 fixture는 계약 단위 시험을 도울 뿐 실제 화면 관측으로 승격하지 않는다.
