## 2026-10-14 사용자 추가 지시와 대상

사용자는 `https://admin.valuehire.cc/admin`의 체감 속도를 원인 분석과 코드 리팩터링으로 개선하고, `https://admin.valuehire.cc/ai-search-list`의 후보 표와 Fleet-job을 아래와 같이 바꾸라고 지시했다. **이번 화면·성능 코드 변경 대상은 v4**다. 2026-09-30 원본이 v6를 신규 AI Search 운영 시스템의 개발 대상으로 지정한 사실도 보존한다. v4의 즉시 화면 변경을 v6 운영 데이터 계약 전체가 구현된 것으로 간주하지 않는다. v4/v6 사이의 실제 배포·데이터 소유권은 코드와 운영 근거로 확인한다.

### 후보 목록의 추가 표시 계약

1. **후보자:** 확인된 이름을 기본 표시한다. 이름이 없으면 원본의 §3.3처럼 원천 ID와 미확인 상태를 표시한다. 이름을 만들어내지 않는다.
2. **점수:** 숫자와 함께 평가 주체·실제 모델명/버전·평가 시각·평가 버전/JD 버전을 추적 가능한 경우 표시한다. ChatGPT/Claude/Gemini 등은 원천 증거가 있는 경우에만 표기하며, 메타데이터가 없으면 `평가 주체 미확인` 등으로 표시한다. 기존 승인 평가 함수와 가중치는 변경하지 않는다. 미분석·실패·레거시 미검증 점수와 유효한 0점을 구별한다(원본 R-04/12, §3.4, §4.7).
3. **프로필:** 대학·전공·재학 기간 `YY.MM~YY.MM`, 최근 경력 최대 3개의 회사·부서·직책·재직 기간 `YY.MM~YY.MM`을 **목록에서** 읽을 수 있게 한다. 누락 항목과 불완전한 날짜는 추정하지 않는다. 이 지시는 원본 §3.3의 프로필 최대 3줄 제한에 우선한다. 상세는 구조화 자료의 전체 근거와 원문 링크를 제공한다.
4. **왜 잘 맞는지:** 목록에서는 짧은 bullet point와 근거 상태를 표시하고, 후보 상세에서는 근거 참조·강점·위험·확인 필요 사항을 풍부하게 보여 준다. 원문 근거를 목록 길이에 맞춰 저장 단계에서 잘라내지 않는다(원본 §3.4/3.6).
5. **매칭:** 회사–포지션 표시를 유지한다. 한 후보가 여러 모집 건에 매칭됐다면 실제 매칭 단위를 보존해 최신순으로 보여 주고, 목록의 요약에서 전체 이력을 여는 `더 보기`를 제공한다. 상세에는 모든 매칭의 full version과 근거를 표시한다. 이름·제목만으로 서로 다른 사람이나 모집 건을 합치지 않는다(원본 §4.1/4.3/4.4).

위 다섯 항목은 기존 SOT §3.3의 **고정 7컬럼 전체를 삭제하라는 지시로 해석하지 않는다**. 서치 일시, 증거 기반 제안 발송, 담당·다음 행동도 유지한다. 점수와 적합 이유는 원본의 한 셀 안에서 구분된 블록으로 표현할 수 있다. 실제 컬럼 구조를 바꿀 필요가 있으면 화면 설계와 회귀 기준에 변경 이유를 명시한다.

### Fleet-job·Gmail 연결

Fleet-job은 장식용 탭이 아니라 v6 기준 AI Search 실행·동기화 진단을 반영한다. 현재 내부 AI Search 결과가 Gmail로 도착하는 경로를 조사하고, 검증된 보고 메일의 message ID·발신 계정·수신 시각·보고 ID·후보/포지션 locator·파싱/연결 상태를 DB에 중복 없이 기록해 Fleet-job에서 조회한다. 메일 원문과 DB 결과가 연결되면 원본 근거를 보존하고 같은 사건으로 설명한다. **내부 보고메일은 후보자에게 실제 제안을 발송했다는 증거가 아니다**(원본 R-01/05, §4.11, §6.3, §10.2, WU-23). Gmail 수신 시각을 검색 실행 시각으로 추정하지 않는다. 읽기 권한·계정·실제 운영 경로가 확인되지 않은 부분은 `unknown/blocked`로 표시한다.

### 원본의 필수 계약

- 결과는 구조화 DB에 먼저 저장하고 웹·내부 보고메일은 같은 저장 결과를 읽는다(§1.2, R-02/03).
- 권한 있는 **전체 DB**에서 검색한다. 기본 50건/페이지, 선택 25/50/100, 안정적인 정렬·ID tie-breaker를 사용한다. 공백 단어는 AND, 각 단어의 검색 필드는 OR다. `%`, `_`, 따옴표를 삭제하거나 쿼리 구문으로 취급하지 않고 사용자 입력 문자 그대로 검색한다(§3.7). v4 PR #796의 500건 출력 상한과 문자 삭제·구절 단위 검색은 이 계약의 완료 증거가 아니다.
- 사람인·잡코리아·LinkedIn의 실제 발송은 채널별 직접 증거와 관측 범위를 보여 준다. 확인 실패를 미발송이나 초록색 완료로 표시하지 않는다(§5).
- 주간 경계는 `[일요일 00:00 KST, 다음 일요일 00:00 KST)`다(R-09, §8.1).
- 재검색·재시도·Gmail 재수집은 고유 후보자·매칭 업무·실제 발송 건수를 부풀리지 않는다(R-06/07, §4/8).
- 기존 인증·권한, DB 정본, 점수 함수, 보존·동기화·승인 경계는 유지한다. 실메일 발송, 후보자 발송, 운영 DB bulk 쓰기, 배포는 각각 별도 실행 경계다(원본 §1.3/11.2).

## `/admin` 및 리스트 성능의 완료 기준

로그인한 사용자의 실제 `/admin` 최초 표시와 메뉴 클릭을 같은 조건에서 변경 전·후 측정한다. 브라우저 요청, Next 라우팅·레이아웃, 인증, 서버 렌더, Supabase/외부 API, 파일 I/O, 클라이언트 번들·hydration의 구간별 시간을 남겨 병목을 특정한다. v4 `docs/engineering/admin-navigation-full-performance-audit-prompt-2026-07-22.md`의 대기 경로는 가설 출발점이며 2026-10-14 현행 사실로 재검증한다. 수치·오류·권한을 숨겨 빠르게 보이게 해서는 안 된다.

리스트 읽기 API의 원본 §9.3 목표는 지정된 합성 10,000매칭/50,000관측/30,000발송 환경에서 첫 50행 서버 응답 p95 2초 이내다. 로그인한 `/admin` 화면은 별도 기준선을 측정하고, 같은 경로·데이터·인증 조건에서 p50/p95, 주요 콘텐츠 표시와 메뉴 전환 시간을 비교한다. 목표 미달이나 운영 미검증은 수치와 함께 남긴다.
