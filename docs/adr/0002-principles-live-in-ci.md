# 0002 원칙은 문서가 아니라 CI에 둔다
- 상태: 승인
- 날짜: 2026-08-06
- 발단 명령: 원문 미보존 — 요지: 사장님이 코딩 원칙 원본 27개를 주고 v6 원칙으로 확정하라고 지시
- 연결: `docs/engineering/v6-coding-principles-goal-2026-08-06.md`, `docs/sot/coding-principles.md`

## 배경
v5는 테스트 3,100개가 통과하는 상태에서 실제 운영에서 전부 실패했다. v4·v5 실패 9건 중 5건은 코드 버그가 아니라 검사를 약화한 경우였다(skip 전환, 몰래 revert 등).

## 결정
원칙 27개를 P1~P15와 검증 체제 V-1~V-5로 압축했다. 기계로 강제할 수 없는 원칙은 삭제한다. 검사 약화 금지(P13)를 P1 다음으로 중요한 원칙으로 둔다. 억제에는 반드시 만료일을 붙인다.

## 버린 대안
- 5분 주기 자동 수정 봇: 1인 조직이 봇 커밋을 리뷰할 수 없다.
- DDD 계층: 도메인이 얇다.

## 대가 / 재검토 조건
새 원칙을 추가하자는 논의가 나오면 먼저 "이것을 강제할 CI 검사가 무엇인가"를 묻는다. 답이 없으면 원칙을 추가하지 않는다.
