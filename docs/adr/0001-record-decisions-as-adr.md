# 0001 결정 이력은 ADR로 남긴다
- 상태: 승인
- 날짜: 2026-09-23
- 발단 명령: "의사 결정 히스토리를 관리하는 adr -->검토해줘 . 내 프롬프팅(명령) 을 기반으로 어떤 생각 흐름가져왔는지 저장할 필요가 있어보임." → 제안 후 "응"
- 연결: [README](README.md)

## 배경
사장님 결정은 세 곳에 흩어져 있었다. `docs/engineering/`의 goal·판정 문서 100여 개에는 결정 이유가 본문에 묻혀 있었다. Claude 로컬 메모리에는 한 PC의 Claude만 볼 수 있는 기록이 있었다. 커밋 trailer에는 결정이 커밋 단위로 쪼개져 있었다. 그래서 Codex나 다른 PC에서는 "왜 이렇게 정했나"를 찾을 수 없었고, 같은 질문이 반복됐다(예: [0003](0003-password-rotation-declined.md)의 재요구 사고).

## 결정
`docs/adr/`에 한 결정당 한 파일로 남긴다. 표준 ADR 틀에 **발단 명령** 필드를 더해, 어떤 명령에서 결정이 출발했는지 남긴다. 첫 내용물로 Claude 메모리에 있던 사장님 결정을 옮긴다(0002~0013).

## 버린 대안
- 메모리에만 두기: 다른 도구·PC에서 보이지 않는다.
- 모든 결정을 ADR로 쓰기: 또 하나의 검증 계층이 된다([0012](0012-one-pass-verification-pipeline.md)).

## 대가 / 재검토 조건
ADR 형식을 강제하는 CI 검사는 아직 없다([0002](0002-principles-live-in-ci.md) 기준으로 보면 약점이다). 형식이 무너지기 시작하면 그때 검사를 추가한다.
