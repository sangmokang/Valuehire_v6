# 0009 HumanSearch 운영 결정 5건
- 상태: 승인
- 날짜: 2026-09-08
- 발단 명령: 원문 일부 — 프로필 저장은 "똑바로", LinkedIn 상세도 저장하느냐는 질문에 "당연히"
- 연결: `docs/engineering/goal-prompts/`의 HumanSearch 착수 프롬프트

## 배경
HumanSearch 착수 프롬프트를 준비하면서 기존 정본과 충돌하는 운영 방식을 사장님이 정해야 했다.

## 결정
1. **자동 재개를 한다.** 새 인증 관측과 checkpoint가 있을 때만 재개한다. 비밀번호·캡차 입력은 재개 경로에도 두지 않는다.
2. **본 프로필은 무조건 저장한다.** 실행마다 따로 받는 동의 절차는 두지 않는다. 저장에 실패하면 순회를 멈춘다. LinkedIn 후보 상세도 저장한다.
3. **"멈춰"라고 하면 1초 안에 멈춘다.** 멈춤 경로는 3개다(`/hs stop`, STOP 파일, 브라우저 접촉). 플래그 방식이 아니라 전송 핸들을 회수하는 방식으로 구현한다.
4. **브라우저는 Aside만 쓴다.**
5. **사람인·잡코리아는 여러 브라우저에서 동시에 쓸 수 있다.** 한 자리만 허용하는 것은 RPS뿐이다.

## 버린 대안
- 자동 재개 금지(기존 정본): 사장님이 뒤집었다.
- 멈춤 플래그 방식: 확인 시점과 사용 시점 사이의 경쟁(TOCTOU)으로 멈춘 뒤에도 전송 1건이 나가는 것을 실측했다.

## 대가 / 재검토 조건
동의 없이 무기한 보존한다. 삭제는 `/hs purge`로만 한다.
