# 0004 검증 도구 경계는 다시 나누지 않는다
- 상태: 승인
- 날짜: 2026-08-09
- 발단 명령: "`/verify` 하나로 통합해줘, 기본빵으로"(08-06) → "verify와 codeaudit 합칠까? 헷갈린다"(08-08)
- 연결: `~/.claude/skills/strict/SKILL.md` 도구 라우팅 표

## 배경
verify·codeaudit·gptreview·strict의 경계를 5일 동안 3번 바꿨고, 그때마다 며칠 안에 같은 혼란이 돌아왔다. 08-06에 실제로 통합했는데도 3일 만에 같은 문제가 다시 나왔다. 통합이 해법이 아니라는 증거다.

## 결정
원인은 도구 개수가 아니었다. 사장님이 매번 도구를 직접 골라야 했다는 점이 원인이었다. 그래서 `/strict`에 라우팅 표를 두고, 사장님은 `/strict`(코드 변경)와 `codeaudit`(남의 답변 검증) 두 개만 직접 쓴다. 나머지 도구는 `/strict`가 자동으로 부른다.

## 버린 대안
- 도구 파일을 다시 합치거나 나누기: 3번 해 봤고 3번 모두 재발했다.

## 대가 / 재검토 조건
바꿔야 한다면 파일 경계가 아니라 발동 조건을 고친다.
