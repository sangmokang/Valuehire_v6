# PR #37 원격 본문 수정안

## 결론

기존 정책 작업을 최신 변경 위에 복구하고 잘못된 입력과 가짜 검사 성공을 거부하도록 보완했습니다. 이 문서는 게시 전 초안이며 원격 반영·병합은 하지 않았습니다.

## 사장님이 반드시 볼 부분

1. 정책 의미 보존: `docs/sot/work-unit-policy.yaml`은 한 단위 한 주장, PR 1~5개, 48시간, 전체 관문 순서·고위험 검토·비용·복구 경계를 유지합니다. 이 뜻을 바꾸는 변경이면 반려해야 합니다. 승인 없이 숫자만 바뀌어도 통과하는 것을 막았습니다.
2. 정본과 실제 강제의 범위: `docs/sot/verification-commands.md:30`은 정책 일관성 검사가 실제 개발자의 작업 장부·PR 수·기간까지 자동 강제하지 않음을 명시합니다. 작업 관리 시스템 구현을 요구한다면 이 변경을 그 완료로 승인하면 안 됩니다.
3. 검사 신뢰성: `scripts/verify/work-unit-policy-contract-test.rb`와 `work-unit-policy-gates-test.rb`는 실제 명령 실행으로 잘못된 정책·가짜 성공·검사 삭제를 공격합니다. 고장 사본이 초록으로 남거나 정상 키 순서를 거부하면 반려 기준입니다.
4. 최신 기능 보존: `.github/workflows/verify.yml:55`·`:58`은 새 정책 검사 두 개를 연결합니다. main 4379b2f의 검사 결과 전량 집계와 실행 제한은 그대로입니다. 기존 HumanSearch·Invoice 검사가 빠지면 반려해야 합니다.
5. 전달 경계: 현재 PR37 head는 0b4dd2c로 별도 복구 브랜치와 다릅니다. 이전 성공 검사를 새 코드의 결과로 승인하면 안 됩니다. 새 커밋의 서버 검사와 병합 가능 여부를 확인해야 하며, 원본 이력 강제 갱신은 이 초안의 승인에 포함되지 않습니다.

- 최신 main의 원칙·장부·검사기·44개 P23 시험은 원문 그대로이며, 서버 검사 문서표29개 이름·순서를 실제 YAML과 대조했습니다.
- 최신 조합의 전체 로컬 검사와 Codex 최종 판정은 아래 증거 장부의 마감 결과를 기준으로 합니다.

## 제가 확인하지 못한 부분

- 새 커밋의 GitHub Actions 실행, 원격 PR 변경, 병합 후 결과.
- 새 코드의 GitHub 러너 Ruby 환경 실행. 로컬 Ruby 2.6.10에서 검증했습니다.
- 동일 권한으로 구현과 시험을 함께 고치는 공격을 막는 권한 분리. 무작위 시험은 임의의 악성 프로그램에 대한 보증이 아닙니다.
- 운영 데이터 저장·외부 발송은 변경 범위 밖이므로 실행하지 않았습니다.

## 판단 근거·복구·증거 원문

> **무엇을** — 정책 입력을 단일 정본으로 유지하고 기존 검사와 연결을 보완합니다.
> **왜** — 잘못된 자료형과 검사 수 위조, 알려진 시험만 외운 가짜가 기존 검사에서 통과했습니다.
> **버린 길** — 자연어 동의어 검색으로 회귀하거나 모든 기대값을 정본에서 함께 재생성하면 독립 검증이 사라집니다.
> **대가** — 정책 변경 때 기대 계약과 독립 시험을 먼저 개정해야 합니다.
> **되돌리기** — 병합 전은 로컬 변경별 역적용, squash 병합 뒤는 PR 전체 복구. 운영 데이터 변경은 없습니다.
