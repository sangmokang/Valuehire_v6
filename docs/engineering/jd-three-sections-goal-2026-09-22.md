# JD 원문 보존·삭제 규칙 정정

현재 두 포털의 수정은 진행 중입니다. 사람인은 새 조회가 로그인 전 안내로 이동하여 인증 확인이 필요합니다. 기존 7개 변경은 보존하고 인계 33개 파일의 해시 일치를 확인했습니다.

판단 근거: 기존 패킷의 단위 누락 검사는 공식 원문 추출 누락을 검출하지 못합니다. 보고 메일에 원문 전체를 붙이는 이전 규칙은 최신 삭제 지시와 충돌합니다. 공식 원문 각 항목을 새 저장값에 연결해야 합니다.

## 계약 (T)

위험등급 L3. 실행자는 한 명이며 사용자 지시에 따라 서브에이전트와 외부 검증 에이전트 위임을 사용하지 않습니다. 독립 V1/V2는 NOT_RUN으로 기록하며 자체 점검을 대신 PASS로 표시하지 않습니다. 실제 포털 수정·저장 및 단일 최종 메일은 현재 요청으로 승인됐습니다. 후보자 제안·발송, 원격 push/PR/병합은 범위 밖입니다.

- When 공식 원문을 읽으면 각 문장/항목에 source-unit ID와 원문을 부여해야 한다.
- When 새 저장값을 읽으면 모든 유지 항목을 실제 대응 문장·필드·근거에 연결해야 한다. 미배치가 있으면 완료가 아니다.
- When 후보자 본문 및 보고 메일을 만들면 삭제 지시된 안내·푸터 및 전형 추가/생략 변형을 포함하지 않아야 한다.
- When 사람인 구획을 확정하면 실제 로그인 편집 UI와 표시 화면의 이름·ID·제한·순서를 근거로 해야 한다. 제목은 본문으로 사용하지 않는다.
- When 잡코리아를 저장하면 영구 필드와 임시 제안 내용을 별개로 새 조회해야 한다. 임시 본문 미저장은 PARTIAL이다.
- When 최종 메일을 보내면 operation ID로 보낸편지함을 먼저 조회하고 한 통만 발송한 뒤 수신자·본문·시간·ID를 대조해야 한다.

반례: 패킷끼리 일치하지만 공식 항목 누락; 입력값을 저장값으로 오인; 숨겨진 세 번째 필드를 가정; 원문 부록에서 삭제 문구 재노출; 후보자 발송으로 임시 저장을 증명; 테스트만 통과하고 포털 완료 주장.

입출력: raw-source.json → source-unit 원문/채널별 대응 → 기존 jd_channels packet → Aside 실제 UI 저장 → 새 조회 observed.json → readback 결과 → 삭제규칙 검증된 메일. 빈 원문·누락 ID·필드 초과·대상 불일치·인증 실패는 차단하고 임의 기본값으로 통과하지 않는다.

## 작업 단위와 검증

1. 직접 원칙 로드·검사, 인계 해시 검증, 현재 UI 확인, 골든 대조.
2. 원문 배치표와 문안 준비. 제외 검증 반례를 먼저 실행하고 최소 보강. 실제 구조 차이가 없으면 필드 스키마를 늘리지 않는다.
3. 기존 포지션 ID 확인·저장·새 조회·문장별 coverage.
4. 스킬/정본/JSON·시험 반영 및 로컬 checkpoint. 최종 메일 1통, 보낸편지함 대조.

검증 명령: bash scripts/acceptance-principles-check.sh; python3 -m unittest discover -s tests -p 'test_jd*.py' -v; python3 -m unittest discover -s tests; bash verify.sh; 기존 packet/readback CLI. UI 값과 시험 전체 출력은 artifacts/jd-three-sections-20260922에 보존한다. 원칙 검사 exit=0, 34/34; 시작 HEAD eaaee6219ed63d8ed4be1d52a3977216a15e5a03. 파일 hard 한도는 P11의 600줄이다.

## 안전·되돌리기

영향 범위: 지정 포지션 두 개와 JD 정책·검증. 저장 전 해당 필드값을 보관하고 복구 시 동일 ID/그룹을 재확인한 뒤 이전 값으로 저장·새 조회한다. 새 포지션·후보자 접촉을 만들지 않는다. 개인정보·로그인 세션·원문 증빙은 커밋하지 않는다. 배포/DB 변경/신규 제품 표면은 없어 SKELETON 배포 계약은 NOT_APPLICABLE. 포털 결과는 실제 readback 범위에서만 보고한다.

무엇을 — 공식 항목과 저장 문장 간 대조를 추가한다.
왜 — 패킷 생성 이전의 누락을 잡기 위해서다.
버린 길 — 요약 패킷의 자체 일치만으로 완료 판단하기.
대가 — 원문 항목과 UI를 직접 대조하는 시간이 필요하다.
되돌리기 — 로컬 변경은 별도 커밋으로 보존하며 포털은 사전 캡처를 사용한다.

## 검증 중 발견과 좁은 정리 계획

잡코리아에서 불릿 문자가 물음표로 변환되어 첫 readback은 FAIL이었다. 문자 수만 같다는 이유로 일치라고 설명한 오류를 정정했다. 실제 캡처와 실패를 보존하고, 전용 회귀 시험 후 입력 전 안전 불릿 치환을 추가한다.

기존 인계 테스트 파일은 630줄로 P11 한도 600을 초과한다. 이미 통과한 기존 116개/추가 후 JD 60개를 기준으로, 패킷 생성 시험과 저장 재조회 시험을 책임별 파일로 나누되 단언·기대값·시험 수는 바꾸지 않는다. 기존 인계 변경의 시험 내용도 보존한다. 경계 시험 600/601과 0개 대상 차단을 다시 실행한다.
