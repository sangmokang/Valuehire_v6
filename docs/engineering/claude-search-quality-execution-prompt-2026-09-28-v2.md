# Claude 실행 프롬프트 — 검색 품질 중심 최소 서치 v2

`$strict`를 사용하되 새 프레임워크·스키마·검증 프로그램을 만들지 마십시오. 기존 브라우저·장부·저장·메일 도구만 사용하십시오.

## 목표

현재 JD에 맞는 좋은 후보를 RPS와 사람인에서 찾아 상세 원문과 검색 결과를 저장하고, 기존 접촉을 확인한 뒤 내부 메일로 전달하십시오. 후보 수 20명+20명이나 검색조합 5개를 채우는 것은 목표가 아닙니다.

## 1. JD 고정과 Clear

사용자 URL을 공식 페이지에서 다시 열어 회사명·직무명·경력요건·내부 JD ID를 한 줄로 기록하십시오. URL과 기존 장부의 포지션명이 다르면 임의로 매핑하지 말고 `BLOCKED_ID_MISMATCH`로 종료하십시오.

이전 실행이 섞였거나 잘못된 포지션의 검색·후보·메일이 보이면 새 실행 키로 시작하십시오. 기존 원문은 삭제하지 말고 `prior_run`으로만 참조하십시오.

## 2. 접근 가능성

RPS와 사람인에서 실제 검색 화면과 후보 상세 화면을 각각 열어 보십시오. 로그인 화면, 세션 충돌, CAPTCHA, 상세 접근 거부가 나오면 우회하지 말고 즉시 다음만 보고하십시오.

`VERDICT: BLOCKED`

`채널 / 화면 / 오류 / 내가 직접 해결해야 하는 한 가지`

## 3. 검색 품질 질문

검색을 끝내기 전에 아래 질문에 각각 답할 수 있어야 합니다.

1. JD 핵심 키워드가 모두 추출되었는가?
2. 영문·한글·띄어쓰기·붙여쓰기·약어·정식명·유관어 누락을 점검했는가?
3. 실제 검색 필터에 입력된 값과 최종 적용 상태를 화면에서 확인했는가?
4. 업계 JD와 최고 수준 실무자들이 사용하는 상위 실무 용어를 조사해 검색 가설에 반영했는가?
5. 회사 LinkedIn 직원 프로필을 참고해 역할·경력·용어·학력 패턴을 확인했는가? 사용자 지정 교육 배경 우선순위를 후보 평가의 보조 가중치로 반영했는가?
6. 과거 목표 회사 재직자를 현재 재직자로 잘못 판정하지 않았는가?
7. 국적·외국인 여부를 선별 기준으로 사용하지 않았는가? 필요한 경우 직접 근거가 있는 한국어 업무 수행·근무 가능성만 별도 기록했는가?
8. 프리랜서·단기계약 상태를 확인했는가? 고객 지시가 없는데 자동 탈락시키지 않았고, 확인되지 않은 정규직 가능성을 추정하지 않았는가?
9. 모든 추천 후보의 본인 상세 원문·현재 회사·직무·최근 재직 상태를 직접 확인했는가?
10. 프로필과 검색 결과 페이지가 올바른 후보·URL·검색어·필터·관찰 시각으로 저장되었는가?

## 4. 학력 정보 처리

후보 본인 프로필에 실제 표시된 학교·캠퍼스·학위·전공·졸업 상태만 기록하십시오. 학교명이나 캠퍼스를 추정하거나 이름·사진으로 학력을 보완하지 마십시오.

학력은 다음 순서로 처리하십시오.

1. JD에 특정 전공·학위·면허·연구 배경이 명시되어 있으면 해당 요건과 직접 일치하는지 점수에 반영하십시오.
2. 사용자 지정 교육 우선순위를 적용하십시오. 인서울 대학과 주요 지방 국공립대는 후보 본인 원문에서 실제 학교와 해당 캠퍼스를 확인했을 때만 보조 가중치로 기록하십시오. 캠퍼스가 불명확하면 가중치를 적용하지 마십시오.
   학교 간 참고 순서는 `docs/sot/search-query-and-filter-rules.md`의 **학력 순위 참고 기준**을 사용하십시오. 거기에 적힌 QS 2027 서울 목록과 THE 2026 지방 국공립대 순위를 웹에서 재확인하고 출처·순위판·조회일을 결과에 남기십시오. 서로 다른 순위의 숫자를 합치거나 동률·구간에 임의 순서를 붙이지 마십시오. 출처를 확인할 수 없으면 순위 가중치를 적용하지 말고 `순위 확인 불가`로 기록하십시오.
3. 학교 가중치는 직무 적합성·성과·현재 재직 상태를 대체하지 않습니다. 학력 근거가 없으면 가중치를 적용하지 말고 `확인되지 않음`으로 기록하십시오.
4. 회사 LinkedIn 직원 표본에서 관찰된 학력 분포는 검색 우선순위 참고로만 쓰고, 후보 본인 학력을 추정하는 데 사용하지 마십시오.

## 5. 후보 판단

회사명·학교명·사진·Similar Profiles·추천문구·listing 한 줄만으로 추천하지 마십시오. 후보 본인 원문에서 JD 적합 근거를 찾아 기록하십시오. 이메일은 후보 본인 Contact info에 실제 표시된 경우만 저장하고 추정하지 마십시오. 기존 InMail·프로젝트·Viewed·Contacted 후보는 신규 후보와 분리하십시오.

프리랜서·단기계약 후보는 현재 계약 상태와 정규직 전환 가능성이 확인되지 않으면 `확인 필요`로 두십시오. 과거 프리랜서 경력만으로 탈락시키지 마십시오.

## 6. 종료와 메일

관련 후보가 계속 나오면 계속 탐색하고, 검색어 변형과 필터를 바꿔도 같은 후보만 반복되거나 추가 정보 가치가 낮아지면 그 이유를 기록하고 종료하십시오. 종료 전 추천 후보를 한 번 다시 읽고 동일 포지션 기존 메일과 중복을 확인하십시오.

내부 메일은 기존 승인된 수신자에게만 보냅니다. 후보자에게 이메일·InMail·연결 요청은 금지합니다.
