# HumanSearch 여정 대안 기획서 작성 목표 — 2026-08-15

## 결론

기존 기획서를 덮어쓰지 않고, 확인된 사실과 제안을 분리한 새 대안 기획서를 만든다. 새 문서는 무인 실행을 사업 목표로 유지하되, 로그인·보안문자·2단계 인증은 사람이 복구하는 예외로 두고, 자동 발송은 바로 켜지 않는 단계형 실험으로 설계한다.

이번 작업은 제품 구현이나 외부 발송이 아니다. 저장소 안에 의사결정용 문서 두 개만 추가하며, 기존 문서·코드·브라우저·외부 서비스는 수정하지 않는다.

## 현재 상태와 근거

- `README.md:5-7`은 이 저장소가 아직 초기 골격 단계라고 밝힌다.
- `humansearch/pyproject.toml:1-6`은 현재 묶음이 사업 기능이 아니라 G2 검증 배관만 담았다고 밝힌다.
- `docs/sot/coding-principles.md:26`의 현재 코드 상한은 파일당 600줄이다. 기존 기획서의 500줄 자동 강제 주장은 실제 검사 파일과 서버 검사 연결이 없으므로 완료 사실로 쓰지 않는다.
- `docs/sot/verification-commands.md:1-35`는 이 저장소의 실제 검사 명령과 서버 검사 목록을 정한다. 존재하지 않는 명령은 인수 기준으로 쓰지 않는다.
- `docs/engineering/humansearch-journey-master-plan-2026-08-14.md:71,122,253`은 Aside 실측을 완료와 예정으로 동시에 적어 모순된다.
- 같은 문서 `:234`는 v1~v5 의존 0을 선언하지만 `:98`은 1차 등록에 v5 스킬을 쓴다고 적어 모순된다.
- `worktrees/humansearch-clean-room-plan/docs/engineering/humansearch-v6-clean-room-rebuild-goal-2026-08-12.md:181-191`은 사람이 선택한 현재 탭만 허용하고 디버깅 포트 직접 제어를 금지한다. 따라서 무인 실행은 현 계약의 연장이 아니라 별도 계약 변경안이다.

## 근본 문제

기존 기획서는 사업 목표, 이미 확인된 사실, 아직 실측하지 않은 가설, 기존 계약을 바꾸는 제안을 한 문장 안에서 섞었다. 그 결과 파일은 존재하지만 “완성”, “확정”, “실측 성공”, “자동 검사 강제”라는 말의 근거 수준이 서로 다르다.

## 인수 기준

1. 새 대안 문서가 기존 기획서를 수정하지 않고 별도 파일로 존재한다.
2. 모든 핵심 항목에 `확인`, `제안`, `미확인`, `결정 필요`, `현재 금지` 중 하나의 상태가 붙는다.
3. 무인 실행, 저장, 자동 발송, 과거 버전 독립, LinkedIn Recruiter, 후보 채점 기준을 각각 독립된 결정 카드로 적는다.
4. 자동 발송은 매칭 점수만으로 켜지지 않으며, 사람 검토 단계와 소량 시험 단계가 선행된다.
5. Aside 실측은 “디버깅 연결과 탭 열거 확인”까지만 확인 사실로 쓰고, 실제 무인 순회·재부팅 복구·로그인 복구는 미확인으로 남긴다.
6. ClickUp의 채택·기각 칸 존재 여부는 원본 응답 증거가 없으므로 미확인으로 남긴다.
7. 서울권 대학, 잦은 이직, 프리랜서, 구조적 글쓰기, 이직 의사 공개 기준을 사용자의 의도와 운영상 오판 방지 조건을 함께 반영해 정의한다.
8. 실제로 존재하는 저장소 검사만 실행하고, 형식 검사 결과를 내용 합격 증거로 과장하지 않는다.
9. 다른 엔진의 적대 검증과 Codex의 재검증 결과를 문서 끝에 남긴다. 검증이 실행되지 않으면 그 사실을 그대로 남긴다.
