## 상속 규약 (rps-candidate-ledger-v2에서 그대로 가져온다 — 재협상 대상 아님)

### 필드마다 값과 별개로 "확인 상태"를 같이 적는다

- `확인됨` — 실제 값이 있음
- `확인 시도, 값 없음` — 접근은 됐지만 해당 정보가 비공개/없음
- `접근 불가` — 구조적으로 열람이 막힘 + **왜 막혔는지 사유**
- `조사 범위 밖` — 시간/범위/크레딧 제약으로 아직 안 봄 (없다고 단정한 게 아니다)

값만 적거나 "미확인"으로 뭉뚱그리는 것 자체가 결함이다.

### 그 외 상속 항목

- **단일 원장** — 표·보고서·CSV를 따로 만들지 말고 원장 하나에서 전부 생성한다. 두 산출물의 값이 다르면 결함이다.
- **PATCH 금지, FULL RECORD REBUILD** — 사용자가 필드 하나를 지적하면 그 후보의 이력서를 다시 보고 레코드 전체를 재작성한다.
- **탐색 한도 사전 선언** — 무기한 탐색 금지. 착수 전에 한도를 정하고, 닿으면 "어디까지 봤는지" 남기고 멈춘다.
- **0은 0으로 보고** — 없는 건 숨기거나 뭉뚱그리지 않는다.
- **발송 0건** — 사람인 쪽지·메일·연락 일절 금지. 이번 작업은 원장 작성과 사용자 보고까지다.
- **이전 결과는 정본이 아니라 재검증할 가설** — 기존 세션 보고서에 "확보됨"으로 적힌 값도 다시 확인해 확인시각을 새로 찍는다.

## Step 1. 필터 맵 작성 — 서치보다 먼저 (건너뛰기 = 작업 실패)

**어떤 검색도 하기 전에** 필터 패널을 전부 펼쳐보고 아래 표를 채워 출력한다.
사람인 UI는 개편이 잦고 상품 등급에 따라 보이는 필터가 다르므로, **실제로 보이는 것만** 적는다.

| 필터명 (화면 표기 그대로) | 입력 방식 | 선택 가능 값/범위 | 다중선택 | URL 파라미터 | 비고 |
|---|---|---|---|---|---|

작성 규칙:
- 화면의 **한글 라벨을 그대로** 쓴다. 이 프롬프트가 부르는 이름과 다르면 **화면이 정답**이다.
- 접힌 섹션(`상세조건`·`더보기`·`+`)을 **모두 펼쳐** 확인한다.
- 회색·잠금·유료 표시된 필터는 `비고`에 `잠김`으로 적는다.
- 값 목록이 긴 필터(직종 트리·전공·지역)는 대분류만 적고 `하위 있음` 표기.
- 필터를 하나 바꿔보고 **URL 쿼리스트링이 따라 바뀌는지** 확인해 파라미터명을 적는다.
  → 바뀌면 이후는 **URL 직접 편집으로 필터를 세팅**한다. 훨씬 빠르고 재현 가능하다. URL 패턴도 함께 보고한다.
  → 안 바뀌면 그 사실을 적고, 이후 모든 필터 조작은 UI 클릭으로만 한다.

## Step 4. 크레딧 가드 — 열람 순서 (사람인 고유, 반드시 이 순서)

사람인은 **이력서 상세 열람 시 유료 크레딧이 차감된다.** 이게 이 작업의 실질적 탐색 한도다.

```
[필터 적용] → [결과 수 기록] → [리스트 뷰에서만 1차 판정] → [통과자만 상세 열람] → [원장 작성]
```

**1차 판정은 리스트 뷰에 보이는 정보만으로 한다.** 아래 중 하나라도 걸리면 **열지 않는다**:

- 최종학교가 인서울/4대 과기원 밖 (Tier 표는 별도 문서 §2)
- 전공이 컴공 계열 밖 (DS만 인접 전공 허용)
- 경력 연차가 포지션 최소 요건 미달
- 별도 문서 §5 블록리스트(기존 진행 후보 11명)와 이름+소속 일치

**착수 전에 열람 한도를 선언한다: 포지션당 최대 15건, 전체 최대 60건.**
한도에 닿으면 열람을 멈추고 "몇 명 중 어디까지 봤는지"를 원장 요약에 남긴다.
열지 않은 1차 통과자는 **`조사 범위 밖`으로 원장에 남긴다** — 빼버리지 마라. 다음 회차의 출발점이 된다.

크레딧 부족 경고가 뜨면 **즉시 중단하고 사용자에게 알린다.** 계속 시도하지 마라.

## Step 5. 이력서 아카이빙 (열람할 때마다 즉시)

상세 이력서를 열어 `get_page_text`(또는 `read_page`)로 내용을 뽑은 **직후마다** 저장한다.
크레딧을 써서 본 페이지를 저장 안 하면 그 돈을 다시 써야 한다.

```bash
curl -s -X POST http://127.0.0.1:7777/api/archive \
  -H 'Content-Type: application/json' \
  -d '{"url":"<이력서 URL>","pageTitle":"<페이지 제목>","textContent":"<get_page_text 결과>"}'
```

- `url`만 필수. `screenshots` 생략 가능.
- 같은 URL을 최근 저장했으면 서버가 자동 스킵한다 — 매번 호출해도 안전하다.
- SQLite 즉시 insert → 서버가 30초마다 Supabase 동기화 (추가 조치 불필요).
- 아카이버 서버가 안 떠 있으면(`Connection refused`) **그 사실을 기록하고 서치는 계속한다.** 여기서 멈추지 마라.

## Step 6. 필터 조정 루프 — 사람인은 키워드보다 필터로 좁힌다

사람인 검색창은 Boolean을 처리하지 못한다. **좁히는 일은 필터가, 키워드는 1~2단어로 회전.**

| 관측 | 조정 |
|---|---|
| 결과 300건 초과 | 경력 범위를 2년 폭으로 자르거나 직종 소분류를 하나로 좁힌다. **키워드를 늘리지 마라** |
| 결과 20건 미만 | 이력서 수정일 6→12개월 → 지역에 인천/충청 추가 → 마지막에 키워드 삭제 |
| 1차 통과율 30% 미만 | 키워드가 엉뚱한 직군을 잡고 있다. 직종 필터를 조이고 키워드를 교체 |
| 같은 사람만 반복 | 정렬 전환(최신순↔정확도순) 또는 경력 구간 이동 |
| 통과율 높은데 결과 적음 | 키워드를 고정하고 **경력 구간만 슬라이딩** (3-5 / 5-7 / 7-10년) |

**포지션당 최소 6회 필터 조합을 바꿔 돌린다.** 한 조합으로 끝내면 작업 실패다.

## Step 7. 산출물 — 원장 하나에서 전부 생성

### 7-1. 원장 (포지션별 섹션, 후보 1명 = 1행)

12개 필드 + `이력서최종수정일` + `상세열람여부`, **각 필드에 확인 상태·출처·확인시각 병기.**

```
이름: 홍길동 (확인됨, 리스트뷰+상세, 2026-09-27 확인)
학력: 한양대 컴퓨터공학 학사 (확인됨, 이력서 학력란, 2026-09-27) → Tier 2
연락처: 확인 시도, 값 없음 (이력서 열람했으나 연락처 비공개)
과거 컨택: 이력 없음 (조사범위: ClickUp FY26CandidstesStatus + 사람인 열람이력, 2026-09-27)
이력서 최종수정일: 2026-09-12 (확인됨, 리스트뷰)
상세 열람: 열람함 (크레딧 1건 차감)
```

**70점 미만은 추천 목록에 넣지 마라.** 리스트뷰만으로 판정한 후보는 점수에 `(리스트뷰 기준)` 표기.

### 7-2. 필터 로그 (없으면 작업 미완료)

```
회차 | 포지션 | 경력범위 | 직종 | 전공 | 지역 | 이력서수정일 | 키워드 | 결과수 | 리스트판정수 | 1차통과 | 상세열람 | 통과율%
```

### 7-3. 최종 상태 보고 — 이 숫자들을 반드시 포함 (0이면 0이라고 적는다)

- Step 1 **필터 맵 표** (원문 라벨) + **URL 파라미터 패턴** + **잠긴 필터 목록**
- 실행 필터 조합 수 / 리스트뷰 판정 후보 수 / 1차 통과 수
- **총 상세 열람 건수 = 크레딧 소모량**
- 완결(전 필드 확인) 후보 수 / **보완 대기**(일부 `조사 범위 밖`) 후보 수
- 신규 추천 후보 수 (블록리스트 제외 후) / 블록리스트로 제외한 수
- 하드필터 탈락 통계 — 학력·전공·연차 중 무엇에서 가장 많이 걸렸는지
- 포지션별 인재풀 두께 판정 — 사람인에 그 직군이 실제로 없으면 **"사람인에 없다"고 그대로 보고**한다
- **LinkedIn RPS와 중복된 후보** — 이름+회사+학교로 대조. 양쪽 등록자는 이직 의향 신호이므로 별도 강조
- 아카이빙 성공/실패 건수

**정상 완료 조건: 미완성 레코드 = 0, 또는 "보완 대기" 명단으로 명시적으로 분리.**
