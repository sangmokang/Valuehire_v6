# P20 — Aside 로컬 진단과 목표 탭 발견

아래 내용을 새 Codex 작업의 첫 프롬프트로 그대로 사용한다.

## 목표

각 머신 로컬 실행기만 127.0.0.1 Aside 진단면을 읽고 허용 주소의 목표 탭이 정확히 하나일 때만 핸들을 반환하며, 실제 사람 개입 신호를 제공할 로컬 출처를 지원/미지원으로 목록화한다.

## 선행조건

P02·P15·P16 `CONTRACT_PASS`. `LIVE_PASS`에는 Aside 진단 규약 승인과 해당 로컬 머신이 필요하다.

## 작업 소유 범위

`humansearch/src/humansearch/browser/aside_discovery.py`, 진단 포트 추상화, fixture·계약시험, 로컬 진단 CLI.

경로가 현재 SOT와 충돌하면 임의로 다른 영역까지 고치지 말고 목표 문서에 충돌을 증거와 함께 기록해 이 프로젝트를 중단한다.

## 비범위

외부 진단 포트 공개, 페이지 클릭·입력, 기본 Chrome 프로필 우회, 중앙 원격 조작.

## RED 먼저

0개 또는 2개 목표 탭, 외부 바인딩, 버전 불일치인데 핸들이 반환되는 실패 시험을 먼저 만든다.

## 구현 계약

loopback 주소만 허용하고 Aside/규약 버전, 탭 URL·제목 지문, 로그인/보안화면 분류를 반환한다. 로컬 제어 화면·중단 단축키·Aside/운영체제 신호 후보를 출처·관측시각·만료 가능 여부와 함께 목록화하되 지원을 추정하지 않는다. 불확실하면 브라우저 명령 0건이다.

## 가짜 합격을 깨는 시험

IPv6/hostname 우회, 외부 IP, 중복 탭, 리디렉션, 보안문자, 2단계 인증, 진단 규약 변경을 시험한다.

## 검증

가짜 진단 서버 계약시험; 승인된 로컬 머신이면 탭 목록 읽기 1회·명령 0회를 기록; `bash verify.sh`.

## 원자적 인수 기준

후속 구현은 `bash scripts/acceptance-ai-ra-p20.sh` 한 명령으로 각 머신에서 승인된 진단 주소와 정확한 대상 탭만 찾고 사람 개입 신호 출처의 지원/미지원을 추정 없이 기록하며 불일치·복수 탭·기본 자료 폴더 대체를 거부함을 검사해야 한다. 정상 실행은 `PASS AI_RA_P20 <실제 핵심 건수>`를 출력하되 실제 핵심 건수는 반드시 1 이상이고 종료값 0을 남겨야 하며, 핵심 차단을 한 줄 고장 낸 반대 시험은 0이 아닌 종료값이어야 한다. 이 프로젝트는 자기 인수 스크립트만 소유한다. P04가 소유한 `scripts/acceptance-ai-ra-all.sh`와 서버 workflow가 이름 규칙으로 자동 발견해야 하며, 이후 프로젝트는 공용 workflow를 직접 수정하지 않는다.

## 라이브 증거와 멈춤점

실제 진단 읽기는 해당 머신에서 명시된 로컬 주소만 수행한다. 머신이나 승인이 없으면 `BLOCKED_AUTH`이며 `LIVE_PASS`가 아니다. 클릭·입력 없이 발견 증거에서 멈춘다.

## 공통 strict 실행 지시

1. 기본 작업공간을 수정하지 말고 최신 기준 커밋에서 이 프로젝트 전용 worktree와 `task/` 브랜치를 만든다.
2. 코드보다 먼저 이 프로젝트 목표 문서를 작성하고 원자적 인수 기준 1개, 반대 시험, 비범위, 실제 검증 명령을 적는다.
3. `docs/sot/INDEX.md`, `coding-principles.md`, `git-workflow.md`, `hook-contracts.md`, `verification-commands.md`와 P00B 이후 새 정본을 전문으로 읽고 체크리스트를 목표 문서에 남긴다.
4. v4/v5 코드는 행동·실패 사례와 테스트 오라클만 참고한다. import, 복사, subprocess 호출, 런타임 의존성은 금지한다.
5. RED를 실제 런타임 시험으로 먼저 만들고 실패 출력을 목표 문서에 남긴다. 소스 문자열 검색만으로 기능을 증명하거나 테스트 0건을 PASS로 세지 않는다.
6. 최소 구현 뒤 대상 시험→자기 번호 인수 검사→P04 공용 `scripts/acceptance-ai-ra-all.sh`→`bash verify.sh` 순으로 실행한다. P04 전 프로젝트는 자기 스크립트만 만들고 P04가 공용 배관을 연결하며, P04 이후 프로젝트는 이름 규칙 자동 발견을 증명하고 `.github/workflows/verify.yml`을 직접 수정하지 않는다.
7. 비밀·후보 원문·인증정보를 터미널, fixture, 문서, 커밋에 남기지 않는다. 외부 쓰기·발송·운영 DB 변경·배포는 이 프롬프트가 명시적으로 허용하지 않으면 하지 않는다.
8. `claude -p` 1차 적대검토를 실행하고 각 지적을 Codex가 직접 명령으로 재현한다. 한 항목이라도 동의하면 수정 후 1차부터 다시 반복한다.
9. 완료 보고는 변경 파일, 실제 처리 건수, 테스트/인수 검사 종료 코드, `git diff --check`, 남은 `NOT_RUN`과 위험을 구분한다. 검사가 하나라도 빨갛거나 증거가 없으면 완료라고 하지 않는다.
