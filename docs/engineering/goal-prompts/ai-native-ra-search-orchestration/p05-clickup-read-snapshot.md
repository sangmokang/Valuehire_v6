# P05 — ClickUp 읽기 전용 포지션 스냅샷

아래 내용을 새 Codex 작업의 첫 프롬프트로 그대로 사용한다.

## 목표

열린 포지션을 끝까지 페이지 순회해 구조 지문과 원자료 참조를 가진 읽기 전용 스냅샷으로 만든다.

## 선행조건

P03·P04 `CONTRACT_PASS`. `LIVE_PASS`에는 ClickUp 읽기 권한이 필요하다.

## 작업 소유 범위

`humansearch/src/humansearch/adapters/clickup_reader.py`, 포트 계약, 응답 fixture·단위/계약시험, 읽기 전용 CLI.

경로가 현재 SOT와 충돌하면 임의로 다른 영역까지 고치지 말고 목표 문서에 충돌을 증거와 함께 기록해 이 프로젝트를 중단한다.

## 비범위

상태·필드·댓글 쓰기, 우선순위 계산, API 토큰 저장.

## RED 먼저

첫 페이지만 읽고 완료하거나 빈 페이지를 정상 0건으로 확정하는 실패 시험을 먼저 만든다.

## 구현 계약

목록·상태·필드 구조 지문, 페이지 완주 여부, 원문 ID, 수정시각을 반환한다. 429 헤더를 존중하고 불완전 읽기는 `NOT_RUN`이다.

## 가짜 합격을 깨는 시험

페이지 토큰 반복, 중복 태스크, 중간 429, 구조 변경, 응답 순서 변경, 0건과 미실행 혼동을 시험한다.

## 검증

fixture 계약시험, 실제 읽기 전용 1회는 사용자 승인·자격증명이 있을 때만 수행하고 요청·응답 건수 및 0회 쓰기를 기록; `bash verify.sh`.

## 원자적 인수 기준

후속 구현은 `bash scripts/acceptance-ai-ra-p05.sh` 한 명령으로 페이지 끝까지 읽은 스냅샷의 지문·건수·필드 누락이 재현되며 외부 쓰기 호출이 0건임을 검사해야 한다. 정상 실행은 `PASS AI_RA_P05 <실제 핵심 건수>`를 출력하되 실제 핵심 건수는 반드시 1 이상이고 종료값 0을 남겨야 하며, 핵심 차단을 한 줄 고장 낸 반대 시험은 0이 아닌 종료값이어야 한다. 이 프로젝트는 자기 인수 스크립트만 소유한다. P04가 소유한 `scripts/acceptance-ai-ra-all.sh`와 서버 workflow가 이름 규칙으로 자동 발견해야 하며, 이후 프로젝트는 공용 workflow를 직접 수정하지 않는다.

## 라이브 증거와 멈춤점

읽기 자격증명이 없으면 `CONTRACT_PASS`까지만 가능하고 실제 경계는 `BLOCKED_AUTH`다. `NOT_RUN` 또는 `BLOCKED_AUTH`는 `LIVE_PASS`나 외부 통합 선행조건을 충족하지 않는다. 쓰기 호출은 항상 0건이다.

## 공통 strict 실행 지시

1. 기본 작업공간을 수정하지 말고 최신 기준 커밋에서 이 프로젝트 전용 worktree와 `task/` 브랜치를 만든다.
2. 코드보다 먼저 이 프로젝트 목표 문서를 작성하고 원자적 인수 기준 1개, 반대 시험, 비범위, 실제 검증 명령을 적는다.
3. `docs/sot/INDEX.md`, `coding-principles.md`, `git-workflow.md`, `hook-contracts.md`, `verification-commands.md`와 P00B 이후 새 정본을 전문으로 읽고 체크리스트를 목표 문서에 남긴다.
4. v4/v5 코드는 행동·실패 사례와 테스트 오라클만 참고한다. import, 복사, subprocess 호출, 런타임 의존성은 금지한다.
5. RED를 실제 런타임 시험으로 먼저 만들고 실패 출력을 목표 문서에 남긴다. 소스 문자열 검색만으로 기능을 증명하거나 테스트 0건을 PASS로 세지 않는다.
6. 최소 구현 뒤 대상 시험→자기 번호 인수 검사→P04 공용 `scripts/acceptance-ai-ra-all.sh`→`bash verify.sh` 순으로 실행한다. P04 전 프로젝트는 자기 스크립트만 만들고 P04가 공용 배관을 연결하며, P04 이후 프로젝트는 이름 규칙 자동 발견을 증명하고 `.github/workflows/verify.yml`을 직접 수정하지 않는다.
7. 비밀·후보 원문·인증정보를 터미널, fixture, 문서, 커밋에 남기지 않는다. 외부 쓰기·발송·운영 DB 변경·배포는 이 프롬프트가 명시적으로 허용하지 않으면 하지 않는다.
8. `claude -p` 1차 적대검토를 실행하고 각 지적을 Codex가 직접 명령으로 재현한다. 한 항목이라도 동의하면 수정 후 1차부터 다시 반복한다.
9. 완료 보고는 변경 파일, 실제 처리 건수, 테스트/인수 검사 종료 코드, `git diff --check`, 남은 `NOT_RUN`과 위험을 구분한다. 검사가 하나라도 빨갛거나 증거가 없으면 완료라고 하지 않는다.
