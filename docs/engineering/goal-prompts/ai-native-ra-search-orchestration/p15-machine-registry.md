# P15 — 실행 머신 등록과 능력 계약

아래 내용을 새 Codex 작업의 첫 프롬프트로 그대로 사용한다.

## 목표

각 컴퓨터의 머신 ID·버전·허용 채널·계정 참조 지문·중단 스위치·사람 사용 신호 출처·로컬 자동화 예약을 등록하고 자격 없거나 상태가 불명인 머신을 거부한다. 이 문서에서 실행자와 머신은 같은 개념이며 정식 필드명은 `machine_id`다.

## 선행조건

P00B·P02·P04 `CONTRACT_PASS`.

## 작업 소유 범위

`humansearch/src/humansearch/fleet/machine_registry.py`, 저장 포트, 합성 fixture·단위시험.

경로가 현재 SOT와 충돌하면 임의로 다른 영역까지 고치지 말고 목표 문서에 충돌을 증거와 함께 기록해 이 프로젝트를 중단한다.

## 비범위

비밀번호·쿠키 저장, 실제 브라우저 조작, v5 fleet 코드 이식.

## RED 먼저

알 수 없는 머신, 버전 불일치, 계정 참조 없음이 작업 자격을 얻는 실패 시험을 먼저 만든다.

## 구현 계약

OS·제품/Aside 버전·허용 채널·계정 지문·정책 모드·중단 스위치·사람 상태 신호 출처/관측/만료·`local_reservation_epoch`을 버전된 레코드로 관리한다. `local_reservation_epoch`은 사람의 로컬 제어 동작만 새로 발급·증가시킬 수 있고 중앙 스케줄러는 읽고 결합할 뿐 만들지 못한다. 사람 상태 값은 `IDLE_CONFIRMED | HUMAN_ACTIVE | HUMAN_UNKNOWN`으로 고정하고, 신호가 없거나 오래됐으면 `HUMAN_UNKNOWN`이며 작업 자격이 없다. 자격증명 원문은 금지한다.

## 가짜 합격을 깨는 시험

중복 `machine_id`, 계정 지문 충돌, 버전 다운그레이드, 채널 별칭, 중단 스위치, 중앙 발급/감소/재사용 `local_reservation_epoch`, 민감값 직렬화를 시험한다.

## 검증

등록/갱신 상태전이, 비밀 패턴 검사, 반복 등록 멱등성, `bash verify.sh`.

## 원자적 인수 기준

후속 구현은 `bash scripts/acceptance-ai-ra-p15.sh` 한 명령으로 승인된 실행자만 고유 머신 ID와 허용 채널로 등록되고, 사람 상태가 `IDLE_CONFIRMED | HUMAN_ACTIVE | HUMAN_UNKNOWN` 외의 값이 되지 않음을 검사해야 한다. 중복·폐기·미승인·`HUMAN_UNKNOWN` 실행자는 작업을 받지 못해야 한다. 정상 실행은 `PASS AI_RA_P15 <실제 핵심 건수>`를 출력하되 실제 핵심 건수는 반드시 1 이상이고 종료값 0을 남겨야 하며, 핵심 차단을 한 줄 고장 낸 반대 시험은 0이 아닌 종료값이어야 한다. 이 프로젝트는 자기 인수 스크립트만 소유한다. P04가 소유한 `scripts/acceptance-ai-ra-all.sh`와 서버 workflow가 이름 규칙으로 자동 발견해야 하며, 이후 프로젝트는 공용 workflow를 직접 수정하지 않는다.

## 라이브 증거와 멈춤점

합성 머신만 등록한다. 운영 머신이나 계정 정보는 별도 승인 전 입력하지 않는다.

## 공통 strict 실행 지시

1. 기본 작업공간을 수정하지 말고 최신 기준 커밋에서 이 프로젝트 전용 worktree와 `task/` 브랜치를 만든다.
2. 코드보다 먼저 이 프로젝트 목표 문서를 작성하고 원자적 인수 기준 1개, 반대 시험, 비범위, 실제 검증 명령을 적는다.
3. `docs/sot/INDEX.md`, `coding-principles.md`, `git-workflow.md`, `hook-contracts.md`, `verification-commands.md`와 P00B 이후 새 정본을 전문으로 읽고 체크리스트를 목표 문서에 남긴다.
4. v4/v5 코드는 행동·실패 사례와 테스트 오라클만 참고한다. import, 복사, subprocess 호출, 런타임 의존성은 금지한다.
5. RED를 실제 런타임 시험으로 먼저 만들고 실패 출력을 목표 문서에 남긴다. 소스 문자열 검색만으로 기능을 증명하거나 테스트 0건을 PASS로 세지 않는다.
6. 최소 구현 뒤 대상 시험→자기 번호 인수 검사→P04 공용 `scripts/acceptance-ai-ra-all.sh`→`bash verify.sh` 순으로 실행한다. P04 전 프로젝트는 자기 스크립트만 만들고 P04가 공용 배관을 연결하며, P04 이후 프로젝트는 이름 규칙 자동 발견을 증명하고 `.github/workflows/verify.yml`을 직접 수정하지 않는다.
7. 비밀·후보 원문·인증정보를 터미널, fixture, 문서, 커밋에 남기지 않는다. 외부 쓰기·발송·운영 DB 변경·배포는 이 프롬프트가 명시적으로 허용하지 않으면 하지 않는다.
8. `claude -p` 1차 적대검토를 실행하고 각 지적을 Codex가 직접 명령으로 재현한다. 한 항목이라도 동의하면 수정 후 1차부터 다시 반복한다.
9. 완료 보고는 변경 파일, 실제 처리 건수, 테스트/인수 검사 종료 코드, `git diff --check`, 남은 `NOT_RUN`과 위험을 구분한다. 검사가 하나라도 빨갛거나 증거가 없으면 완료라고 하지 않는다.
