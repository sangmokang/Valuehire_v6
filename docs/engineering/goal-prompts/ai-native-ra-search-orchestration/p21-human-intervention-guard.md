# P21 — 사람 개입 즉시 브라우저 권한 폐기

아래 내용을 새 Codex 작업의 첫 프롬프트로 그대로 사용한다.

## 목표

사람 개입 신호 뒤에는 같은 드라이버 객체로 클릭·입력·스크롤을 호출할 수 없게 구조적으로 차단한다.

## 선행조건

P18·P19·P20 `CONTRACT_PASS`. `LIVE_PASS`에는 P18·P19 `LIVE_PASS`와 실제 로컬 `TAKE_OVER` 또는 중단 신호 출처 1개가 필요하다.

## 작업 소유 범위

`humansearch/src/humansearch/browser/intervention_guard.py`, `humansearch/src/humansearch/browser/human_signal.py`, 권한 토큰/상태기계, 로컬 신호 포트, 단위·경합시험.

경로가 현재 SOT와 충돌하면 임의로 다른 영역까지 고치지 말고 목표 문서에 충돌을 증거와 함께 기록해 이 프로젝트를 중단한다.

## 비범위

사이트별 탐색, OS 입력 감시 설치, 사람이 떠났다고 자동 추정.

## RED 먼저

개입 신호와 클릭이 경합할 때 개입 이후 명령 1건이 실행되는 실패 시험을 먼저 만든다.

## 구현 계약

active capability를 P17의 `queue_lease_epoch`, P18의 `account_fencing_token`, P15에서 시작해 P19 배정에 결합된 `local_reservation_epoch` 세 값과 큐 lease의 데이터베이스 만료시각·그에 대응하는 로컬 단조시계 마감에 묶인 일회성 토큰으로 만들고 개입 시 원자 폐기한다. 모든 클릭·입력·스크롤 직전에 세 값의 최신 로컬 스냅샷과 로컬 마감을 다시 검사하고, P19의 회수/재배정 통지로 `queue_lease_epoch`이 달라지거나 통지가 끊겨 마감이 지나면 네트워크 재시도 없이 권한을 폐기한다. 신호는 `machine_id`·`local_reservation_epoch`·단조 사건 번호·출처·관측시각을 가져야 하며 없거나 오래되면 `HUMAN_UNKNOWN`으로 명령을 막는다. 개입 사건은 P19의 `RUNNING→PAUSED_FOR_HUMAN` 조건부 전이를 요청해 계정 사용권을 해제하고 `queue_lease_epoch`을 올린다. 재개는 이 전이 영수증을 확인하고 사람이 P15 로컬 제어에서 새 `local_reservation_epoch`을 만든 뒤, P19가 `PAUSED_FOR_HUMAN→QUEUED`로 전환하고 P18 사용권 재획득으로 새 `account_fencing_token`을 받은 다음 로그인 영수증·탭·포지션 검증을 거친 새 객체로만 가능하다. 전이 요청이 전달되지 않으면 재개하지 않고 로컬 마감 뒤 폐기한다.

## 가짜 합격을 깨는 시험

클릭 경합, 오래된 콜백, 재시도 큐, 사람 개입 없는 큐 lease 만료·다른 머신 재배정, 회수 통지 유실과 로컬 마감 경계, 예외 처리, 프로세스 재시작, 개입 해제 위조를 시험한다.

## 검증

경합시험 반복에서 개입 이후 명령 0건, stale capability 타입/런타임 거부, `bash verify.sh`.

## 원자적 인수 기준

후속 구현은 `bash scripts/acceptance-ai-ra-p21.sh` 한 명령으로 실제 로컬 인계·보안문자·로그아웃 신호 뒤 브라우저 명령이 0건이고 사람 상태 불명과 명시적 재개 전에는 새 명령이 거부됨을 검사해야 한다. lease가 아직 만료되지 않은 같은 머신에서도 개입 뒤 pause 영수증·계정 해제·새 `queue_lease_epoch`·새 로컬 예약·새 계정 토큰이 모두 없으면 재개 0건이고, 이 전이가 모두 끝난 뒤에만 새 객체 1개가 가능해야 한다. 새 객체가 P15/P17/P18에서 시작해 P19가 결합한 세 최신 epoch/token을 모두 소비하고 하나라도 오래되면 명령 0건이어야 한다. 사람 개입이 없어도 `queue_lease_epoch`만 증가하거나 회수 통지가 끊긴 채 로컬 마감이 지나면 과거 capability의 클릭·입력·스크롤이 모두 0건임도 검사해야 한다. 정상 실행은 `PASS AI_RA_P21 <실제 핵심 건수>`를 출력하되 실제 핵심 건수는 반드시 1 이상이고 종료값 0을 남겨야 하며, 핵심 차단을 한 줄 고장 낸 반대 시험은 0이 아닌 종료값이어야 한다. 이 프로젝트는 자기 인수 스크립트만 소유한다. P04가 소유한 `scripts/acceptance-ai-ra-all.sh`와 서버 workflow가 이름 규칙으로 자동 발견해야 하며, 이후 프로젝트는 공용 workflow를 직접 수정하지 않는다.

## 라이브 증거와 멈춤점

합성 드라이버 spy는 `CONTRACT_PASS`까지만 가능하다. `LIVE_PASS`는 외부 사이트를 조작하지 않은 로컬 빈 탭에서 실제 `TAKE_OVER` 또는 중단 신호 1건 뒤 명령 0건, 오래된 권한 거부, 새 예약 전 재개 거부 영수증을 요구한다. 실제 신호 출처가 없으면 `BLOCKED_POLICY`이며 공유 대화형 운영을 열지 않는다.

## 공통 strict 실행 지시

1. 기본 작업공간을 수정하지 말고 최신 기준 커밋에서 이 프로젝트 전용 worktree와 `task/` 브랜치를 만든다.
2. 코드보다 먼저 이 프로젝트 목표 문서를 작성하고 원자적 인수 기준 1개, 반대 시험, 비범위, 실제 검증 명령을 적는다.
3. `docs/sot/INDEX.md`, `coding-principles.md`, `git-workflow.md`, `hook-contracts.md`, `verification-commands.md`와 P00B 이후 새 정본을 전문으로 읽고 체크리스트를 목표 문서에 남긴다.
4. v4/v5 코드는 행동·실패 사례와 테스트 오라클만 참고한다. import, 복사, subprocess 호출, 런타임 의존성은 금지한다.
5. RED를 실제 런타임 시험으로 먼저 만들고 실패 출력을 목표 문서에 남긴다. 소스 문자열 검색만으로 기능을 증명하거나 테스트 0건을 PASS로 세지 않는다.
6. 최소 구현 뒤 대상 시험→자기 번호 인수 검사→P04 공용 `scripts/acceptance-ai-ra-all.sh`→`bash verify.sh` 순으로 실행한다. P04 전 프로젝트는 자기 스크립트만 만들고 P04가 공용 배관을 연결하며, P04 이후 프로젝트는 이름 규칙 자동 발견을 증명하고 `.github/workflows/verify.yml`을 직접 수정하지 않는다.
7. 비밀·후보 원문·인증정보를 터미널, fixture, 문서, 커밋에 남기지 않는다. 외부 쓰기·발송·운영 DB 변경·배포는 이 프롬프트가 명시적으로 허용하지 않으면 하지 않는다.
8. `claude -p` 1차 적대검토를 실행하고 각 지적을 Codex가 직접 명령으로 재현한다. 한 항목이라도 동의하면 수정 후 1차부터 다시 반복한다.
9. 완료 보고는 변경 파일, 실제 처리 건수, 테스트/인수 검사 종료 코드, `git diff --check`, 남은 `NOT_RUN`과 위험을 구분한다. 검사가 하나라도 빨갛거나 증거가 없으면 완료라고 하지 않는다.
