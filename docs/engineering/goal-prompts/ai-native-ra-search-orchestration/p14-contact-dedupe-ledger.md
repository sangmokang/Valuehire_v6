# P14 — 중복 접촉·접촉금지 보호 장부

아래 내용을 새 Codex 작업의 첫 프롬프트로 그대로 사용한다.

## 목표

후보·고객사·포지션·채널·기간별 중복 접촉과 명시적 접촉금지를 외부 발송보다 먼저 차단한다.

## 선행조건

P01·P02·P03·P12 `CONTRACT_PASS`.

## 작업 소유 범위

`humansearch/src/humansearch/contact_safety/ledger.py`, 로컬 저장 포트 계약, 단위·동시성시험.

경로가 현재 SOT와 충돌하면 임의로 다른 영역까지 고치지 말고 목표 문서에 충돌을 증거와 함께 기록해 이 프로젝트를 중단한다.

## 비범위

메일·인메일 발송, 원천 Gmail 수정, 실제 후보 연락.

## RED 먼저

동일 후보가 다른 출처 ID나 다른 머신에서 동시에 승인되는 실패 시험을 먼저 만든다.

## 구현 계약

P02의 정규 채널 ID·별칭 계약, P03의 정식 고객사·포지션 ID, P12의 `canonical_candidate_id`·별칭 폐쇄·강한 식별자, 기간을 결합한 강한 키로 `ALLOWED | DUPLICATE | DO_NOT_CONTACT | NEEDS_REVIEW`를 반환하고 의도 영수증·만료·취소를 기록한다. 고객사·포지션 이름 문자열을 키로 쓰거나 추측해 합치지 않는다. P12 연결 해제 뒤에는 분리된 양쪽 ID가 승계한 접촉금지를 모두 확인하며, 사람 검토 사건 없이 과거 보호를 제거하지 않는다.

## 가짜 합격을 깨는 시험

동시 두 요청, 채널·후보 ID 별칭, 같은 고객사 ID의 다른 이름 표기, 같은 이름의 다른 고객사 ID, 후보 연결 해제와 접촉금지 양쪽 승계, 기간 경계, 취소 후 재요청, 과거 포지션, 삭제 요청 후보, 오래된 머신 결과를 시험한다.

## 검증

두 프로세스 동시 fixture에서 승인 1건, 발송 포트 0회, 전후 장부 일관성, `bash verify.sh`.

## 원자적 인수 기준

후속 구현은 `bash scripts/acceptance-ai-ra-p14.sh` 한 명령으로 후보·고객사·포지션·채널·기간 고유키가 중복 연락을 막고, P02의 채널 별칭과 P03의 고객사·포지션 정식 ID를 적용한 후에도 이름 표기가 달라 중복이 빠지거나 같은 이름의 다른 ID를 합치지 않으며 만료·충돌·늦은 영수증을 조용히 덮어쓰지 않음을 검사해야 한다. 정상 실행은 `PASS AI_RA_P14 <실제 핵심 건수>`를 출력하되 실제 핵심 건수는 반드시 1 이상이고 종료값 0을 남겨야 하며, 핵심 차단을 한 줄 고장 낸 반대 시험은 0이 아닌 종료값이어야 한다. 이 프로젝트는 자기 인수 스크립트만 소유한다. P04가 소유한 `scripts/acceptance-ai-ra-all.sh`와 서버 workflow가 이름 규칙으로 자동 발견해야 하며, 이후 프로젝트는 공용 workflow를 직접 수정하지 않는다.

## 라이브 증거와 멈춤점

합성 후보만 사용한다. 실제 메시지 발송이나 외부 쓰기 전에 멈춘다.

## 공통 strict 실행 지시

1. 기본 작업공간을 수정하지 말고 최신 기준 커밋에서 이 프로젝트 전용 worktree와 `task/` 브랜치를 만든다.
2. 코드보다 먼저 이 프로젝트 목표 문서를 작성하고 원자적 인수 기준 1개, 반대 시험, 비범위, 실제 검증 명령을 적는다.
3. `docs/sot/INDEX.md`, `coding-principles.md`, `git-workflow.md`, `hook-contracts.md`, `verification-commands.md`와 P00B 이후 새 정본을 전문으로 읽고 체크리스트를 목표 문서에 남긴다.
4. v4/v5 코드는 행동·실패 사례와 테스트 오라클만 참고한다. import, 복사, subprocess 호출, 런타임 의존성은 금지한다.
5. RED를 실제 런타임 시험으로 먼저 만들고 실패 출력을 목표 문서에 남긴다. 소스 문자열 검색만으로 기능을 증명하거나 테스트 0건을 PASS로 세지 않는다.
6. 최소 구현 뒤 대상 시험→자기 번호 인수 검사→P04 공용 `scripts/acceptance-ai-ra-all.sh`→`bash verify.sh` 순으로 실행한다. P04 전 프로젝트는 자기 스크립트만 만들고 P04가 공용 배관을 연결하며, P04 이후 프로젝트는 이름 규칙 자동 발견을 증명하고 `.github/workflows/verify.yml`을 직접 수정하지 않는다.
7. 비밀·후보 원문·인증정보를 터미널, fixture, 문서, 커밋에 남기지 않는다. 외부 쓰기·발송·운영 DB 변경·배포는 이 프롬프트가 명시적으로 허용하지 않으면 하지 않는다.
8. `claude -p` 1차 적대검토를 실행하고 각 지적을 Codex가 직접 명령으로 재현한다. 한 항목이라도 동의하면 수정 후 1차부터 다시 반복한다.
9. 완료 보고는 변경 파일, 실제 처리 건수, 테스트/인수 검사 종료 코드, `git diff --check`, 남은 `NOT_RUN`과 위험을 구분한다. 검사가 하나라도 빨갛거나 증거가 없으면 완료라고 하지 않는다.
