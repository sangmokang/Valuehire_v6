# P08 — 읽기 전용 서치 작업 제안 생성

아래 내용을 새 Codex 작업의 첫 프롬프트로 그대로 사용한다.

## 목표

포지션 우선순위와 부족분을 결합해 실행 가능한 포지션·채널·검색 범위 제안만 만든다.

## 선행조건

P02·P03·P06·P07·P13 `CONTRACT_PASS`.

## 작업 소유 범위

`humansearch/src/humansearch/work_proposals/generator.py`, 고유키 계약, 단위·계약시험, 제안 출력 CLI.

경로가 현재 SOT와 충돌하면 임의로 다른 영역까지 고치지 말고 목표 문서에 충돌을 증거와 함께 기록해 이 프로젝트를 중단한다.

## 비범위

Supabase 큐 삽입, 브라우저 실행, ClickUp 상태 변경.

## RED 먼저

내부 후보가 목표를 채웠거나 채널이 차단됐는데도 작업 제안이 생기는 실패 시험을 먼저 만든다.

## 구현 계약

P03의 `READY` 결정, ClickUp 스냅샷 지문, P06 `position_priority_decision_hash`, P07 부족분 지문과 양쪽의 `candidate_eligibility_receipt_set_hash`를 직접 입력으로 받고 하나라도 없거나 P03·P05·후보 영수증 집합·정책의 서로 다른 입력 세대를 가리키면 제안을 만들지 않는다. 내부 `ELIGIBLE`과 외부 `ACCEPTED`의 고유 후보 합집합이 목표를 채우면 외부 제안은 0건이다. 고유키는 포지션+채널+검색식버전+필터버전+범위버전이다. 제안은 선택·제외 사유, 모든 입력 지문, 정책 버전, 시간/페이지 상한을 갖고 외부 쓰기를 하지 않는다.

## 가짜 합격을 깨는 시험

중복 입력, 동점 순서, 차단 채널, 후보 영수증 집합 누락·지문 불일치·고유 후보 충분, P06 결정 지문 누락·세대 불일치, P06/P07이 서로 다른 P03·P05·후보 영수증 집합·정책 세대를 가리키는 조합, `REVIEW_REQUIRED`만 있는 경우, 구성만 부족, 정책 만료, 고유키 충돌을 시험한다.

## 검증

골든 제안 목록, 반복 실행 0개 중복, 쓰기 포트 호출 0회, `bash verify.sh`.

## 원자적 인수 기준

후속 구현은 `bash scripts/acceptance-ai-ra-p08.sh` 한 명령으로 같은 P06 결정·P07 부족분·`candidate_eligibility_receipt_set_hash`·정책 버전은 같은 고유키 1개만 만들고, 고유 적격 후보 합집합이 목표를 채운 경우·P06/P07 후보 집합 또는 입력 세대 불일치·지문/영수증 누락·금지 채널·준비 안 된 포지션은 제안 0건임을 검사해야 한다. 정상 실행은 `PASS AI_RA_P08 <실제 핵심 건수>`를 출력하되 실제 핵심 건수는 반드시 1 이상이고 종료값 0을 남겨야 하며, 핵심 차단을 한 줄 고장 낸 반대 시험은 0이 아닌 종료값이어야 한다. 이 프로젝트는 자기 인수 스크립트만 소유한다. P04가 소유한 `scripts/acceptance-ai-ra-all.sh`와 서버 workflow가 이름 규칙으로 자동 발견해야 하며, 이후 프로젝트는 공용 workflow를 직접 수정하지 않는다.

## 라이브 증거와 멈춤점

JSON/표준출력 제안까지만 허용한다. 실제 작업 큐나 외부 서비스 쓰기 전에 멈춘다.

## 공통 strict 실행 지시

1. 기본 작업공간을 수정하지 말고 최신 기준 커밋에서 이 프로젝트 전용 worktree와 `task/` 브랜치를 만든다.
2. 코드보다 먼저 이 프로젝트 목표 문서를 작성하고 원자적 인수 기준 1개, 반대 시험, 비범위, 실제 검증 명령을 적는다.
3. `docs/sot/INDEX.md`, `coding-principles.md`, `git-workflow.md`, `hook-contracts.md`, `verification-commands.md`와 P00B 이후 새 정본을 전문으로 읽고 체크리스트를 목표 문서에 남긴다.
4. v4/v5 코드는 행동·실패 사례와 테스트 오라클만 참고한다. import, 복사, subprocess 호출, 런타임 의존성은 금지한다.
5. RED를 실제 런타임 시험으로 먼저 만들고 실패 출력을 목표 문서에 남긴다. 소스 문자열 검색만으로 기능을 증명하거나 테스트 0건을 PASS로 세지 않는다.
6. 최소 구현 뒤 대상 시험→자기 번호 인수 검사→P04 공용 `scripts/acceptance-ai-ra-all.sh`→`bash verify.sh` 순으로 실행한다. P04 전 프로젝트는 자기 스크립트만 만들고 P04가 공용 배관을 연결하며, P04 이후 프로젝트는 이름 규칙 자동 발견을 증명하고 `.github/workflows/verify.yml`을 직접 수정하지 않는다.
7. 비밀·후보 원문·인증정보를 터미널, fixture, 문서, 커밋에 남기지 않는다. 외부 쓰기·발송·운영 DB 변경·배포는 이 프롬프트가 명시적으로 허용하지 않으면 하지 않는다.
8. `claude -p` 1차 적대검토를 실행하고 각 지적을 Codex가 직접 명령으로 재현한다. 한 항목이라도 동의하면 수정 후 1차부터 다시 반복한다.
9. 완료 보고는 변경 파일, 실제 처리 건수, 테스트/인수 검사 종료 코드, `git diff --check`, 남은 `NOT_RUN`과 위험을 구분한다. 검사가 하나라도 빨갛거나 증거가 없으면 완료라고 하지 않는다.
