# P00B — 승인된 정보 책임 장소 SOT 강제

아래 내용을 새 Codex 작업의 첫 프롬프트로 그대로 사용한다.

## 목표

P00A에서 오너가 승인한 ClickUp·`position_policy`·공유 제어 장부·후보 보호 장부·머신 로컬 장부의 책임과 금지 데이터를 그대로 저장소 정본과 서버 검사로 강제한다.

## 선행조건

P00A가 `DECISION_APPROVED`이고 승인 기록의 버전·지문·오너가 모두 확인돼야 한다.

## 작업 소유 범위

`docs/sot/data-ownership.md` 신설, `docs/sot/INDEX.md`, `docs/sot/coding-principles.md`, P04가 자동 발견할 전용 문서 인수 스크립트. 공용 서버 workflow 연결은 P04가 소유한다.

경로가 현재 SOT와 충돌하면 임의로 다른 영역까지 고치지 말고 목표 문서에 충돌을 증거와 함께 기록해 이 프로젝트를 중단한다.

## 비범위

DB 테이블 생성, 후보 자료 이동, ClickUp 쓰기, 기존 v4/v5 코드 이식.

## RED 먼저

책임 장소와 `position_policy` 정본 중 하나가 없거나 공유 SQLite·후보 원문 큐 저장을 허용하면 실패하는 문서 계약 검사를 먼저 만든다.

## 구현 계약

승인 기록에 있는 각 데이터 종류의 단일 정본, 허용 복제, 금지 필드, 보존·삭제 책임, 외부 쓰기 영수증, 단일 머신 폴백을 임의 변경 없이 명시한다. 다른 선택이 필요하면 구현하지 말고 P00A 새 버전으로 되돌린다.

## 가짜 합격을 깨는 시험

네트워크 SQLite 공동 쓰기, ClickUp을 실행권 장부로 사용, Supabase 큐에 이력서 원문 저장, 정본 둘 이상을 각각 주입해 모두 거부되는지 증명한다.

## 검증

전용 인수 검사, SOT 링크 검사, `bash verify.sh`를 실행하고 실제 검사 수와 종료 코드를 기록한다.

## 원자적 인수 기준

후속 구현은 `bash scripts/acceptance-ai-ra-p00.sh` 한 명령으로 승인 기록의 버전·지문·오너와 정본 내용이 정확히 같고 불일치·미승인 상태에서는 정본 변경이 거부됨을 검사해야 한다. 정상 실행은 `PASS AI_RA_P00 <실제 핵심 건수>`를 출력하되 실제 핵심 건수는 반드시 1 이상이고 종료값 0을 남겨야 하며, 핵심 차단을 한 줄 고장 낸 반대 시험은 0이 아닌 종료값이어야 한다. 이 프로젝트는 자기 인수 스크립트만 소유한다. P04가 소유한 `scripts/acceptance-ai-ra-all.sh`와 서버 workflow가 이름 규칙으로 자동 발견해야 하며, 이후 프로젝트는 공용 workflow를 직접 수정하지 않는다.

## 라이브 증거와 멈춤점

문서 계약만 반영한다. 운영 DB·후보 자료·외부 서비스는 건드리지 않고 SOT 검사가 통과하면 멈춘다.

## 공통 strict 실행 지시

1. 기본 작업공간을 수정하지 말고 최신 기준 커밋에서 이 프로젝트 전용 worktree와 `task/` 브랜치를 만든다.
2. 코드보다 먼저 이 프로젝트 목표 문서를 작성하고 원자적 인수 기준 1개, 반대 시험, 비범위, 실제 검증 명령을 적는다.
3. `docs/sot/INDEX.md`, `coding-principles.md`, `git-workflow.md`, `hook-contracts.md`, `verification-commands.md`와 P00B 이후 새 정본을 전문으로 읽고 체크리스트를 목표 문서에 남긴다.
4. v4/v5 코드는 행동·실패 사례와 테스트 오라클만 참고한다. import, 복사, subprocess 호출, 런타임 의존성은 금지한다.
5. RED를 실제 런타임 시험으로 먼저 만들고 실패 출력을 목표 문서에 남긴다. 소스 문자열 검색만으로 기능을 증명하거나 테스트 0건을 PASS로 세지 않는다.
6. 최소 구현 뒤 대상 시험→자기 번호 인수 검사→P04 공용 `scripts/acceptance-ai-ra-all.sh`→`bash verify.sh` 순으로 실행한다. P04 전 프로젝트는 자기 스크립트만 만들고 P04가 공용 배관을 연결하며, P04 이후 프로젝트는 이름 규칙 자동 발견을 증명하고 `.github/workflows/verify.yml`을 직접 수정하지 않는다.
7. 비밀·후보 원문·인증정보를 터미널, fixture, 문서, 커밋에 남기지 않는다. 외부 쓰기·발송·운영 DB 변경·배포는 이 프롬프트가 명시적으로 허용하지 않으면 하지 않는다.
8. `claude -p` 1차 적대검토를 실행하고 각 지적을 Codex가 직접 명령으로 재현한다. 한 항목이라도 동의하면 수정 후 1차부터 다시 반복한다.
9. 완료 보고는 변경 파일, 실제 처리 건수, 테스트/인수 검사 종료 코드, `git diff --check`, 남은 `NOT_RUN`과 위험을 구분한다. 검사가 하나라도 빨갛거나 증거가 없으면 완료라고 하지 않는다.
