# P00A — 정보 책임 장소 오너 결정

아래 내용을 새 Codex 작업의 첫 프롬프트로 그대로 사용한다.

## 목표

ClickUp·승인된 `position_policy`·공유 제어 장부·후보 보호 장부·머신 로컬 장부의 책임 장소 선택지를 증거와 함께 제시하고, 오너가 선택한 버전·대가·되돌리기를 서명된 결정 기록으로 남긴다.

## 선행조건

없음. 다만 오너 답변 없이 선택을 추정하거나 SOT를 바꾸지 않는다.

## 작업 소유 범위

P00A는 아래 세 산출물만 소유한다.

1. `docs/engineering/ai-ra-data-ownership-decision-<date>.md` — 선택지·근거·오너 결정 기록
2. `docs/engineering/ai-ra-data-ownership-owner-decision-goal-<date>.md` — 이번 프로젝트 목표 문서
3. `scripts/acceptance-ai-ra-p00a.sh` — P00A 자기 인수 검사

경로가 현재 SOT와 충돌하면 임의로 다른 영역까지 고치지 말고 목표 문서에 충돌을 증거와 함께 기록해 이 프로젝트를 중단한다.

## 비범위

`docs/sot/` 변경, P00A 자기 인수 검사 외의 검사 추가, DB·후보 자료·외부 서비스 변경, 오너 대신 선택 확정.

## RED 먼저

오너 이름·결정시각·선택지·대가·되돌리기·`position_policy` 책임·개인정보 책임 중 하나가 없으면 `DECISION_APPROVED`가 될 수 없는 문서 계약 검사를 먼저 만든다.

## 구현 계약

최소 두 선택지를 같은 기준으로 비교하고 권고안을 밝히되, 오너의 명시적 선택 전 상태는 `BLOCKED_OWNER`다. 승인 기록은 결정 버전과 이후 P00B가 읽을 고유 지문을 갖는다.

## 가짜 합격을 깨는 시험

권고안만 있는 문서, 빈 서명, 모호한 “동의”, 선택지 없는 단일안, 되돌리기 없는 결정을 각각 주입해 `DECISION_APPROVED`가 거부되는지 증명한다.

## 검증

문서 계약 검사와 `bash verify.sh`를 실행하고 실제 검사 수·종료 코드를 기록한다. 오너의 명시적 답변 원문 참조 없이는 PASS를 출력하지 않는다.

## 원자적 인수 기준

후속 구현은 `bash scripts/acceptance-ai-ra-p00a.sh` 한 명령으로 오너·시각·선택지·대가·되돌리기·개인정보 책임이 모두 있을 때만 승인되고, 하나라도 없으면 `BLOCKED_OWNER`임을 검사해야 한다. 정상 실행은 `PASS AI_RA_P00A <실제 핵심 건수>`를 출력하되 실제 핵심 건수는 반드시 1 이상이고 종료값 0을 남겨야 하며, 핵심 차단을 한 줄 고장 낸 반대 시험은 0이 아닌 종료값이어야 한다. 이 프로젝트는 자기 인수 스크립트만 소유한다. P04가 소유한 `scripts/acceptance-ai-ra-all.sh`와 서버 workflow가 이름 규칙으로 자동 발견해야 하며, 이후 프로젝트는 공용 workflow를 직접 수정하지 않는다.

## 라이브 증거와 멈춤점

오너 결정이 있으면 `DECISION_APPROVED`, 없으면 `BLOCKED_OWNER`로 멈춘다. 두 상태 모두 SOT와 운영 자료를 바꾸지 않는다.

## 공통 strict 실행 지시

1. 기본 작업공간을 수정하지 말고 최신 기준 커밋에서 이 프로젝트 전용 worktree와 `task/` 브랜치를 만든다.
2. 코드보다 먼저 이 프로젝트 목표 문서를 작성하고 원자적 인수 기준 1개, 반대 시험, 비범위, 실제 검증 명령을 적는다.
3. `docs/sot/INDEX.md`, `coding-principles.md`, `git-workflow.md`, `hook-contracts.md`, `verification-commands.md`를 전문으로 읽고 체크리스트를 목표 문서에 남긴다.
4. v4/v5 코드는 행동·실패 사례와 테스트 오라클만 참고한다. import, 복사, subprocess 호출, 런타임 의존성은 금지한다.
5. RED를 실제 검사로 먼저 만들고 실패 출력을 목표 문서에 남긴다. 소스 문자열 존재만으로 결정을 증명하거나 검사 0건을 PASS로 세지 않는다.
6. 최소 구현 뒤 대상 시험→자기 번호 인수 검사→P04 공용 `scripts/acceptance-ai-ra-all.sh`→`bash verify.sh` 순으로 실행한다. P04 전 프로젝트는 자기 스크립트만 만들고 P04가 공용 배관을 연결하며, P04 이후 프로젝트는 이름 규칙 자동 발견을 증명하고 `.github/workflows/verify.yml`을 직접 수정하지 않는다.
7. 후보 원문·인증정보·운영 자료를 읽거나 옮기지 않는다. 오너 결정을 대신 만들지 않는다.
8. `claude -p` 1차 적대검토를 실행하고 각 지적을 Codex가 직접 재현한다. 한 항목이라도 동의하면 수정 후 1차부터 다시 반복한다.
9. 완료 보고는 결정 상태, 검증 종료 코드, `git diff --check`, 남은 차단을 구분한다. 오너 결정이 없으면 완료라고 하지 않는다.
