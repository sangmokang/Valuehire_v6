# Codeaudit 파일 크기 게이트 후속 goal — 강제력 설명 정정 (2026-08-15)

## 결론

파일 크기 검사는 실제로 작동하지만, 목표 문서가 서버 검사를 마지막 차단선이라고 잘못 설명해 현재 상태를 과장했습니다. 원격 기본선은 보호되지 않았으므로 설명을 사실대로 고치고 검증을 다시 통과시킨 뒤에만 병합 준비 상태로 보고합니다.

사장님께서 지금 결정하실 일은 없습니다. 병합과 배포는 자동 실행하지 않습니다.

## 판단 근거

- 파일 크기 본체와 자기시험은 로컬·서버 자동검사 실행 칸에 연결돼 있고 기존 서버 검사도 성공했습니다.
- 그러나 원격 기본선 조회 결과는 `protected=false`였고, 보호 규칙과 저장소 규칙 조회는 현재 요금제에서 403으로 거부됐습니다. 따라서 실패 표시는 생겨도 합치기 자체가 자동으로 막히지 않습니다.
- 로컬 전송 전 검사는 `git push --no-verify`로 우회할 수 있습니다. 현재 강제력은 사람 규율과 실패 표시까지이며, 문서가 말한 “마지막 차단선”은 존재하지 않습니다.

> **무엇을** — 파일 크기 목표 문서의 강제력 설명을 원격 실측과 로컬 우회 한계에 맞게 고칩니다.
> **왜** — 검사가 합치기를 막는다고 믿으면 사람 검토를 줄이는 잘못된 결정을 할 수 있기 때문입니다.
> **버린 길** — “서버 검사가 중요하다”처럼 표현만 약하게 바꾸는 길은 실제 차단 권한이 없다는 핵심을 숨기므로 버렸습니다.
> **대가** — 문서가 길어지고, 계정 요금제나 저장소 공개 범위가 바뀌면 원격 상태를 다시 확인해야 합니다.
> **되돌리기** — 이 문서 정정 커밋만 되돌릴 수 있지만, 그러면 이미 반증된 과장 문구가 다시 살아납니다.

## 증거와 실행 계약

### 1. 현재 상태

### 2. 근본 원인

서버 자동검사가 성공·실패 결과를 만든다는 사실과, 실패한 변경을 합치지 못하게 막는 원격 보호 설정을 같은 것으로 취급했습니다. 보호 설정을 직접 조회하지 않은 상태에서 강제력을 단정한 것이 원인입니다.

### 왜 B2를 합격으로 봤는가

B2의 반례는 "문서 정정 과정에서 실행 파일이나 검사 연결이 달라지면 불합격"입니다. 저는 이걸 두 방향으로 확인했습니다. 첫째, 이번 변경이 건드린 파일 목록을 뽑아 문서 2개뿐임을 확인했습니다(검사 프로그램·훅·CI 설정 파일은 목록에 없음). 둘째, 그것만 믿지 않고 검사 세 가지를 실제로 실행해 결과를 봤습니다. 파일 목록만 봤다면 "파일은 그대로인데 실행하면 깨지는" 경우를 놓쳤을 것이고, 실행만 했다면 "다른 파일이 조용히 바뀐" 경우를 놓쳤을 것입니다.

### 이 판정이 틀리면 무엇이 깨지는가

- 제가 B1을 잘못 합격시켰다면, 사장님께서 "검사가 있으니 사람 검토를 줄여도 된다"고 판단하실 위험이 되살아납니다. 실제로는 지금 **실패한 검사를 무시하고 합치기 버튼을 누르는 것이 기계적으로 가능**합니다(원격 조회로 확인).
- 제가 B2를 잘못 합격시켰다면, 문서를 고치는 과정에서 500줄 검사가 조용히 무력화된 채 병합됩니다. 그 경우 앞으로 늘어날 서치·등록 코드가 한도를 넘어도 아무도 모릅니다.
- 제가 "아직 서버에 안 올라갔다"를 놓쳤다면, 사장님께서 "서버 검사까지 초록"으로 오해하신 채 병합을 승인하실 수 있습니다. 지금 초록불은 **수정 전 문장이 들어 있는 버전**에 대한 것입니다.

|---|---|---|

| 요금제 때문에 저장소 규칙 403 | HTTP 403 "Upgrade to GitHub Pro..." | 일치 |

| `verify`를 필수 상태 검사로 지정 | 서버 검사 이름이 실제로 `verify` (아래 §7) | 일치 |

3. **중간에 다시 돌린 것:** 처음 두 번은 명령을 이어 붙이는 과정에서 종료 코드(프로그램이 성공/실패를 알리는 숫자)가 가려져 값을 못 읽었습니다. 그래서 세션 상태 점검과 원격 조회 3건을 **각각 다시 실행**해 종료 코드를 정확히 받았습니다. 아래 근거는 전부 재실행 결과입니다.

**판정은 통과(PASS)입니다.** 지난번 지적했던 "기계가 막습니다"라는 과장은 실제로 사라졌고, 그 자리에 들어간 새 설명이 **제가 GitHub에 직접 물어본 실측 결과와 정확히 일치**합니다. 요약(7행)과 잔여 한계(119행)가 "기계는 위반을 **실패로 표시**만 한다 / **합치기를 막는 권한**은 지금 없다"를 같은 방향으로 말합니다. 검사 장치 5종(파일 크기 본체, 19개 자기시험, 비밀 검사, 문서 정본 검사, 전체 세션 점검)은 전부 통과했고, 이번 수정이 실행 파일을 건드리지 않았음도 확인했습니다.
