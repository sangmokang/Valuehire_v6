# Admin Weekly Dashboard v6 Phase 0 계획 복구 goal — 2026-08-17

## 1층 — 결론

첫 준비 단계의 기존 합격은 무효입니다. 빠진 요구와 합쳐진 작업을 바로잡고, 새 독립 검사가 통과하기 전에는 다음 제품 작업을 시작하지 않습니다.

이번 작업은 계획과 그 판정 장치만 고칩니다. 관리자 화면, 의존성 설치, 외부 서비스 호출은 하지 않습니다.

## 2층 — 판단 근거

기존 계획은 실행 환경 버전을 두 곳에 고정하라는 상위 요구 중 한 곳만 작업으로 만들었습니다. 또한 공개 방지 설정과 작업 폴더 선언이라는 서로 다른 결과를 한 작업에 묶었습니다.

기존 감사는 행 개수와 연결 관계는 셌지만 요구 문장별 누락을 잡지 못했습니다. 따라서 과거 합격 문서는 보존하되 실행 허가로 사용할 수 없다고 별도 기록하고, 같은 결함을 다시 잡는 저장소 검사를 추가해야 합니다.

정본 문서는 현재 루트 설정 파일이 없다고 적고 있지만 실제 파일은 존재합니다. 계획보다 정본이 먼저이므로 이 사실도 같은 변경에서 바로잡습니다.

### 결정 카드 1 — 누락된 실행 환경 요구

**무엇을** — `package.json`의 `engines.node`를 별도 원자 작업으로 추가합니다.

**왜** — `.node-version`과 `engines.node`는 파일, 실패 이유, 되돌림 단위가 다릅니다.

**버린 길** — 기존 Node 작업에 사후 편입하는 길은 기존 작업의 허용 파일과 독립 감사 범위를 바꾸므로 버립니다.

**대가** — 작업 행과 의존 관계가 하나 늘고 별도 검증 기록이 필요합니다.

**되돌리기** — 새 행과 그 연결만 독립적으로 제거할 수 있지만, 그러면 상위 요구 누락 상태로 돌아가므로 계획 합격도 함께 취소해야 합니다.

### 결정 카드 2 — 루트 설정과 작업 폴더 선언 분리

**무엇을** — `private=true`와 `pnpm-workspace.yaml` 선언을 서로 다른 작업으로 나눕니다.

**왜** — 하나가 맞고 다른 하나가 틀릴 수 있어 실패 이유와 되돌림이 독립적입니다.

**버린 길** — 둘을 “하나의 패키지 관리자 경계”로 계속 묶는 길은 한 작업에 두 결과를 허용하므로 버립니다.

**대가** — 기존 작업 이름과 의존 관계를 갱신해야 합니다.

**되돌리기** — 새 작업 둘을 과거 묶음으로 되돌릴 수 있지만, 계획의 원자성 합격은 다시 취소됩니다.

### 결정 카드 3 — 과거 합격 기록 처리

**무엇을** — 과거 감사 파일은 수정하거나 삭제하지 않고, 별도 무효화 기록으로 실행 허가만 회수합니다.

**왜** — 과거 원문을 보존하면서도 다음 작업이 잘못된 합격을 의존성으로 쓰지 못하게 해야 합니다.

**버린 길** — 과거 감사 파일을 덮어쓰는 길은 당시 증거를 훼손하므로 버립니다.

**대가** — 독자는 과거 감사와 최신 무효화 기록을 함께 봐야 합니다.

**되돌리기** — 새 무효화 기록을 되돌릴 수 있지만, 그러려면 누락과 비원자 결함이 없다는 새 독립 증거가 먼저 있어야 합니다.
