# AI-native RA 기획 패킷 최신 기준 결합 재검증 목표 — 2026-08-18

## 결론

기획 패킷은 아직 최신 기준에 결합됐다고 인정할 수 없습니다. 별도 작업공간은 최신 기준에서 만들었지만, 결합 전 시작 검사에서 기존 예상과 달리 실패 1건이 나왔으므로 원인을 해소하고 모든 검사를 다시 통과해야 합니다.

이번 작업은 기획 문서의 결합 가능성만 확인합니다. 실제 책임자 선택이나 제품 구현은 시작하지 않으며, 모든 완료 조건을 충족하지 못하면 차단 근거만 남깁니다.

## 판단 근거

감사 당시에는 기획 패킷과 기준 브랜치의 같은 파일 경로가 없다는 사실만 확인됐고, 실제 결합과 최신 전체 검사는 수행되지 않았습니다. 파일 경로가 겹치지 않아도 문서 계약이나 저장소 검사가 새 기준에서 깨질 수 있으므로 실제 결합 결과만 합격 근거로 삼습니다.

작업 시작 직전 원격 기준을 새로 받아 확인한 결과, 로컬 기준과 원격 기준은 같은 기록이었습니다. 그러나 별도 작업공간에서 시작 자격 검사를 실행하자 실패 1건이 보고됐습니다. 이 값은 결합 전부터 존재했으므로 기획 패킷 탓이라고 추정하지 않고, 실패한 검사 이름과 원인을 직접 찾아 원래 명령을 재실행합니다.

최신 검증 정본(=저장소가 공식 답으로 삼는 문서)은 서버 자동 검사 17단계와 도달 불가능한 과거 기록을 공격하는 13개 합성 사례를 요구합니다. `docs/sot/verification-commands.md:20`은 17단계 전체가 정본이라고 선언하고, 같은 파일 24~40행은 각 단계를 열거하며, 28행은 13개 합성 사례를 AC-19(=도달 불가능한 과거 기록 검사의 합격 조건)로 지정합니다.

P00A 프롬프트는 세 산출물만 소유합니다. 소스 커밋의 `docs/engineering/goal-prompts/ai-native-ra-search-orchestration/p00a-data-ownership-owner-decision.md:13`은 작업 소유 범위를 시작하고, 15~19행은 결정 기록·목표 문서·자기 인수 검사 세 경로만 열거합니다. 이번 작업은 그 문구의 정확성만 대조하며 세 산출물을 실제로 만들지 않습니다.

## 결정 카드

**무엇을** — 최신 기준 기록에서 만든 별도 작업공간에 목표 문서를 먼저 고정하고, 그 다음 기획 패킷 한 기록만 가져와 전체 검증을 실행합니다.

**왜** — 기본 작업공간과 기준 브랜치를 건드리지 않으면서 실제 결합 결과와 검사 증거를 남길 수 있기 때문입니다.

**버린 길** — 기존 기획 작업공간에서 기준 브랜치를 합치거나 기준 브랜치를 직접 고치는 길은 버렸습니다. 어느 쪽도 “정확한 최신 기준에서 새 작업공간을 만든다”는 요청을 충족하지 못합니다.

**대가** — 목표 문서 기록과 기획 패킷 기록이 별도 기록으로 남고, 전체 검증과 두 엔진 검토에 시간이 듭니다.

**되돌리기** — 이 작업 브랜치와 별도 작업공간만 제거하면 시작 전 상태로 돌아갑니다. 기준 브랜치에는 쓰지 않으므로 되돌림 비용은 격리된 작업 기록 폐기뿐입니다.
