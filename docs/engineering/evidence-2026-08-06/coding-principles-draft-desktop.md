### 2-E. 모듈 크기 — 실측 (원칙 F의 근거)

v5 소스 모듈 126개를 크기 구간으로 묶어, **같은 분량 대비** 결함이 얼마나 붙었는지 측정.
패키지 표시 파일(`__init__.py`)과 명령줄 실행 스크립트는 **import 되지 않는 게 정상**이므로 제외.

| 모듈 크기 | 파일 | 100줄당 결함수정 | 100줄당 라이브사고 | 고아율 |
|---|---|---|---|---|
| **~99줄** | 19 | **0.44** | 0.088 | **16%** |
| **100~299줄** | 47 | 0.97 | 0.035 | 23% |
| **300~599줄** | 23 | 1.42 | 0.063 | **9%** |
| **600~999줄** | 6 | 1.52 | **0.181** | 17% |
| **1000줄+** | 8 | 0.92* | 0.012* | **50%** |

\* 1000줄+ 의 결함 밀도가 낮아 보이는 건 **그 구간 8개 중 4개(8,940줄)가 고아**라 아예
안 고쳐졌기 때문이다. **고아를 빼고 실사용만 보면 1.80으로 전 구간 최악.**

**결론 세 가지**

1. **결함 밀도는 크기에 단조 증가한다** — 0.44 → 1.52. 어디에도 "너무 작아서 나빠지는" 지점이 없다.
2. **600~999줄이 라이브 사고 최악**(0.181, 다른 구간의 2~5배).
3. **고아는 큰 파일에서 생긴다** — 1000줄+ 고아율 **50%**. 무서워서 아무도 못 건드린다.
   실제 예: `portal_live_check.py` 3,963줄(호출자 0), `humansearch_register.py` 897줄
   (**22번 고쳤는데 배선 안 됨**).

> **따라서 하한은 두지 않는다.** 잘 쓰이는 23줄짜리(`portal_keychain.py`, 호출자 3)가
> 실제로 있다. 상한만 건다: **300줄 경고 / 600줄 차단.**

**정정 기록**: 초판에서 "99줄 아래는 고아율 50%라 너무 잘게 쪼개면 안 된다"고 썼으나,
이는 **측정 오류**였다 — `__init__.py` 7개와 실행 스크립트 6개를 고아로 잘못 셌다
(16개 중 13개가 오탐). 사장님 지적으로 재측정해 결론을 뒤집었다.

## 3. 적대검증의 한계 — 원칙 3을 쓸 때 반드시 함께 안다

**적대검증을 통과하고도 깨진 것은 예외 없이 "코드 안에 없는 사실"에 기댄 것이었다.**
생성자도 검증자도 코드와 테스트만 본다. 실제 화면은 둘 다 못 본다.

| 실제 사례 | 무슨 일 |
|---|---|
| 상세 화면 완료 판정 | **3연속 오판** — HTML 77만 자인데 화면엔 "Loading." / 200자 임계 / 2000자 |
| 다음 페이지 버튼 | `button[aria-label='Next']` 가 **실제 화면에 없었다**. 가짜 화면은 만들어 줬다 |
| 지역 선택 클릭 | **5연속 수정** — 라이브 1회 실행당 결함 1개만 드러난다 |
| 로그인 여부 | 모델에게 *"login_verified 를 적어라"*고 시켰다 → 위조 가능, 3주 뒤 봉인 |
| 미검증 배송 | 커밋에 `Not-tested: Live ... round trip` 이라 **정직하게 적고도 통과** |

**대응**: 적대검증은 유지하되, 그 위에 **라이브 1건 영수증**을 완료 조건으로 얹는다.
적대검증은 "코드가 자기 규칙을 지키는가", 라이브 영수증은 "현실이 그 규칙과 같은가".
**둘은 대체재가 아니라 서로 못 하는 일을 맡는다.**

## 4. 브랜치·배포 전략

| 단계 | 규칙 | 근거 |
|---|---|---|
| **브랜치** | `main` 하나 + 작업별 단명 브랜치. 장수 브랜치 금지 | 6주 묵은 워크트리가 **98커밋 한 덩어리**가 됨 |
| **크기** | 한 PR = 인수 기준 1개 = **300줄 이내** | 98커밋 PR은 리뷰 불가 |
| **머지** | squash merge만. 머지 즉시 브랜치·워크트리 삭제 | 옛 세대 동거 방지 |
| **게이트** | CI 초록 없이 머지 불가 | v4는 테스트 549개인데 **CI 실행 0건** |
| **배포** | 태그 = 배포 단위. **예약작업 등록이 배포 스크립트에 포함**(원칙 H) | 손으로 등록해 v2를 가리킨 채 방치 |
| **롤백** | 이전 태그로 되돌리는 명령 한 줄이 항상 존재 | 없음 |
| **비밀** | 저장소에 두지 않음. Keychain/시크릿 매니저만 | `.env.local` 백업 3개 산재 |

## 5. 웹 자동화(사이트에 붙어 조회·수집·입력)에만 적용되는 5조

가장 많이 실패한 영역이라 따로 둔다.

1. **셀렉터는 코드가 아니라 데이터다** — `contracts/*/markers.json` 한 곳. 드리프트 대응 = 데이터 수정.
2. **판정기는 하나다** — 자동로그인 판정과 증거캡처 판정이 같은 함수를 쓴다.
3. **브라우저 계층은 한 벌이다** — 두 벌이 생기면 셀렉터 출처가 4곳으로 갈라진다(실측).
4. **테스트는 실캡처 스냅샷으로만** — 시나리오 전체를 가짜 브라우저로 흉내내는 테스트를 **만들지 않는다.** 판정 / 배선 / 동작 3갈래로 나눠 검사한다.
5. **개입 감지는 규율이 아니라 구조로** — 드라이버 포트를 감싸 개입 신호 이후 호출이 **타입상 불가능**하게. (손으로 검사 호출을 뿌린 v5에서 같은 결함 8회 재발)
