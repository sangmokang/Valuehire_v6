# Issue #71 검사 삭제 우회 차단 goal

## 결론

Issue #71의 결함은 현재 기준선에서 다시 재현됐습니다. 검사 실행 줄·스텝·워크플로 파일을 지우거나 실행되지 않는 확장자로 바꾼 다섯 경우가 커밋 훅을 통과했습니다.

구현 완료로 올릴 수는 없습니다. 필수 작업 단위 정책 파일 `docs/sot/work-unit-policy.yaml`이 현재 정본에 없고, 기존 PR #74는 최신 `main`보다 오래된 기준에서 작성됐으며 검사 스크립트와 호출을 같이 지우는 것만으로 은퇴를 허용해 이번 지시와 충돌합니다.

## 판단 근거

작업 단위 정책은 각 작은 변경의 필수 필드와 완료 전환 규칙을 소유해야 합니다. 파일이 없는데 PR #37 또는 다른 세션의 미병합 사본을 정본으로 쓰면, 검사를 보호하면서 정작 보호 규칙을 임의로 선택하는 모순이 생깁니다.

기존 PR #74의 구현은 회수 대상이지 현재 합격 증거가 아닙니다. 현재 `main`에 이미 들어간 PR #70·#80·#81의 보호와 다시 합친 뒤, 아래 계약으로 실패 재현부터 새로 검증해야 합니다.

> **무엇을** — `.github/workflows/*.yml|*.yaml`의 실제 검사 실행이 스테이지된 커밋에서 사라지는 모든 경우를 차단합니다.
> **왜** — 파일이나 호출 한쪽 또는 양쪽을 지워 자동 검사를 없애도 기존 훅이 초록으로 끝나는 결함이 재현됐기 때문입니다.
> **버린 길** — PR #74를 현재 상태 그대로 완료 처리하는 길은 버립니다. 오래된 기준과 자동 은퇴 허용이 최신 계약을 위반합니다.
> **대가** — 작업 단위 정책이 병합되기 전에는 안전한 재현·비교·계약 초안까지만 진행할 수 있습니다.
> **되돌리기** — Issue #71 전용 브랜치의 각 WU 커밋만 역적용하며 `main`, PR #37, 다른 작업 공간은 초기화하지 않습니다.

## 3. T 계약: 입력·출력·오류·경계

### 생산 호출

```text
hooks/pre-commit
  -> scripts/verify/check-workflow-deletion.sh
  -> exit 0 | 1 | 2
```

→ 실제 제품 진입점은 Git 커밋 훅이며 검사기는 인자 없는 생산 호출을 지원해야 합니다. 테스트 전용 인자 경로만 통과하면 고아 코드로 판정합니다.

### 입력

- 기준 입력: 현재 `HEAD`의 추적 트리.
- 확정 입력: 커밋될 Git index의 스테이지된 트리. 작업 폴더 본문은 판정 권한이 아닙니다.
- 보호 범위: `.github/workflows/*.yml`과 `.github/workflows/*.yaml`의 실행 가능한 `run` 경로와 저장소의 필수 검사 명부.
- 은퇴 입력: 정본이 승인한 명시적 은퇴 기록. 파일 부재나 호출 부재 자체는 승인 기록이 아닙니다.

### 출력과 종료값

- `0`: 정상 변경이며 `PASS`와 양수 `CHECKED`를 출력합니다.
- `1`: 검사 실행 소실 또는 승인되지 않은 은퇴이며 `BLOCKED`, 사라진 검사 ID·경로를 출력합니다.
- `2`: 저장소·HEAD·index·정본·파서·임시 입출력·대상 수 확인 실패이며 `NOT_RUN` 또는 `FAIL`, `CHECKED: 0`을 출력합니다.
- 종료값 0인데 `PASS` 또는 양수 `CHECKED`가 없으면 성공으로 세지 않습니다.

### 경계·오류·동시성·재시도

- 워크플로 0개, 필수 검사 0개, 파싱 불가, 정본 누락은 성공이 아닙니다.
- 스테이지와 작업 폴더가 다르면 스테이지를 판정하고 작업 폴더 미끼를 무시합니다.
- 검사 줄 삭제, 스텝 삭제, 워크플로 파일 삭제, `.yml`에서 실행되지 않는 확장자로 이름 변경을 모두 차단합니다.
- 실행 순서 이동, 스텝 표시 이름 변경, 주석 삭제, 다른 `.yml|.yaml`로 이름 변경은 실행 집합이 같으면 통과합니다.
- 스크립트와 호출을 같이 삭제해도 승인된 은퇴 기록이 없으면 차단합니다.
- Git index가 검사 도중 바뀌면 성공을 내지 않습니다. 같은 커밋 시도에서 자동 재시도하지 않고 원인을 출력합니다.
- 첫 커밋처럼 `HEAD`가 없거나 필요한 기준을 만들 수 없으면 이 저장소의 보호 이력을 비교할 수 없으므로 종료값 2입니다.

## 4. EARS 합격 조건과 counter-AC

### AC-71-01 — 실행 소실 차단

When 남아 있는 필수 검사 스크립트의 실제 워크플로 실행 줄·스텝·파일을 스테이지에서 제거하면, 시스템은 커밋을 종료값 1로 차단하고 사라진 검사 경로를 출력해야 합니다.

- 검증 명령: `bash scripts/acceptance-p13-deletion.sh`
- 기대: 양성 시연 전부 차단, 정상 대조 전부 통과, `CHECKED` 양수, 최종 종료값 0.
- counter-AC: 주석·echo·환경값에 경로 문자열만 남아 실행이 사라졌는데도 집합에 남았다고 합격하면 가짜입니다.

### AC-71-02 — 삭제 전용 스테이지

When 변경이 삭제만 포함하거나 작업 폴더에 정상 미끼가 남아 있어도, 시스템은 Git index의 삭제를 실제 훅 검사 대상으로 삼아야 합니다.

- 검증 명령: `bash scripts/acceptance-p13-deletion.sh`
- 기대: 삭제 전용과 index/worktree 불일치 시연이 해당 검사 사유로 차단되고 훅을 끄면 같은 스테이지가 커밋됩니다.
- counter-AC: 다른 훅 오류의 종료값 1을 이 검사의 성공으로 세거나 작업 폴더의 정상 파일을 읽으면 가짜입니다.

### AC-71-03 — 로컬·CI·명부 연결

Where 보호 장치가 존재하면, 시스템은 pre-commit 생산 호출, CI의 판정 래퍼 호출, 기계 명부, 검증 명령 정본에서 같은 검사 ID와 실행 경로를 확인해야 합니다.

- 검증 명령: `bash scripts/acceptance-verify-ac-m.sh`, `bash scripts/acceptance-principles-check.sh`, `bash scripts/acceptance-ci-step-integrity.sh` 및 현재 정본이 확정한 관련 원명령.
- 기대: 각 명령 종료값 0, 양수 `CHECKED`, 로컬·CI 대상이 0개가 아님.
- counter-AC: 검사 파일만 있고 실제 훅이나 CI가 부르지 않거나, 문자열을 echo하는 줄을 실행으로 세면 가짜입니다.

### AC-71-04 — 승인된 은퇴만 허용

If 필수 검사 스크립트와 모든 호출을 함께 제거하면, 시스템은 현재 정본의 은퇴 승인 조건이 충족된 경우에만 통과하고 그렇지 않으면 종료값 1로 차단해야 합니다.

- 검증 명령: 작업 단위 정책과 은퇴 정책의 정본 경로가 확정된 뒤 별도 RED로 고정합니다.
- 기대: 승인 없는 동시 삭제 차단, 만료·오형식·위조 승인 차단, 정본상 정상 은퇴만 통과.
- counter-AC: 파일이 없다는 사실, 억제 만료일 연장, 같은 작성자가 만든 임의 장부만으로 은퇴를 승인하면 가짜입니다.

4. Gate 3.5: `git commit` → `hooks/pre-commit` → 검사기, CI workflow → 판정 래퍼 → 인수 검사의 두 호출 경로를 증명합니다.

7. Gate 6·SHIP: 이번 범위 밖입니다. push·PR 수정·병합·배포를 실행하지 않습니다.

감사 순서는 실패 재현 → 최소 구현 → 회귀시험 → codeaudit → humanreview → V1 → V2입니다. 감사에서 결함이 나오면 수정 뒤 같은 원명령과 영향을 받은 감사를 다시 실행합니다.
