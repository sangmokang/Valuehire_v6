## 3. Issue → PR → CI → Merge 사슬의 실제 상태

**붙어 있는 칸**: 이슈-PR 1:1 연결은 잘 된다. `#71→#74` · `#72→#77` · `#73→#75` · `#76→#78`.

**비어 있는 칸**:
- **required check 없음** — `gh api repos/.../rulesets` 와 `.../branches/main/protection` 둘 다
  `HTTP 403 "Upgrade to GitHub Pro"`. 개인계정 + private 저장소의 구조적 제약.
  → CI가 빨간불이어도 병합 버튼이 막히지 않는다.
- **merge = 사람 1명** — strict 계약 `USER_MERGE_ONLY`. 안전 규칙으로는 옳으나 현재 유일한 병목.

**L4. 검증 산출물을 gitignore 에 넣는 순간 검증이 관측 불가능해진다.**

→ 상세: `docs/engineering/` 밖, 메모리 `project-ci-outage-20260909`.

**L7. "원시적"이라는 감각의 정체는 방법론의 오류가 아니라 실행체의 부재다.**

**L8. 세션 병렬 실행은 경계를 명시하지 않으면 중복을 만든다.** 2026-09-09 CI 장애를
두 세션이 각자 조사해 4분 간격으로 거의 동일한 메모리를 중복 생산했다(하나 폐기).
