# 밸류커넥트 Weekly 작성·검증 프롬프트 — Codex / Claude 공용 v2.2

이 문서는 기존 주간보고 스킬을 대체하지 않는다. 두 에이전트가 동일한 검증 규칙을 사용하도록 하는 공용 보충 지침이다. 정기 주간 작성·게시 요청은 설치된 `weekly` 스킬과 저장소 정본을 따른다. 기존 페이지·프롬프트의 검토 요청은 별도 쓰기 지시가 없으면 읽기·검증·초안 모드다.

## 지금 실행할 입력

- 모드: 읽기·검증·재집계 초안. 기존 페이지를 고치지 않는다.
- W46 live 형식 사례: https://app.notion.com/p/valueconnect/FY26W46-40d345c17dca8194995ccd15dd9c1210
- W45 원형 샘플: https://app.notion.com/p/valueconnect/FY26W45-406345c17dca81a8951cc7f778b91c48
- admin 실측 화면: https://admin.valuehire.cc (인증 후 Weekly/Operations 화면)
- 요청: 세 자료의 역할을 구분하고, 같은 기간·정의·cutoff에 대해 Notion과 admin 실측을 대사한다. 원문을 읽지 못한 값은 검증 완료로 표시하지 않는다.

미래 주차에서는 Notion 대상 URL과 승인된 기간을 이번 실행에서 다시 확인한다. URL 변경만으로 페이지 생성·쓰기·공유 권한이 생기지 않는다.

## 1. 근거로 삼는 자료와 쓰임

1. **W45**는 원형·구조 골든 샘플이다. 섹션 구성·표현·보존 방식을 참고한다. 과거 숫자, 목표, 담당 배분, 정의를 새 주에 복사하지 않는다.
2. **W46**은 live 형식 사례다. 표준 구성과 실제 페이지 순서 차이 및 데이터 충돌을 찾는 자료다. 오류가 있는 수치나 형식을 정답으로 간주하지 않는다.
3. **admin.valuehire.cc**는 이번 기간 운영 실측을 확인할 별도 시스템이다. Notion이나 Weekly Brief의 문구를 그대로 되풀이하지 말고 인증된 앱 화면에서 지표 정의·기간·cutoff·행/식별자를 확인한다.
4. 승인된 데이터 계약, Notion 원천 DB, Gmail의 실제 이벤트 및 Weekly Brief의 `public.weekly_brief_snapshot(date)`는 각 지표의 정의·출처를 확인하는 근거다. 각 시스템이 서로 다르면 임의로 우선순위를 만들지 말고 차이를 기록한다.

페이지를 열 수 없거나 로그인 화면만 보이면 정상 접근을 진단하고, 사용자가 승인한 계정·공식 UI/연결 도구만 사용한다. 암호·쿠키·토큰·브라우저 저장값을 읽거나 복사하지 않는다. 우회 API, 숨은 endpoint, 자격증명 파일은 사용하지 않는다. Notion 또는 admin의 원문을 못 읽으면 해당 소스의 범위 완전성은 `불명` 또는 `부분`이고, 그 소스 기반 지표는 `미검증/보류`다.

## 2. 실행 전 확인

먼저 현재 도구·계정·권한·schema와 승인된 지표 계약을 확인한다. `docs/sot/29-weekly-machine-spec.md`, `docs/sot/14-weekly-screen-columns.md`, 대상 회의록의 `WEEKLY_KPI` 계약이 있는 환경이면 이를 읽는다. 파일·도구가 없는 환경에서는 없다고 기록하고 대체 근거의 한계를 밝힌다.

대상과 두 샘플의 page ID, 제목, 객체 종류, Date, Duration, FY/Week, 속성, 본문, 표, 하위 페이지·DB 참조, last-edited 및 읽은 범위를 기록한다. 페이지네이션·truncation·미열람 링크를 확인한다. 제목만 같다는 이유로 다른 객체를 대신 고르지 않는다.

운영 기간은 최신 승인된 주간 정의와 실제 페이지·소스를 서로 대조한다. KST 반열린 구간을 승인된 시작요일에 따라 계산하고, 회의일(Date)과 성과기간(Duration)을 구분한다. 일반 규칙의 월~일은 운영 정의가 확인된 경우에만 적용한다. 종료일 경계, timezone, 소스별 cutoff를 검수한다. 승인된 정의가 충돌하거나 불명확하면 기간 의존 집계를 보류하고 구조 점검과 원문 수집만 계속한다.

## 3. admin ↔ Notion 대사 절차

1. admin 화면에서 같은 주차·기간을 선택하고 화면의 조회시각, 데이터 cutoff, 필터, 지표 정의, 단위, 분모·분자를 기록한다. 대시보드 카드 합계만으로 전수 확인이라 부르지 않는다.
2. 가능한 범위에서 세부 행 또는 항목별 식별자를 확인한다. ClickUp 카드와 admin 행은 `clickup_task_id` 또는 승인된 정규화 프로필 키 등 공통 ID로 대조한다. 수가 같다는 사실만으로 같은 집합이라고 하지 않는다. AI Search 배치, 검색 모집단, 프로필 정독, 접촉 발송, 내부 추천판정, 고객사 외부추천, ClickUp 역매칭은 각각 구분한다.
3. Notion 본문·표·속성·자동 미러와 admin의 행·요약을 같은 정의 및 cutoff끼리 대조한다. 핵심 KPI마다 `Notion 값 / admin 값 / 원천 값 / 단위 / 정의 / cutoff / 연결 가능한 ID 수 / 차이 / 원인 상태`를 남긴다.
4. 고객사 추천은 Gmail 외부 발송을 실제 수신자·본문·발송시각으로 확인하고 최초 외부 발송 기준으로 중복 제거한다. 내부 전달, 초안, 예약, 실패, 재작성은 외부 발송이 아니다. 원문 Message-ID/action ID나 복사본 증거가 없으면 이름·유사본문·근접시각만으로 합치지 않는다.
5. 합계가 다른 경우 기간 경계·timezone·집계 단위·중복·누락 ID·지연 반영·취소/실패 상태·필터를 차례로 점검한다. 원인을 입증하지 못하면 차이를 남기고 `충돌/미검증`으로 판정한다. 더 최신으로 보이는 숫자를 자동 정답으로 선택하지 않는다.
6. admin 인증·조회·페이지네이션이 안 되면 그 사실과 영향 KPI를 구체적으로 적는다. ClickUp 카드 수와 admin 행 수를 비교할 수 없으면 `대조 미실시`로 남기고 set equality를 주장하지 않는다.

## 4. 지표·근거 규칙

다음은 혼합하지 않는다.

- 프로필 정독: 상세 보고서에서 확인한 프로필 수
- 접촉 발송: 플랫폼별 발송 이벤트 수. 채널 간 중복을 제거하지 못하면 최소 건수와 비고를 쓴다.
- 내부 추천 판정: AI Search 내부 등급으로 분류된 후보 수
- 고객사 실제 추천: Gmail 외부 발송 중복 제거 후의 추천 행위 수
- ClickUp 역매칭: 원시 카드 수와 고유 후보 수를 나누고 신규 소싱에서 제외
- 수락·후속요청·자료수신·고객추천·ATS 접수·면접·오퍼·입사·매출: 각기 별도 단계

같은 ID로 분자와 분모 코호트를 연결하지 못하면 전환율을 계산하지 않는다. 활동량을 전환율로 부르지 않는다. 동일 이벤트를 증명할 수 없는 중복 의심 건은 격리하고 신규 실적에 넣지 않는다. 로그 0행은 수행 0회를 증명하지 않는다. `null`·빈 값은 0이 아니다.

각 지표에는 근거 등급을 붙인다: `E1` 이번 실행에서 원문/이벤트 직접 확인, `E2` 이전 검증기록 인용(이번 재검증 아님), `E3` 메타데이터·검색결과·요약만 확인, `E0` 미접근/근거 없음. 또한 범위 완전성(완료/부분/불명), 정합성(통과/충돌/미검증), 집계상태(확정/하한/표본/보류)를 각각 분리한다. 일부 E1 관측만으로 전수 확정하지 않는다.

수치가 확정되려면 승인된 기간·정의·완료된 범위·충분한 원문 근거·중복 대사·산술 및 본문/표/속성 정합성이 모두 필요하다. 부분 확인은 `확인된 최소 N건` 또는 `표본 N건`으로 한정하고, 확정값과 하한/표본의 평균·증감을 섞지 않는다. 출처는 가능한 경우 객체 ID·block/section ID·버전/snapshot·cutoff·조회시각까지 식별한다. 지원하지 않는 식별자를 만들어내지 않는다.

## 5. W45/W46 사례에서 유지할 주의점

아래는 이 프롬프트를 작성할 때 제공된 조사 요약에 포함된 과거 사례이며, 이번 실행의 live 재검증 결과나 다음 주 기본값이 아니다.

- W46 요약에는 Date `2026-11-09`, Duration `2026-11-02~2026-11-08`, KST 구간 `[2026-11-02 00:00, 2026-11-09 00:00)`가 적혀 있었다. 회의일과 성과기간 및 회의일 신규실적 제외 여부를 다시 확인한다.
- W46에 달성 8/목표 20, 상단·미러 40%, KPI 일부 35% 충돌이 있었다. `8÷20=40%`라는 산술은 맞아도 운영상 최신 값이라고 단정하지 않는다. 소스·정의·cutoff·행별 명단을 재확인한다.
- 역사 보고의 외부 추천 7에 후속 1건이 추가된 사례가 있어 카드 생성 수와 고유 추천 수를 같다고 추정하지 않는다.
- 알림 검색 첫 25건 중 수락 9·거절 16은 표본일 수 있으므로 전수 수락률로 부르지 않는다.
- 기존 상세열람·접촉·AI Search subtask·admin 행 수는 정의와 cutoff가 달라 서로 나누어 전환율로 만들지 않는다.
- W46 본문에서 지난주 회의 핵심 내용이 출처 뒤에 있고 자동 미러가 마지막에 놓였다는 사례는 구조 관찰이다. 관리 경계와 순서를 확인하기 전에 재배열하지 않는다.
- W45는 원형 구조 참고다. W46의 수치·수정오류·순서를 그대로 복제하지 않는다.

## 6. 결과와 변경 경계

검토 출력에는 ① 확정 KPI ② 하한/표본 KPI ③ 보류 KPI ④ 접근실패와 영향범위 ⑤ 수정안·차이·미확인 사항을 먼저 요약한다. 이어 실행모드, 대상 URL, 기간·cutoff, 소스별 접근상태, 근거등급·범위완전성·정합성·집계상태, admin↔Notion 차이표, W45/W46 구조 매핑, 액션 제안을 쓴다.

기존 페이지 검토는 기본적으로 읽기 전용이다. 명시적 업데이트 요청이 있을 때만 기존 weekly 스킬의 승인·동시성·자동미러 소유권·부분실패·read-after-write 조건을 따른다. 원문/하위페이지/자동관리 영역을 보존하고, 최신 버전 확인과 배타성/조건부 갱신이 안 되면 초안으로 끝낸다. 수치·Status·목표·formula를 추정으로 고치지 않는다. 메일·메시지·후보/포지션 변경은 별도 요청 없이 수행하지 않는다.

### 이 버전의 검토 상태

v2.2는 W45/W46과 admin을 함께 확인하도록 규칙을 보강한 문안이다. 2026-11-09 작성 환경에서는 Notion 페이지가 로그인 없는 브라우저에서 본문으로 열리지 않았고 admin은 `/login?next=/admin/operations-summary`로 이동했다. 따라서 이 저장소 변경은 이 두 시스템의 실데이터 독립검증을 의미하지 않는다. 접근할 수 있는 계정에서 재조회한 뒤, 실제 받은 리뷰·검증만 완료로 기록한다. 이전 v2.1의 ChatGPT 의견은 이 v2.2의 외부 재검토가 아니다.
