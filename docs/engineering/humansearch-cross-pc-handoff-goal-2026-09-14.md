# HumanSearch 다른 PC 재개 — goal (2026-09-14)

## 결론

사용자 요청은 현재 작업을 GitHub에서 이어갈 수 있게 보존하고 준비가 끝나면 본인에게 설정 안내를
이메일로 보내는 것이다. 이 WU는 재개 안내와 과거 실행 프롬프트 원문 2개·선행 장부/kickoff 2개를 저장소 문서로 보존한다.
사용한 strict/codeaudit Codex 지침 원문도 프로젝트에 보존한다. 제품 기능 수정은 담당 PR이 소유한다. 안내 메일 승인은 제품 후보 접촉·팀메일 발송 승인과 구분한다.

## 계약

- 입력: 9월 14일 사용자 요청, 실제 원격 브랜치/PR/CI, pyproject, hooks, 검증 SOT.
- 출력: 상대경로 재개 문서, 실행 원문, 복제·worktree·검증 명령, 보호 데이터 이관 경계.
- 오류: 원격에 없는 SHA나 미완료 감사는 명시하고 완료 링크로 표현하지 않는다.
- 부작용: task 브랜치 push/PR와 승인된 owner 안내 메일. main 자동 병합 없음.
- AC: 새 clone에서 안내·근거 문서 5개가 열리고 작업 브랜치를 조회할 수 있으며 설치/시험 명령이 실제 저장소와 일치한다.
- counter-AC: Git만으로 로그인·후보 DB·대화 상태가 이관된다고 설명하거나 라이브 NOT_RUN을 완료로 바꾼다.
- 보존: 과거 원문은 수정하지 않고 최신 지시 우선과 절대경로 치환을 안내 문서에 명시한다.
- 검증: 원문 SHA 대조, 상대 링크·원격 ref 확인, diff check, verify, principles, 문서 검토, 현재 SHA CI.

현재 상태: 검토 후보. 원격 전달과 안내 메일은 아직 실행하지 않았다. 설정 절차는 현재 macOS 관측에 근거하며
다른 PC에서 실제 설치·브라우저 운영을 시험했다는 뜻이 아니다.

검증 장부(인계 준비 시점): 원문 6개(v5·HS13·장부·kickoff·스킬 2개)는 출처와 바이트/SHA 일치.
새 안내/goal 형식 검사는 위반 0건이며 제품 검증이 아니다. 외부 Sonnet 문서 검토는 안전·범위 적합으로
판정하고 Python 준비 절차 보강을 요구했다. 공식 uv 문서는 자동 설치가 기본임을 확인하므로
“명시 설치 없으면 반드시 실패”는 재현된 결함으로 채택하지 않았다. 다만 `uv python install 3.14`를
안내에 추가해 준비 단계를 분명히 했다. 원격 ref 사전 조회와 다른 worktree의 스킬 회수 명령도 보강했다.
로그·원문은 보호 경로에 보존하며 GitHub 인계 및 새 clone 검증은 아직 진행 중이다.
