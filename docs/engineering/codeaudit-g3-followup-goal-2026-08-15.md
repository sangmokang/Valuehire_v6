# Codeaudit G3 후속 수정 goal — 명부·강제력·잔여 한계 (2026-08-15)

## 결론

이 변경 요청은 검사 장치 자체는 작동하지만, 장치 명부 누락과 잘못된 강제력 설명, 서로 다른 잔여 한계 목록이 남아 있어 아직 병합 준비가 끝나지 않았습니다. 세 결함과 주석만으로 명부 대조를 속이는 옆문을 닫고, 두 번의 독립 검증과 서버 검사가 모두 통과할 때만 병합 준비 상태로 보고합니다.

사장님께서 지금 결정하실 일은 없습니다. 병합·배포는 이 문서의 검사와 교차검증이 끝난 뒤에도 자동 실행하지 않습니다.

## 판단 근거

- G3 검사는 서버 자동검사 실행 칸에 여덟 명령으로 연결돼 있지만, 검사 장치 명부에는 한 건도 없습니다. 실제 장치가 명부 감시 밖에 있으므로 명부가 완전하다는 기존 합격은 과장입니다.
- 현재 명부 대조기는 서버 자동검사 파일 전체에서 목표 문구를 찾습니다. 실행 칸에서 명령을 지우고 주석에만 남겨도 합격하므로, 명부 항목 추가만으로는 가짜 합격을 닫지 못합니다.
- 원격 기본선은 보호되지 않았고, 현재 요금제에서는 합치기 차단 규칙을 켤 수 없습니다. 서버 검사는 실패 표시를 만들 뿐 합치기 자체를 거부하지 못합니다.
- 기존 G3 목표 문서와 과거 판정서는 각각 여섯 후보를 기록했지만 구성원이 하나 다릅니다. 과거 판정서는 당시 증거이므로 고쳐 쓰지 않고, 두 목록의 합집합 일곱 후보를 이 문서와 G3 목표 문서의 현재 목록으로 고정합니다.

> **무엇을** — G3를 검사 장치 명부에 올리고, 서버 자동검사의 실제 실행 칸만 명부 근거로 인정하며, 강제력 설명과 잔여 한계 목록을 현재 사실에 맞춥니다.
> **왜** — 명부 누락과 주석 옆문을 함께 닫지 않으면 장치가 사라져도 명부 검사가 합격할 수 있고, 잘못된 강제력 설명은 사람 검토를 느슨하게 만들기 때문입니다.
> **버린 길** — 명부 항목과 문구만 고치는 길은 검사기가 주석을 실행으로 오인하는 결함을 남기므로 버렸습니다. 과거 판정서를 덮어쓰는 길도 증거의 시간 순서를 훼손하므로 버렸습니다.
> **대가** — 명부 대조기가 서버 자동검사 문법을 구조로 읽게 되어 코드와 회귀 시험이 조금 늘고, 과거 여섯 후보 판정서는 현재 일곱 후보 목록과 함께 읽어야 합니다.
> **되돌리기** — 문제가 생기면 이 후속 커밋들만 되돌릴 수 있습니다. 다만 되돌리면 G3 명부 누락과 주석 옆문, 잘못된 강제력 설명이 모두 다시 살아납니다.

1. G3를 서버 자동검사에 추가할 때 검사 장치 명부 갱신이 같은 변경으로 묶이지 않았습니다.
2. 명부 대조기가 서버 자동검사 문서를 구조가 아닌 전체 문자열로 읽어, 주석과 실행을 구분하지 못합니다.
3. 서버 검사 성공과 합치기 차단 권한을 같은 것으로 설명했습니다.
4. 두 검증 기록이 서로 다른 여섯 후보를 가졌지만 현재 목록을 한 곳에서 다시 확정하지 않았습니다.

현재 잔여 후보의 단일 목록은 다음과 같습니다.

| 번호 | 후보 | 현재 분류 |
|---|---|---|

| 2 | 작업 수준 `timeout-minutes: 0` | 서버 유효성 판정이 필요함 |
