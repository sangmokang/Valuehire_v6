# 메일 분류·공유 초기 구현 검증

이 문서는 초기 구현 시점의 기록이다. 현재 판정·권한·장부는 [PR #139 현재 검수](mail-governance-pr139-current-review-2026-10-21.md)를 우선한다. 초기 시험 통과나 아래 조치 설명을 현재 결함 해소로 읽지 않는다.

추적: [Issue #138](https://github.com/sangmokang/Valuehire_v6/issues/138).
실제 메일·고객 연락처 장부·계정별 메시지 ID·원문 인용·자격증명은 이 공개 문서에 포함하지 않는다.

## 판정 범위

이 변경은 전사 메일 자동화의 첫 구현이다. 버전 있는 검토 JSON의 증거 검증, 다중 레이블 계산, Ontology 사건, SQLite 불변 장부, 공유 계획과 수신 확인 계약을 구현한다. 운영 Gmail 어댑터·전체 메일 backfill·기존 스케줄러 연결·원격 Ontology 이관은 아직 배포하지 않았다. 설정된 멤버를 전체 멤버로 간주하지 않는다.

## Claude 적대 검토와 조치

로컬 Claude CLI로 설계를 읽기 전용 검토했다. 최초 OMX 경로가 응답 없이 지연돼 해당 작업의 자식 프로세스만 종료하고, 도구·MCP·사용자 훅을 비활성화한 `claude -p`로 재실행해 정상 응답을 받았다. 전체 프롬프트와 원문 판정서는 로컬 `.omx/artifacts/claude-mail-governance-20261021.md`에 보존한다.

| 지적 | 처리 및 한계 |
|---|---|
| 읽기/발송 권한으로 레이블 변경까지 가능하다고 가정할 위험 | DWD `gmail.modify`와 Directory 범위의 `unauthorized_client`를 실제 확인. 대표 Gmail 연결 도구의 레이블 쓰기는 별도로 실행·재조회해 확인 |
| 같은 고객 메일을 여러 구성원이 받아 중복 공유 | 전역 RFC 범위 선점. 같은 RFC-ID의 다른 본문 표현은 새 공유·수신 레이블 계획 없이 검토 대기로 격리 |
| 인용된 과거 JD/피드백이 새 사건처럼 통과 | 입력은 최신 작성 부분만 허용. 한국어·Outlook·인라인 답장 분리기는 향후 어댑터 책임이며 불명확한 추출은 검토 대기 |
| 내부 맥락이 풍부한 메일을 후보자용 모범 문서로 승격 | 회사·직무·상단 개인화·가독성의 네 축과 후보자 적합성·기밀 여부를 각각 요구. HTML 존재나 이름 치환만으로 통과 금지 |
| 보류·추가 설명이 탈락으로 합쳐짐 | `client_hold`와 `feedback_clarification`을 독립 사건으로 보존. ID 미확정은 unresolved, 미기재 사유는 reason_unknown |
| 발송 응답만 보고 dev 수신·동일 레이블까지 완료 처리 | 발송 의도와 관측을 분리. 실제 수신 계정의 본문/레이블 확인이 모두 있어야 VERIFIED |
| 공개 저장소의 고객 장부·메일 인용 유출 | 합성 테스트만 커밋. 실제 메일·원문·private 실행 장부는 git 제외 경로와 제한된 파일 권한으로 보존 |

Claude가 제안한 추가 사람 승인·외부 수신자 필수 조건·직접 import 방식은 일괄 채택하지 않았다. 사용자가 내부 공유를 명시 승인했고, 후보자용 문서의 보관 위치만으로 품질을 결정할 수 없으며, import는 현재 승인된 API 범위 밖이다. 원문 MIME 보존은 전송 수단의 문서 설명과 별개로 실제 수신 바이트를 대조한다. Claude의 미확인 추정은 실측 근거와 구별한다.

## 검증

- 14개 단위 테스트: Golden 상태 729조합, 잘못된 해시/오프셋/자료형 거부, 비-JD·다중 레이블, 보류/추가 설명 분리, 미확정 ID/사유, 원문 최소 보존, 불변·권한 제한 SQLite, 전역 중복/표현 변형 격리, 기존 DB 이관, 미러 재전달 차단, 수신 관측 상태, 페이지 누락·cap 실패.
- MIME/ZIP 테스트 11개: 고정 수신자, 헤더 주입·누락·잘못된 본문 자료형 거부, UTF-8 제목, 인코딩 후 용량 제한, 바이너리/줄바꿈 보존, ZIP CRC·중복·경로·후행 데이터 거부. Python `zipfile`과 상호운용을 확인했다. pure builder는 네트워크를 호출하지 않는다.
- 별도 SQLite 연결의 동시 예약에서도 공유 계획 1개와 변형 격리 1개를 확인했다.
- 구문 검사와 CLI 검토 import → plan 실행을 확인했다. 테스트는 메일 의미 판단을 증명하지 않는다. 검토자의 선언과 provider 관측의 인증은 어댑터가 책임진다.
- 대표 메일함 표본 7건: JD 2건·면접 2건·고객 피드백 2건의 레이블 추가 후, 기존 데일리 1건까지 실제 재조회했다. 기존 골든 표본 2건은 새 기준의 개인화/역할 일관성이 부족해 새 Golden 레이블을 부여하지 않았다. 기존 레이블은 보존했다.
- dev 공유 표본: 최초 2통은 실제 수신됐지만 `.eml` 첨부가 펼쳐져 원본 파일 보존에 실패했다. 나머지 전송을 중단하고 ZIP으로 변경했다. 기존 실패 관측을 유지한 별도 보완 작업 2건을 포함해 총 9통을 전달했다. 7개 고유 원본 모두 dev에서 내려받은 ZIP 내부 원문을 Python으로 열어 원본 RFC 바이트와 직접 비교해 일치했다. 자기 선언 해시끼리만 비교한 결과가 아니다.
- 위 7개 수신본의 레이블 변경은 DWD 권한 부족으로 실행하지 못했다. 원문 보존 확인과 레이블 완료를 합치지 않았으며 공유 작업은 `SENT_UNVERIFIED`로 남겼다. 피드백 2건의 회사/지원회차 매칭도 미확정이므로 unresolved를 유지했다.
- 첫 커밋의 로컬 pre-push 필수 27개 게이트와 GitHub 분류 전용 CI·기존 verify를 통과했다. 후속 MIME 변경은 새 커밋의 검사 결과로 별도 확인한다.

## 남은 배포 조건

승인된 전사 계정 명단, 계정별 Gmail 변경 권한, dev 계정의 레이블 변경·재조회, 한국어 인용 추출·review 큐를 포함한 어댑터, 전체 cursor backfill 및 기존 스케줄러 연결이 필요하다. 7건의 전달 무결성 표본으로 전체 수집 범위나 다른 메일의 첨부 보존을 입증하지 않는다. 이 항목을 확인하기 전에는 전사 완료나 향후 자동 공유가 작동한다고 보고하지 않는다. 자동 병합하지 않는다.
