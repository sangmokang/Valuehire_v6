# HS-00.02 — 잘못된 실패 사유를 합격으로 세지 않는다

## T 계약 — 합격 조건과 가짜 합격 조건

EARS 합격 조건: 기대한 실패 사유가 실제 FAIL 행의 정규 문구에 나타나면 음성 대조 함수는 PASS 한 건·CHECKED 1·종료값 0을 내야 한다. 기대 사유가 없거나 다른 사유의 부분문자열·정규식 일치·PASS 행의 미끼뿐이면 FAIL 한 건·CHECKED 1·종료값 1을 내야 한다.

입력은 기대 문구 한 개와 현재 실행에서 나온 출력 파일이다. 문자열은 명령·정규식으로 해석하지 않는다. 출력 파일은 읽기만 하며 기대 문구가 비었거나 파일이 없거나 FAIL 행이 없으면 거부한다. 원래 negative 함수의 대상 실행 실패·실제 변조 여부 확인도 유지한다.

일반 사유는 `FAIL: ` 뒤에서 정확한 기대 문구로 시작하며, 문구 끝 또는 공백·정상 상세 구분자 경계가 있어야 한다. `불량XYZ`를 `불량`으로 세지 않는다. 기존 호출이 쓰는 짧은 사유 `행 없음`, `대상 칸에 다른 대상`, `처분이 둘 이상`은 기존 검사기가 출력하는 대상·행 문구 전체의 정규 형식에서만 인정한다. 기존 31개 음성 기대 문자열과 6개 양성은 변경하지 않는다.

부작용은 임시 시험 파일 작성뿐이다. 시험은 고유 임시 폴더에서 실행하고 GIT_*·BASH_ENV·ENV를 제거한다. 저장·경쟁·외부 응답 유실은 제품 경계에 해당하지 않으며 실제 포털·운영 DB 호출은 0건이다.

가짜 합격 조건(counter-AC)은 항상 허용, 항상 거부, FAIL 행 제한 생략, 문자 경계 생략, 문자 그대로 대조 대신 정규식 사용, 빈 기대값 수락, 기존 정상 실패 문구를 거부하는 과잉 차단이다.

## 구현 결정과 검증 계획

**무엇을** — 사유 대조를 작은 전용 보조 함수/CLI로 분리하고 기존 음성 대조가 직접 호출하게 한다.
**왜** — 기존 변이 파일이 593줄이어서 사유 형식과 경계 처리를 안에 계속 추가하면 파일 한도 600줄을 넘는다.
**버린 길** — grep -F만 쓰면 다른 사유 중간의 문구가 통과한다. 전체 행 완전 일치만 쓰면 기존 짧은 사유와 상세 설명의 정상 형식이 깨진다.
**대가** — 정규 실패 문구를 변경할 때 사유 대조와 정상 대조군을 함께 갱신해야 한다. 임의 출력의 진위를 인증하는 도구는 아니다.
**되돌리기** — 이 WU의 구현 커밋만 revert하고 고정된 RED 시험이 다시 실패하는지 확인한다. HS-00.01과 다른 작업트리는 유지한다.

1. 새 시험은 기존 negative 본문을 그대로 호출하고 외부 실행·임시 fixture 준비만 고정한다. 제품 구현 문자열을 단언하지 않는다. 값은 셸 문자열 삽입 대신 argv로 전달한다.
2. 실제 행동 RED를 실행하고 독립 시험 검토 후 시험만 커밋한다. 코드 수정 후 기대값은 변경하지 않는다.
3. 정조준 명령은 `cd humansearch && uv run --no-sync pytest -q tests/test_hs_0002.py`. 문자 조합의 속성 대조도 같은 실제 호출 경로로 검증한다.
4. 기존 착수 12개/변이 37개, G2 회귀, Ruff·mypy, 셸 구문, 비밀·공백 검사, 파일 600/601·대상 0개 및 함수 100 한도를 확인한다. 새 독립 acceptance 프레임워크나 CI 단계는 추가하지 않는다.
5. 독립 Codeaudit, 실제 Claude V1, 새 맥락 Codex V2가 정상/고장 사본과 원문을 재공격한다. 각 실행의 명령·시각·종료값·전체 출력·원본 지문을 보존한다. 같은 UID 검토를 OS/P17 영수증으로 부르지 않는다.
6. 같은 제품 지문을 GREEN 커밋하고 커밋 후 다시 읽어 대조한다. 높음 이상 미해결이나 필수 검증 미실행이면 완료로 확정하지 않는다.
