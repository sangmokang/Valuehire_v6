# 후속 후보 검증의 실패와 재시도

추가 RED 초안의 Ruff ISC004 두 건은 문자열 연결 괄호가 빠진 표기 문제였다. 새 시험만 RED 커밋 전에 고쳤으며 기대값·기존 시험은 변경하지 않았다. boundary-ruff.log와 boundary-ruff-recheck.log를 보존했다.

전체 회귀를 처음 부른 final-g2는 존재하지 않는 scripts/acceptance-g2.sh 경로로 종료값 127이었다. 과거 정상 실행 metadata와 정본의 실제 scripts/acceptance-hs-gates.sh를 확인하여 final-g2-recheck에서 262개 수집·실행을 통과했다. 잘못된 명령이 통과했다고 주장하지 않는다.

초기 V2의 환경 목록 조회는 인증 값이 도구 응답과 로컬 로그에 노출되는 사고였다. 로그를 가리고 원문 지문과 처리 기록만 보존했으며, 환경 로그 자체는 Git 증거에서 제외했다. privacy-readback-final에서 V2 파일 106개에 두 값의 정확한 바이트가 남아 있지 않음을 확인했다. 이는 이미 나온 도구 응답을 회수한 증거가 아니다. 후속 검토에는 환경 목록 및 인증 값 수집·출력을 금지했다.

노출 값의 내용만 로컬에서 읽었을 때 role은 service_role이었다. 서명·현재 유효성은 원격에서 검증하지 않았고 실제 요청도 하지 않았다. 관리자용 키일 가능성이 있으므로 키 교체가 필요한 운영 보안 사고로 분리한다. 이번 세션에서는 운영 인증 교체를 실행하지 않았으며 사용자에게 이 사실과 교체 필요를 알렸다. 증거는 값을 포함하지 않는 privacy-key-scope.json이다.

문서 최종 점검의 첫 brief-lint는 종료값 0이지만 README 결론 제목 누락 1건을 출력했습니다. 이를 PASS로 세지 않고 결론·판단 근거 구획을 보완하여 같은 원명령을 재실행합니다. 원문은 checkpoint-brief-lint.log에 보존합니다.
