# HS-00.05 — 앞 단계의 실행 환경 변경 우회 부채

## 결론

앞 단계가 뒤 검사의 실행 환경을 바꿔 검사를 생략하게 하는 경로가 남아 있습니다. 현재 수정본의 별도 검토에서 발견한 후속 작업이며, 해결됐거나 온라인 검증이 끝났다고 주장하지 않습니다.

## 판단 근거와 작업 카드

- 상태: OPEN, 로컬 명세. 온라인 Issue 등록·구현·시험 커밋·원격 CI·병합은 NOT_RUN.
- 출처: 실제 Claude V1 세션 `122a5412-d386-42f5-87fa-83135bb909b5`의 F-A, 중간 심각도. 새 Codex V2의 독립 판단은 HS-00.01 증거에 보존한다. V2가 현재 합격 조건을 무너뜨리는 높음 결함으로 판단하면 HS-00.01도 완료로 확정하지 않는다.
- 사용자 결과: 앞 단계의 환경 설정으로 착수 검사 두 단계가 실행 없이 성공 처리되지 않는다.
- 현재 경계: HS-00.01은 보호 단계의 허용 키와 최상위·잡 수준 키를 검사한다. 다른 단계의 run 본문 전체나 실행 중 환경 변경을 검증한다는 보장은 없다.
- 포함: 앞 단계의 GITHUB_ENV/GITHUB_PATH 변경이 보호 단계의 실제 셸·명령 실행에 미치는 영향과 필요한 방어. 제외: 원격 포털·운영 DB, 동형 문자, 기존 기대 사유 대조와 trigger/concurrency 자체 의미.
- 입력: 실제 verify workflow, 앞 단계의 환경 파일 쓰기, 보호 단계 호출. 출력: 정상 검사 실행과 CHECKED 판정 또는 우회 거부. 오류·경계: 환경 파일 누락/빈값/다른 변수, 정상 설치 단계의 PATH 설정, 셸 시작 파일, 기존 검사 생략.
- 부작용: 검증은 고유 임시 사본과 로컬 합성 실행에서만 수행한다. 실제 GitHub runner 실행은 별도 원격 요청과 실행 증거가 필요하다.
- 소유 파일(예정, 아직 구현 없음): workflow 판독기·CI 무결성 경계와 새 독립 회귀 파일. 정확한 책임 분리는 착수 시 고정하며 593줄 기존 변이 파일에 무작정 추가하지 않는다.
- 선행: HS-00.01의 감사된 코드 지문과 실제 GREEN SHA를 시작 시 다시 회수한다. 현재 검토 기준 HEAD는 tests-only `16e5d649dbd257e6d01318c1a8fb0fbe8e731596`이고 구현 완료 SHA가 아니다.
- 합격 조건: 현재 workflow 정상 대조는 검사 본문 실행 흔적·CHECKED를 남긴다. p01/p13 사본은 본문 생략을 성공으로 처리하지 않는다. 항상 허용·항상 거부·환경 방어 생략 변이는 각각 시험에서 실패한다.
- 시험 명령(예정, 파일 없음): `cd humansearch && uv run --no-sync pytest -q tests/test_hs_0005.py`. 실제 RED 실행·독립 시험 리뷰 뒤에만 시험을 커밋한다.
- RED/GREEN SHA: 없음. Codeaudit·Claude V1·새 Codex V2: 이 부채 구현에 대해서는 NOT_RUN.

## 재현 근거와 한계

`evidence/hs0001-20260910/v1-final-probes-evidence.json`의 p01은 앞 단계가 BASH_ENV를 GITHUB_ENV에 쓰도록, p13은 가짜 bash 경로를 GITHUB_PATH에 쓰도록 바꾼다. 본 검사와 CI 무결성 검사가 두 사본을 수락했다. `v1-final-semantic-local.json`에서 정상 본문은 실행 흔적을 남기고 두 환경 주입은 흔적 없이 성공 종료했다. 이는 로컬 셸 재현이며 실제 GitHub 작업 영수증은 아니다.

→ 검사 입력의 수락과 로컬 실행 생략은 직접 재현됐다. GitHub에서 같은 환경 파일이 후속 단계에 전달되는 의미는 `actions-env-path-official.md`의 공식 문서·고정 runner 소스로 확인했으며 실제 원격 실행으로 바꿔 보고하지 않는다.

**무엇을** — 현재 검사 범위 밖의 실행 중 환경 변경을 별도 한 작업으로 등록한다.
**왜** — 실제 반례를 잃지 않으면서 방어 범위를 검토 없이 확장했다고 주장하지 않기 위해서다.
**버린 길** — 모든 run 본문을 두 번째 셸 파서로 해석하거나 문자열 몇 개 차단만으로 모든 우회가 닫혔다고 선언하지 않는다.
**대가** — 해결 전에는 이 실행 환경 우회가 남으며 workflow 변경의 사람 검토가 필요하다.
**되돌리기** — 구현 착수 후 해당 작업의 변경만 revert하고 고정한 RED 시험으로 원래 결함의 복귀를 확인한다. 다른 WU의 기록은 유지한다.
