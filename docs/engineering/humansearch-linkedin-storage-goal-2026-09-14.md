# LinkedIn 상세 저장 개정 — HS-11.03

## 결론

최신 승인에 맞춰 LinkedIn 상세를 전량 암호화 저장하고 재조회하는 계약을 고정한다.
현재는 문서 개정 후보다. Aside 정책 18fc1b4를 별도 작업 브랜치에 통합했고 §4·§5를 개정했다.
독립 감사·필수 검사·PR이 남았다.

## 판단 근거

브라우저 정본 §4·§5의 저장 불허가 9월 8일 결정과 v5 §1·§6·§7에 충돌한다.
금지 문장만 삭제하면 저장 실패·부분 증거·중단·발송 경계가 빠지므로 대체 계약을 동봉한다.
정본 후보는 [LinkedIn 저장 계약](../sot/humansearch-linkedin-storage-contract.md)이다.

- 위험 L3, 문서 WU이며 배송 NOT_APPLICABLE. 운영 완료를 주장하지 않는다.
- 기준 origin/main fc6beedc78019862bc2f1b3bf4c4ad3bbd8e845b.
- 소유 task/hs-1103-linkedin-storage-contract-20260914, Codex root.
- 브라우저 SOT는 HS-05.01의 18fc1b4 위에서 이 WU가 §4·§5와 관련 §2-1·13·14·18의 대체/미실행/추적 기록을 개정한다. 원래 Aside 작업 파일은 수정하지 않는다.
- 선행 HS-02.01 계약은 별도 감사 중이며 병합 미완료. 타입·저장 구현은 복제하지 않는다.
- 사용자 AGENTS·strict·브라우저 정본·원칙 정본/장부·기존 WU 장부와 kickoff를 대조한다.
- work-unit-policy.yaml은 현재 기준에 없다. 수치와 완료 판정을 임의로 만들지 않는다.
- 원본 후보·인증·운영 입력은 Git에 넣지 않는다. 본 작업은 후보 열람·발송·병합을 하지 않는다.

## 계약·검증

AC와 counter-AC는 연결 계약의 인수 기준 표를 따른다. 제품 구현 없는 문서 WU라 런타임 RED/GREEN은 비해당이다.
문서 대조에서 저장 실패를 성공으로 취급하거나 부분을 전체로 승격하는 반례를 격리 사본에서 공격한다.
실행할 검사: git diff --check, 원칙 검사, staged bash verify.sh, 문서 형식 검사(제품 검증 아님),
독립 Codeaudit, 외부 엔진 V1, 새 맥락 V2. 필수 미실행은 NOT_RUN으로 남긴다.
개정 감사는 자격증명·전체 프로필·탭 추측·사람 개입·세션 지속성·LinkedIn 범위 6축을 포함한다.
PR은 weakens-check 라벨로 기존 금지 대체 사실을 드러낸다. 현재 SHA CI와 main 병합을 별도 확인한다.

실행 후 명령·시각·종료값·전체 출력과 대상 지문을 보호 증거에 연결한다.

## 결정 카드

무엇을 — LinkedIn 상세 저장을 현재 승인 범위와 후속 저장 경계에 연결한다.
왜 — 전량 저장 요구와 과거 정본의 충돌을 없애야 실제 열람을 시작할 수 있다.
버린 길 — 저장 허용을 발송 허용으로 확대하거나 독립 재조회 없이 성공 처리하는 방식.
대가 — 후속 구현과 main 병합까지는 라이브 NOT_RUN을 유지한다.
되돌리기 — 문서 커밋을 revert하고 소비 WU를 중지한다. 원본 자료 삭제는 포함하지 않는다.

## V1 지적과 처리

첫 V1은 원문 URL 증거와 일반 로그 금지의 혼동, 상세 열람 허용 누락을 지적했다.
보호된 출처 저장/세션 값 제외와 상세 열람 선행 조건을 명시하고 대체표·NOT_RUN 장부를 맞췄다.
정책 YAML의 non_scope는 HS-05.01 WU의 구현 범위 표기이며 LinkedIn 저장 금지 권한 값이 아니다.
현재 YAML에는 저장을 허용/금지하는 capability key가 없고 live_authority_verified는 false다.
브라우저 §16의 런타임 변조 증명 의무는 제거하지 않는다. 이번 문서 감사와 정책 반례는 런타임
잔여 명령 0의 대체가 아니며 그 증명은 NOT_RUN이다. 해당 선행 전 운영 완료·병합 준비 완료를 주장하지 않는다.

외부 기본 모델 재검토는 Fable 사용량 제한으로 exit 1이었다. 이를 통과로 계산하지 않고,
인증된 동일 CLI의 Sonnet으로 문서 재검토를 수행해 exit 0/PASS를 확인했다.
원출력과 대상 지문: `private-reviews/hs-1103-20260914/v1-sonnet.jsonl` 및 같은 이름의 meta.json.
감사 파일은 Git 밖 보호 결과이며 새 PC에서는 문서 범위 판정과 런타임 미실행을 분리해 재확인한다.
