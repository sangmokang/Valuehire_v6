# HumanSearch G3 비운영 주소 계약 — 여기 걸리는 토큰은 제품 계층 판정 전에 줄에서
# 제거한다(제거 후에도 금지 패턴이 남으면 그 줄은 여전히 위반이다).
#
# 왜 필요한가(2026-08-25 실측): origin/main 병합 후 게이트가 낸 위반 39줄 중 29줄이
# `portal.invalid`(RFC 2606 예약)와 루프백(127.0.0.1·localhost)이었다.
# `shadow_server.py` 의 루프백 고정은 위반이 아니라 안전장치다. 접속 자체가 불가능하거나
# 자기 자신을 가리키는 주소는 "운영 주소가 제품 코드에 박혔다"는 이 게이트의 대상이 아니다.
#
# 여기에 실제 도달 가능한 주소(사설 대역 포함)를 넣으면 게이트가 무력화된다.
# 목록은 case-insensitive 정규식(이 파일만 Ruby 판정 단계가 읽는다 — grep 은 읽지 않는다).
# 한 줄에 하나. 매치한 부분은 **지우지 않고 중립 자리표시자 `x` 로 바꾼다.**
#
# ⚠ 왜 지우지 않는가(2026-08-25 자체 적대 검증 A3·A4 실측): 토큰을 삭제하면 문자열의
# 모양이 깨져 뒤 규칙이 무력화된다. 예약 도메인을 덧붙이는 것만으로 닫는 따옴표가 사라진다.
#     SEL = "#loginBtn localhost"          삭제 → SEL = "#loginBtn      → id 셀렉터 규칙 무력화
#     SEL = ".login-button portal.invalid" 삭제 → SEL = ".login-button   → 클래스 규칙 무력화
# 둘 다 병합 직후 판정에서는 차단되던 것이라 명백한 회귀였다. 자리표시자로 바꾸면
#     SEL = "#loginBtn x" / SEL = ".login-button x"  → 두 규칙 모두 그대로 잡는다.
#
# ⚠ 경계는 소비하지 말고 lookahead 로 볼 것. 경계 문자를 함께 치환하면 같은 문제가 난다.

# ⚠ 포트가 붙은 형태는 어느 규칙에도 넣지 않는다. `[::1]:9333` 같은 값은 접속 대상이
# 아니라 **진단 엔드포인트 지정**이고, 그건 이 게이트가 잡아야 하는 운영 상수다.
# hardening.sh 의 "D1 IPv6 루프백 host:port" 표본이 그 판정을 고정하고 있다.

# ⚠ 경로(/...)를 규칙에 포함하지 않는다. 2026-08-25 V1(codex) F4 실측: 경로를 탐욕적으로
# 먹는 규칙은 한 줄에 예약 URL 과 실제 URL 이 함께 있을 때 **실제 URL 까지 지웠다**.
#   ENDPOINTS = "https://portal.invalid/,https://api.vendor.jobs".split(",")
#   → 제거 후: ENDPOINTS = "".split(",")   ← 실제 주소가 통째로 사라져 통과
# scheme+호스트까지만 지운다. 남은 경로 문자열(/first 등)은 어느 금지 패턴에도 걸리지 않고,
# 뒤에 실제 URL 이 있으면 scheme 규칙이 그대로 잡는다.

# scheme 이 붙은 예약 도메인 (호스트까지만)
[a-z][a-z0-9+.-]*://[a-z0-9]([a-z0-9.-]*[a-z0-9])?\.(invalid|example|localhost|test)

# scheme 이 붙은 루프백 (호스트까지만)
[a-z][a-z0-9+.-]*://(localhost|127\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}|\[::1\])

# 예약 도메인 호스트 (포트 없음)
[a-z0-9]([a-z0-9.-]*[a-z0-9])?\.(invalid|example|localhost|test)(?![a-z0-9:.-])

# 루프백 주소 (127.0.0.0/8 · localhost · IPv6 ::1) — 포트 없음
127\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}(?![0-9:.])
localhos[t](?![a-z0-9:-])
\[::1\](?![0-9:])
