# HumanSearch G3 비제품 경로 계약 — 여기 걸리는 추적 파일만 "제품 코드가 아니다"로 본다.
#
# 왜 이렇게 뒤집었나(2026-08-25 자체 적대 검증): 제품 루트 발견을 "제품 코드 확장자
# 목록"(py·js·ts·html·css …)으로 하면, 목록 밖 확장자는 조용히 검사망을 빠져나간다.
# 실측 — 신규 폴더 apps/api 에 명백한 위반 2건(홑 클래스 셀렉터 + 목록 밖 TLD 호스트)을
# 심고 확장자만 바꿨더니:
#     apps/api/main.js   → exit 2 (미등재 폴더로 잡힘)
#     apps/api/main.go   → exit 0 (통과)
#     apps/api/main.rb / .java / .php / .rs / .kt → 전부 exit 0 (통과)
# 이건 D4(고정 TLD 열거)에서 고친 것과 **똑같은 실패 방향**이 D3 의 수정 안에 남아 있던
# 것이다. 모르는 확장자가 통과하는 방향으로 실패했다.
#
# 이제 방향이 반대다. 인프라 구역(contracts·docs·scripts·hooks·.github) 밖의 추적 파일은
# **여기 등재되지 않았다면 제품 코드로 본다.** 제품 루트 계약에도 없으면 exit 2(검사 불능)다.
# 새 언어·새 확장자가 들어와도 자동으로 걸린다.
#
# ⚠ 여기에 `^apps/` 같은 넓은 접두를 넣는 것은 이 게이트를 무력화하는 것과 같다.
# 항목은 한 줄에 하나, 경로 전체에 대한 ERE(앵커 포함).

# 저장소 운영 데이터·설정
^\.check-weakening-patterns$
^\.gitignore$
^\.secret-patterns\.default$
^suppressions\.yaml$

# 에이전트 설정·스킬 (제품 코드가 아니라 이 저장소의 작업 도구)
^\.claude/

# 실행 불가능한 문서 형식 — 어디에 있든 제품 코드가 아니다.
# 전역 계층은 이 파일들도 그대로 검사하므로 탐지 범위는 줄지 않는다. 줄어드는 것은
# "이 폴더를 제품 루트로 등재하라"는 요구뿐이다. md·txt 만 넣는다 —
# html·css·js·json·yaml 은 제품 자산일 수 있으므로 계속 등재를 요구한다.
\.(md|txt)$

# 최상위 검사 스크립트 (전역 계층이 그대로 검사한다)
^verify\.sh$

# 빌드·런타임 메타데이터
^humansearch/\.python-version$
^humansearch/pyproject\.toml$
^humansearch/uv\.lock$
