# HumanSearch G3 비운영 접미사 계약 — 점(.)으로 이어진 소문자 토큰의 마지막 라벨이
# 여기 있으면 "운영 주소가 될 수 없는 것"으로 보고 통과시킨다. 없으면 거부한다.
#
# 판정의 실패 방향(codex V2 D4): 예전 규칙은 TLD 를 열거해 "목록에 있으면 거부"였다.
# 목록 밖 확장자(.jobs 등)는 조용히 통과했다 — 모르는 값이 통과하는 방향으로 실패했다.
# 이 계약은 그 방향을 뒤집는다. **모르는 접미사는 거부**다. 새 TLD 가 생겨도 자동으로 막힌다.
#
# 여기 실제 TLD(co, com, kr, io ...)를 넣는 것은 이 게이트를 무력화하는 것과 같다.
# hardening7 시험이 그 경우를 반례로 잡는다.
#
# 2026-08-25 V1(codex) F5 반영 — 파일 확장자로 넣었던 py·md·sh·so·zip 을 **뺐다**.
# 다섯 개 전부 IANA 에 실제 등재된 TLD 다(파라과이·몰도바·세인트헬레나·소말리아·gTLD).
# 확장자로 허용하면 `"vendor.zip"` 같은 2라벨 실호스트가 그대로 통과한다 — 실측 확인.
# 이 저장소 제품 코드에서 실제로 쓰이는 접미사는 json·css·js·html·txt 뿐이라 손실은 없다.
#
# ⚠ 앞으로 `"conftest.py"` 같은 문자열이 이 게이트에 걸리면, **py 를 다시 넣지 마라.**
# 그건 구멍을 되돌리는 것이다. 경로를 contracts/ 데이터로 옮기거나 따옴표 단독 토큰이
# 되지 않게 조립하는 것이 올바른 처리다.
#
# 한 줄에 하나, 소문자.
